# 05 · 路线图与验收标准

## 顺序的逻辑

先解冷启动（没内容 AI 就是空转）→ 再建信任（引用溯源）→ 再谈自动化（建议箱）→ 最后做差异化（主动层、agent）。**不先做炫技的自动整理**：在检索还不可信时就让用户发现笔记被改乱，信任不可逆。

| 里程碑 | 主题 | 交付 | 验收（不达标不进下一档） |
|---|---|---|---|
| **M0** | 地基 | crates workspace（`md-kernel` / `note-core` / `note-cli` / `note-mcp`）+ 薄 `src-tauri`、Vault 目录、块模型、SQLite 索引与重建器、`note` CLI、Tauri 壳跑通、`perf-budget.json` 落库 | ① 往返 golden 测试全绿（中文/CRLF/嵌套列表/表格/`---` 歧义/未知语法降级 `raw`）② 删 `index.db` 后重建，逐表 diff 为空 ③ 写入过程中强杀进程，重启无半截文件 ④ Windows 真机安装成功含 WebView2 bootstrapper（一台纯 Win10 + 一台 Win11）⑤ 删笔记后全库检索命中已删内容数为 0（无孤儿索引行）⑥ ADR-002 的 Obsidian 互操作验证有结论 ⑦ `note-core` 与 `md-kernel` 的依赖图里**没有 Tauri**（CI 用 `cargo tree` 断言）⑧ 全部同步 command 的 P95 < 8ms 基线建立 |
| **M1** | 能记能查（**全程无需 API Key**） | 块编辑器 + **分节渲染**、Inbox 速记 + 全局热键 + 托盘、目录树（虚拟滚动）、双向链接与反链、标签与属性视图、全文搜索、命令面板、回收站与冲突处理、**每日自动快照备份（含首启备份目录引导）**、设计 token 与暗色主题、Obsidian/Notion/MD 导入、导出 Markdown | ① 自己真实用它记一周，无一次"记不进去" ② 导入 1000 篇真实 Vault，块 ID 分配与链接图零错乱 ③ 体验基线（5000 篇）下搜索 < 80ms，设计上限（2 万篇）下可用 ④ 不配任何 key 时所有功能完整可用 ⑤ 在 Obsidian 里改文件后，本应用要么刷新要么报冲突，绝不覆盖 ⑥ **3000 块长文档打字 < 16ms、滚动不掉帧、跨节撤销可用**（分节渲染是本档最大技术风险，必须真机测）⑦ INP P95 < 50ms ⑧ 跨节选区/拖拽明确不支持且有替代入口 ⑨ **从快照里能完整恢复一篇被误删改的文件**（备份不做完就不算 M1 结束）|
| **M2** | 记忆层（第一次真 AI） | 嵌入与混合检索、rerank、带引用的流式问答、拒答判定、隐私硬门、`raw` 块排除、`ai_runs` 审计页、评测集 v1（20 条） | ① `recall@8 ≥ 0.85`，**幻觉率 = 0**（引用不存在的块 ID 视为硬 bug）② 每个答案可点回原文块并高亮 ③ 断网时本地关键词检索照常可用、生成侧明确提示不可用，而非假死或瞎编 ④ `ai.private` 笔记经任何查询路径都召不回（用测试证明，不是靠 review 代码）⑤ 评测集里含"必须拒答"的负样本并通过 |
| **M3** | 组织层（可控自动化） | 建议箱 UI + diff 预览、标题/摘要/标签/建链/归类/合并建议、**视图定义落 `views/*.md`**（动态视图/表格/看板/日历）、自动化三档、版本历史与撤销、关系图谱（WebGL） | ① 任何一条建议接受后都能一步撤销并还原到快照 ② `auto_low_risk` 档连跑 24h，事后被撤销的误改比例 < 5% ③ 建议箱每条都能看到依据块 ④ `link`/`merge`/`split`/`archive`/`restructure` 无法被配置成自动执行（**代码层禁止，不是 UI 限制**）⑤ 图谱 5000 节点 ≤ 2s 可交互 ⑥ 删 `index.db` 后视图定义仍在（I1 复验） |
| **M4** | 主动层（差异化重心） | 本地 cron、`tidy_inbox`、`weekly_review`、`related_now`、`gap_scan`、`resurface`、打扰预算与频控 | ① 连续自用 2 周，主动推送"有用"率 > 60%（以建议箱接受率为代理指标）② 单日推送不超预算上限，且能一键降级为每周一次 ③ 关闭应用期间错过的任务不补炸（下次启动只跑一次合并）④ 评测集扩到 50 条且指标不退化 |
| **M5** | 生成层 + Agent + 生态 | 跨笔记综述、会议纪要/语音整理、PDF/EPUB 解析、图片 OCR、agent 工具循环与预算熔断、MCP Server 只读暴露 | ① "把这批网页笔记整理成一章大纲并新建页面"端到端可跑通，且所有改动都经建议箱 ② agent 12 步 / 50k token 熔断生效 ③ 外部 MCP 客户端（Claude Desktop / Qoder）能搜到并读通本库 ④ 产出可给他人安装的正式安装包 + 使用说明 |

## 粗估与"一个人做不做得完"

单人开发，全职等效投入下的一档粗估（不确定性很大，只用于判断"要不要拆更小"，不用于对外承诺）：

| 里程碑 | 粗估 | 主要不确定性 |
|---|---|---|
| M0 | 2–3 周 | `md-kernel` 往返无损的真实难度（历史上最容易超期的就是它） |
| M1 | 4–6 周 | 分节渲染 + 编辑器交互细节的打磨时间 |
| M2 | 2–3 周 | 检索调参是体力活；嵌入依赖是否走本地 |
| M3 | 3–4 周 | 建议应用器的补丁原子性与撤销 |
| M4 | 2–3 周 | 主动层的"有用率"要靠自用迭代，时间不由代码决定 |
| M5 | 4+ 周 | agent 与多模态解析，范围本身可无限膨胀 |

**必须与可砍**（规格写满不等于一次做完，以下几项允许延后，其余不允许）：

- 可延后：Criterion 微基准、图谱视图、`resurface`、OCR/ASR、便携 zip 之外的第二种打包格式
- **不可砍**：往返无损测试、重建一致性、派生表孤儿测试、`perf-budget.json` 门禁、评测集、每日快照备份。它们都是"以后再说"就会永远不做、且不做就必然崩的东西

如果只能保留三件工程护栏，按这个顺序留：**往返无损测试 → 重建一致性 → 评测集**。

## M0 拆解（下一步动工的具体任务）

1. **Spike A：sqlite-vec on Windows**（半天，风险最高先做）——把 `.dll` 随安装包分发，`note-core` 启动时 `load_extension` 成功，写入并查询 1024 维向量。失败即切 BLOB + 纯 Rust 暴力余弦，不纠缠
2. **Spike B：Obsidian 互操作**（半天，见 ADR-002）——真实 Obsidian Vault 打开→保存→回 Obsidian，验块引用、反链、嵌入是否互相破坏；顺带验 `---` 分隔线歧义与嵌套列表放块 ID 的行为
3. **Spike C：3000 块长文档原型**（半天）——用分节渲染的最小原型验证打字延迟 < 16ms 与跨节撤销可行。**必须在写编辑器功能之前做**，方案不成立要换的是架构不是补丁
4. 仓库脚手架：crates workspace（`md-kernel` / `note-core` / `note-cli` / `note-mcp`）+ 薄 `src-tauri` + React-TS + CI（往返测试、clippy、fmt、`cargo tree` 依赖方向断言、`perf-budget.json`）
5. `md-kernel`：CommonMark+GFM 解析 → 块树 → 序列化回 md。含 `^b-xxx` 块 ID、front-matter、Callout、嵌套列表、表格；未知语法一律降级为 `raw` 节点不丢弃
6. `index`：建表、重建器（`reindex = parse(all)`）、jieba-rs 分词入 FTS5、链接图解析、派生表清理（含"先取 rowid 再删"的顺序）
7. 原子写 + 三种外部修改情形 + `notify` 文件监听 + 回收站移动与索引摘除
8. Tauri 壳：单实例、托盘、窗口恢复、日志、Windows 安装器
9. **`note` CLI**：`import` / `reindex` / `search` / `bench` / `eval` 五个子命令，作为后续所有层的验证入口（`bench` 从 M0 就有，性能基线要越早立越好）

M0 不含产品级编辑 UI，只有 Vault CLI + 一个占位窗口。**故意如此**：地基没钉死前做 UI，等于给要拆的墙贴砖。唯一例外是 Spike C 的分节渲染原型——它是**一次性验证代码，允许丢弃**，作用是决定架构而不是开始实现。

## 度量（每里程碑末记一次，用来判断方向对不对）

| 指标 | 为什么看它 |
|---|---|
| 捕获动作中位耗时 | 记不进去，后面全白搭 |
| Vault 笔记数 / 周 | 内容增长是留存的结果指标 |
| 检索 `recall@8`、幻觉率 | AI 层唯一硬指标，不看主观感受 |
| 建议箱接受率 | 自动化质量的真值；低于 40% 说明 AI 在添乱 |
| 主动推送接受率 | M4 的生死线 |
| 每周"问 AI 且得到有用答案"次数 | 判断"AI 原生"是否成立的最终依据 |
| 月度 token 花费 | 成本失控的早期信号 |
| **笔记丢失 / 内容被破坏事件数** | **目标恒为 0**。出现 1 次就要停下来先修它，任何新功能都不值得换数据完整性 |
| INP P95 / 打字延迟 / 冷启动 | G6 的实测值，每次发版记录；性能是"磨掉的"，只看趋势不看单次 |
| CI 性能门禁拦截次数 | 为 0 通常意味着阈值形同虚设，而不是真的没退化 |

## 风险登记

| 风险 | 等级 | 缓解 |
|---|---|---|
| 块 ID 语法与 Obsidian 兼容性未实测 | **高** | Spike B 用真实 Vault 验证读写互不破坏；失败则退回 `{#id}` 并放弃双向互操作（须重开 ADR-002） |
| `md-kernel` 往返无损比预想难（注释、转义、空行、软换行、`---`、CRLF） | **高** | 独立 crate + property test 前置；**宁可少支持一种块类型，也不接受有损** |
| 空库悖论：没有内容时产品无价值（注意与"冷启动"区分，后者指程序启动速度） | 高 | M1 的导入能力优先于一切 AI 功能；M1 末起全量自用 |
| **ProseMirror 不支持块虚拟化，长文档必卡** | **高** | M1 的分节渲染是唯一出路，也是 M1 最大工作量与风险项；提前在 M0 用一篇 3000 块的样例文档做原型实测，别等到 M1 才发现方案不成立 |
| WebView2 在老集显 Win10 机器上材质/动效不可用或掉帧 | 中 | "流畅优先"降级档（关 Mica、关动效、降缩略图分辨率）；M0 真机验证含一台低配机 |
| sqlite-vec Windows 打包链路不通 | 中 | 兜底已定：BLOB + 暴力余弦，20 万块内够用，不阻塞 |
| 主动层做成骚扰 | 中 | 打扰预算硬编码上限 + 一键降级 + 接受率作为发布门槛 |
| 网络盘（OneDrive/NAS）上文件监听与 SQLite 锁行为异常 | 中 | M1 专项验证，必要时明确不支持并提示用户把 Vault 放本地盘 |
| 单人开发范围失控（又想做协作又想做多端） | 中 | [01] §明确不做 作为拒绝依据；新增范围须写 ADR |
| **规格膨胀超过一人执行力**（文档写的是十人团队的门禁） | **中高** | 见 §必须与可砍：护栏只保三件必留项，其余允许延后；每里程碑末回看一次"哪些门禁其实从没跑过"，砍掉比假装在跑更诚实 |
| 唯一副本在一块盘上，一次磁盘故障即全丢 | 高 | M1 的每日自动快照到第二目录 + 首启引导明确选择；这项不做完不算 M1 结束 |
| 剪藏/导入内容里的提示注入被 AI 当成指令执行 | 中 | [04] §全局契约的"外部内容是不可信语料" + `notes.origin` 在 SQL 层区分来源 |
| 自己不用（最大的沉默失败） | 高 | M1 末开始全量真实自用，问题清单直接进 backlog |
