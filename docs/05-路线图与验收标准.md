# 05 · 路线图与验收标准

## 顺序的逻辑

先解冷启动（没内容 AI 就是空转）→ 再建信任（引用溯源）→ 再谈自动化（建议箱）→ 最后做差异化（主动层、agent）。**不先做炫技的自动整理**：在检索还不可信时就让用户发现笔记被改乱，信任不可逆。

| 里程碑 | 主题 | 交付 | 验收（不达标不进下一档） |
|---|---|---|---|
| **M0** | 地基 | crates workspace（`md-kernel` / `note-core` / `note-cli` / `note-mcp`）+ 薄 `src-tauri`、Vault 目录、块模型、SQLite 索引与重建器、`note` CLI、Tauri 壳跑通、`perf-budget.json` 落库 | ① 往返 golden 测试全绿（中文/CRLF/嵌套列表/表格/`---` 歧义/未知语法降级 `raw`）② 删 `index.db` 后重建，逐表 diff 为空 ③ 写入过程中强杀进程，重启无半截文件 ④ Windows 真机安装成功含 WebView2 bootstrapper（一台纯 Win10 + 一台 Win11）⑤ 删笔记后全库检索命中已删内容数为 0（无孤儿索引行）⑥ ADR-002 的 Obsidian 互操作验证有结论 ⑦ `note-core` 与 `md-kernel` 的依赖图里**没有 Tauri**（CI 用 `cargo tree` 断言）⑧ 全部同步 command 的 P95 < 8ms 基线建立 |

## 粗估与"一个人做不做得完"

单人开发，全职等效投入下的一档粗估（不确定性很大，只用于判断"要不要拆更小"，不用于对外承诺）：

| 里程碑 | 粗估 | 主要不确定性 |
|---|---|---|
| M0 | 2–3 周 | `md-kernel` 往返无损的真实难度（历史上最容易超期的就是它） |
| M1 | 4–6 周 | 分节渲染 + 编辑器交互细节的打磨时间 |
| M2 | 2–3 周 | 检索调参是体力活；嵌入依赖是否走本地 |
| M3 | 3–4 周 | 建议应用器的补丁原子性与撤销 |
| M4 | 2–3 周 | 主动层的"有用率"要靠自用迭代，时间不由代码决定 |
| M5 | 4+ 周 | agent 与多模态解析，范围本身可无限膨胀 |

**必须与可砍**（规格写满不等于一次做完，以下几项允许延后，其余不允许）：

- 可延后：Criterion 微基准、图谱视图、`resurface`、OCR/ASR、便携 zip 之外的第二种打包格式
- **不可砍**：往返无损测试、重建一致性、派生表孤儿测试、`perf-budget.json` 门禁、评测集、每日快照备份。它们都是"以后再说"就会永远不做、且不做就必然崩的东西

如果只能保留三件工程护栏，按这个顺序留：**往返无损测试 → 重建一致性 → 评测集**。

## M0 拆解（下一步动工的具体任务）

1. **Spike A：sqlite-vec on Windows**（半天，风险最高先做）——把 `.dll` 随安装包分发，`note-core` 启动时 `load_extension` 成功，写入并查询 1024 维向量。失败即切 BLOB + 纯 Rust 暴力余弦，不纠缠
2. **Spike B：Obsidian 互操作**（半天，见 ADR-002）——真实 Obsidian Vault 打开→保存→回 Obsidian，验块引用、反链、嵌入是否互相破坏；顺带验 `---` 分隔线歧义与嵌套列表放块 ID 的行为
3. **Spike C：3000 块长文档原型**（已完成，见 ADR-004）——结论是**原定的多实例分节方案被推翻**，改为单实例 + 装饰惰性化 + 1500 块阈值。仍需在真 TipTap + 可见窗口下复测一次 P95
4. 仓库脚手架：crates workspace（`md-kernel` / `note-core` / `note-cli` / `note-mcp`）+ 薄 `src-tauri` + React-TS + CI（往返测试、clippy、fmt、`cargo tree` 依赖方向断言、`perf-budget.json`）
5. `md-kernel`：CommonMark+GFM 解析 → 块树 → 序列化回 md。含 `^b-xxx` 块 ID、front-matter、Callout、嵌套列表、表格；未知语法一律降级为 `raw` 节点不丢弃
6. `index`：建表、重建器（`reindex = parse(all)`）、jieba-rs 分词入 FTS5、链接图解析、派生表清理（含"先取 rowid 再删"的顺序）
7. 原子写 + 三种外部修改情形 + `notify` 文件监听 + 回收站移动与索引摘除
8. Tauri 壳：单实例、托盘、窗口恢复、日志、Windows 安装器
9. **`note` CLI**：`import` / `reindex` / `search` / `bench` / `eval` 五个子命令，作为后续所有层的验证入口（`bench` 从 M0 就有，性能基线要越早立越好）

M0 不含产品级编辑 UI，只有 Vault CLI + 一个占位窗口。**故意如此**：地基没钉死前做 UI，等于给要拆的墙贴砖。唯一例外是 Spike C 的长文档渲染原型（`probes/spike-c/`）——它是**一次性验证代码，允许丢弃**，作用是决定架构而不是开始实现。

| 每日快照备份 | ✅ **真机走通**（2026-09-26） | `note-core::snapshot`：manifest 记**全量清单**（不是"这份有哪些文件"），于是误删的文件仍能在它消失前的那份里取到；先拷文件后登记，崩溃不会留下指向半截文件的条目；备份目录在库内直接拒绝（这条判据必须与 `Vault::open` 用同一套路径归一化，否则 Windows 的 `\\?\\` 前缀让它静默失效——第一版就栽在这里）。CLI `note backup` 与界面面板走的是同一批服务层方法。新增 12 项测试（快照 9 + 服务层 3），Rust 67 → 79 |

真机第一轮（2026-09-24）抓出四个**编译期与静态核验都看不见**的缺陷，已全部修掉：

1. `base.css` 的 `button { background: none }` 没放进 `@layer base`。未分层声明在级联里压过一切分层声明，与特异性无关，于是 `<button class="bg-accent">` 的底色被吃掉——**全应用所有按钮都会变成纯文字**。已把 reset 归 `@layer base`、组件基线归 `@layer components`。
2. `Vault::open` 里 `canonicalize()` 的 Windows 扩展长度前缀漏到了展示层：标题栏显示 `\\?\D:\Notes`。前缀属于 IO 调用细节（docs/03 §长路径），开库后即剥离，并补一条 Windows 专属测试钉住。
3. 搜索把命中结果与**启动时缓存的笔记列表求交集**，导致速记进来的新笔记（列表里没有）永远搜不到。搜索态改为直接渲染命中并按笔记去重；主窗同时订阅 `note://indexed` 自刷新，记完不用手动刷新。
4. 首启没有任何选库入口：`app_info` 在未选库时返回错误，界面只剩一条报错条和永远转不完的"加载中"。现在未选库返回 `vaultPath: null` 的占位信息，前端据此渲染首启面板。

另两处教训式的确认：`decorations:false` 的窗口在真机上是 1240×780 居中启动（此前一次"最大化 + 主题被改成亮色"是人工点过的痕迹，不是缺陷）；用 `SendKeys` 往 WebView2 里注字会被中文输入法吃掉，DOM 变了但 React state 没变——GUI 自动化必须走 CDP（`WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port`）或 `SendInput` 的 `KEYEVENTF_UNICODE`。

### 真机第二轮（2026-09-25）：浏览与编辑合成同一个实例

改动本身：只读视图不再按索引里的块平铺渲染（那份退化渲染器会把表格与代码洗成一行、把容器块的子项画两遍），
浏览就是块编辑器本身，`editable` 只是它的一个属性；点正文就地转编辑，光标按点击坐标算，不用"第一下解锁、第二下才放光标"。

真机（`pnpm tauri dev` + WebView2 CDP 可信输入，临时库 3 篇：4 块 / 14 块 / 2702 块）逐项量到的**是/否**，不是读码推断：

| 断言 | 结果 |
|---|---|
| 浏览与编辑是同一个 ProseMirror 实例 | **是**——给 DOM 打标记后切模式，标记还在，全程 `.ProseMirror` 计数为 1 |
| 浏览一篇会不会写文件 | **不会**——打开后等过 800ms 自动保存窗口，字节不变（`persist` 在 `mode === "view"` 直接返回） |
| 点某一行末尾，光标是否就在那一行末尾 | **是**——"距行尾 0"，用的是 `posAtCoords().pos` 而不是 `inside`（后者是块首） |
| 打一个字文件的改动 | **+1 字节，且只有那一行变** |
| 编辑有序项后序号 | **按源文件落盘**（`2. 有序二项` 仍是 `2.`）。改前这里是数据损坏：任何一次编辑都把 `3.` 写回 `1.`，而屏幕上还显示 3 |
| 待办行末尾打字会不会吞掉 `due::` | **不会**，新字符落在字段之前 |
| 编辑期间外部改盘，保存时 | **弹"丢掉我的，用磁盘版本 / 仍然存我这份"**，磁盘没被静默覆盖 |

代价与没解决的问题，同样有据：

- **成本从"点编辑"挪到了"打开笔记"**：2702 块那篇打开要 **676–768ms**（dev 构建），小笔记 19–22ms；换来的是点编辑 ≈ 0（原来 release 上是 297ms）。浏览有骨架屏顶着，G7 的"100ms 内有反馈"没破，但"切换笔记 80ms"在长文档上差一个数量级。
- **打字每键 40–56ms、10 键掉 10 帧（>32ms）**——这是 **dev 构建**，与 ADR-004 的 release 数字（事件处理 p95 0.2ms）不可直接比。`keydown` 自有处理仍只有 0.5–1.1ms，贵的是 `keypress`/`input` 的 23–35ms（浏览器侧布局）。**验收 ⑥/⑦ 必须在 release 上重测一次才算数。**
- **保存长文档后打开另一篇等 3.26 秒**（dev；小笔记 21ms）——[03] §后端调用纪律 那条"后台索引握着 `Hub` 锁"的未关闭项在真机上仍然咬人。**同日按那文档列的两步做完**：补索引改用第二条连接（主锁只在取句柄的一瞬被锁住），单篇的三步包进一个事务。同一动作 **3259ms → 96ms**（稳态 19ms），数字与剩下的事记在 [03]。
- **浏览态点链接的结果是就地进编辑态**，不是跳转也不是无操作。链接导航本身还没做，所以这条现在不算坏，但做反链/站内跳转时必须先定：`<a>` 上的点击该归"浏览动作"还是"编辑动作"。
- **编辑区一拿焦点就给整篇文章套一圈焦点环**。试过三条路都不通：去掉 `preventDefault`、去掉程序化 `focus()`、把规则改成 `:not([data-pointer-focus])`——Chrome 对"可编辑的 `contenteditable`"在**指针**聚焦时同样判 `:focus-visible`。剩下唯一手段是 `outline: none`，而 [06] §4 明令禁止，护栏（`scripts/guard.mjs`）也确实拦住了它。所以先留着这条安静的描边（`--border-strong` 而非 accent 环），**观感要不要另解，是样式决定，不在代码里绕**。
- 暗色主题下 `--bg-sunken`(14%) 与页面底(17%) 只差 3% 光亮度，**行内码等于隐形**。没有去加亮底色（`--bg-active` 在 [06] 里的语义是"交互反馈底"），改为给 `.prose-note code` 补一条 `--border-subtle` 描边，代码块内层再复位成无边。


一处**由数据推翻的判断**：我起初想"索引够快就同步做完，省掉异步链路"，实测捕获整体 12ms（超 8ms 预算），拆开后落盘 2.7ms / 索引 7.3ms——于是确认了文档原本写的"落盘同步、索引异步"。这条留在文档里，是为了提醒：这类"看起来更简单"的合并决定，必须量过才准做。

M1 已落：捕获 + 全局热键 + 托盘、首启选库、列表/搜索/浏览、笔记管理与回收站、自动保存与冲突处理 UI、**块编辑器接回界面（浏览与编辑同一个实例）**、设计 token 与暗色主题。

## 度量（每里程碑末记一次，用来判断方向对不对）

| 指标 | 为什么看它 |
|---|---|
| 捕获动作中位耗时 | 记不进去，后面全白搭 |
| Vault 笔记数 / 周 | 内容增长是留存的结果指标 |
| 检索 `recall@8`、幻觉率 | AI 层唯一硬指标，不看主观感受 |
| 建议箱接受率 | 自动化质量的真值；低于 40% 说明 AI 在添乱 |
| 主动推送接受率 | M4 的生死线 |
| 每周"问 AI 且得到有用答案"次数 | 判断"AI 原生"是否成立的最终依据 |
| 月度 token 花费 | 成本失控的早期信号 |
| **笔记丢失 / 内容被破坏事件数** | **目标恒为 0**。出现 1 次就要停下来先修它，任何新功能都不值得换数据完整性 |
| INP P95 / 打字延迟 / 冷启动 | G6 的实测值，每次发版记录；性能是"磨掉的"，只看趋势不看单次 |
| CI 性能门禁拦截次数 | 为 0 通常意味着阈值形同虚设，而不是真的没退化 |

|---|---|---|
