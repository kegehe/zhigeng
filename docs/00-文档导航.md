## 七条全局不变量（G1–G7）

所有设计与代码评审按这七条对齐，违反任意一条即为阻塞级问题。[02] 文档中的 I1–I4 是 G1 与 G5 在数据层的细化。

| 编号 | 不变量 |
|---|---|
| **G1** | **Markdown 文件是唯一真相源。** SQLite 索引是纯派生物，删掉 `index.db` 必须能靠扫描 Vault 完整重建。用户笔记内容不允许只存在于数据库 |
| **G2** | **摘掉 AI 后产品必须是空壳。** 这是"AI 原生"与"接入 AI"的唯一判据。新增功能先回答它属于骨架还是插件。**注意**：该判据针对产品的最终形态；M1 刻意交付一个不配 API Key 也完整可用的记录与检索内核，这是分阶段策略，不是把 AI 做成插件 |
| **G3** | **AI 不得静默改写用户笔记。** AI 产出进入建议箱（`suggestions` 表），用户逐条确认后才落盘。自动化程度是可调档位，默认不是"全开" |
| **G4** | **无引用不作答。** 检索依据不足时明确拒答并说明缺什么，不允许用模型先验冒充"你笔记里的内容" |
| **G5** | **MD ↔ 编辑器模型必须字节级无损往返。** 用户会用 Obsidian/VSCode/git 直接改文件，序列化不能吞掉未知语法 |
| **G6** | **同步调用不得超过 8ms；打字到屏幕不得超过一帧**（120Hz 16ms / 60Hz 33ms——60Hz 上写 16ms 是一条永远绿不了的断言，见 [ADR-004]）。任何可能更久的操作必须改成"立即返回 + 事件流推进度"。性能不是一次做出来的，是被后续每次改动磨掉的，所以这条要进**提交前门禁**（`node scripts/check.mjs --bench`，红线在 `perf-budget.json`）而不是进愿望清单。达没达成分开说：`note ipc-bench` 四个读命令 p95 ≤ 0.86ms、`note write-bench` 同步那一半 save 4.6 / move 1.5 / trash 2.4ms 达标（真机 Tauri 通道首次量得 4.3–4.6ms 同档）；打字到屏幕 release 真机 p50 24 / p95 32ms，在 60Hz 口径内；**"切换笔记 80ms"只有一半**——稳态 19ms 达标，后台正在补索引时 96ms 超线（未关闭项见 [05] §后端调用纪律 那节）；INP 只能真机测，机器拦不到 |
| **G7** | **任何用户动作都要在 100ms 内有视觉反馈。** 允许慢，不允许"看起来没响应"——这是"卡顿"的主观来源，也是优雅感的底线 |

## 术语

| 术语 | 含义 |
|---|---|
| Vault | 用户选定的笔记根目录，全部内容资产都在这里 |
| 块（block） | 可寻址的最小知识单元，有稳定 ID |
| 切片（chunk） | 1..N 个连续块组装成的检索/嵌入单元 |
| 建议箱 | AI 写意图的暂存区，人确认后才落盘 |
| 主动层 | 由定时/上下文触发的 AI 任务，AI 主动找用户 |
| 真相源 | 数据丢失后能否恢复的唯一来源 |
| 后端 / 服务层 | **本产品的后端是本地进程内的 `note-core` 服务，不是远程服务器**（无账号、无云端）。被 UI / CLI / MCP 三个入口共用 |
| 冷启动 | 仅指**程序启动速度**。库里没有内容那个问题叫**空库悖论**，两者别混 |
| `raw` 块 | 解析器不认识的语法，原样保留、只读渲染、不进 AI 上下文（G5 的最后防线） |
| 分节渲染 | 长文档按标题切节，只挂载可视节的编辑器实例。用于绕开 ProseMirror 不支持块虚拟化的限制 |

## 约定

- 文档内 SQL、目录、字段名即最终规格；与代码不一致时以本目录为准并同步修订。
- 每次推翻一个既定选择，在 `adr/` 追加 `ADR-NNN-中文标题.md`，说明背景、选项、结论、代价。
- 里程碑编号 `M0`–`M5` 只在 [05] 定义，其他文档引用它而不重复排期；规模口径（体验基线 / 设计上限 / 极端样本）只在 [03] §性能预算 定义。
- **未决问题集中登记在 [02] §待办决策**，不要散落在各处正文的"待定"里——散落的结果是没人再去看。
- 同一事实只在一处定义，其余引用。已知归口：块类型与枚举 → [02]；建议 kind 与补丁格式 → [04]；阈值数字 → [03]；范围裁剪 → [01]。
