# 03 · 技术架构与选型（Windows 桌面端优先）

## 总体分层

```
┌───────────────────────────────────────────────┐
│  WebView (React + TS)                         │
│  编辑器 / 检索与问答 / 建议箱 / 设置 / 审计     │
└──────────────┬────────────────────────────────┘
               │ tauri command(请求) + event(流式)
┌──────────────▼────────────────────────────────┐
│  note-core（后端服务层，全部业务逻辑）           │
│  vault · index · capture · ai · jobs          │
└──┬───────────┬────────────┬──────────┬────────┘
   │ fs        │ SQLite     │ HTTP     │ keyring
   ▼           ▼            ▼          ▼
 md 文件     index.db    模型 API   Windows 凭据管理器
```

**为什么业务逻辑放 Rust 侧而不是 Node 侧**，三条理由，任一条足够：

1. API Key 不进 WebView，避免前端任意脚本可读；关窗口后台任务照跑
2. AI 整理天然是异步长任务，进程内 `tokio` 调度比前端 `setTimeout` 可靠
3. 单实例 + 文件监听 + SQLite 写锁需要一个常驻 owner，不能让 UI 生命周期决定它

前端只做渲染与交互，不做业务判断。未来 CLI 与其他端复用同一 Rust 层。

## 后端 = 本地服务层（先把这个词对齐）

本产品**没有远程后端**：本地优先、单用户、无账号，服务器上跑什么都不合理。所谓后端就是 `note-core` —— 一个进程内服务，被三个入口共用（UI / CLI / MCP），文件系统 + SQLite 是它的存储。

```
   Tauri IPC (UI)           ┐
   note CLI (基准/脚本)      ├──►  Service trait  ──►  领域层 / 存储层 / AI 网关
   MCP server (外部 agent)  ┘
```

**分层与硬性禁令**：

| 层 | 职责 | 禁止 |
|---|---|---|
| 接口层 `ipc.rs` / `note-cli` / `note-mcp` | 参数校验、DTO 转换、把调用转成命令 | 写业务逻辑（三入口共用 core，逻辑下沉才能保证行为一致） |
| 服务层 `NoteService` / `SearchService` / `AiService` / `JobService` | 编排：一次"保存笔记" = 校验 → 原子写 → 重解析 → 增量索引 → 排队 AI 任务 → 发事件 | 直接碰 HTTP 或文件系统细节 |
| 领域层 `md-kernel`、chunk 切分、检索融合、建议应用 | 纯函数，输入输出确定 | 依赖 SQLite 或 Tauri（要能单测、要能被 CLI 复用） |
| 存储层 `vault/`（文件）、`index/`（SQLite） | 唯一允许碰磁盘和 SQL 的层 | 在 SQL 里写业务判断 |
| AI 网关 `ai/provider/` | OpenAI 兼容客户端、流式、重试、超时、token 记账 | 被 UI 直接调用（必须过服务层，否则 `ai_runs` 审计会漏） |

只有一条纪律要反复守：**只有服务层可被外部调用，只有存储层可碰磁盘和数据库。** 破坏它的典型症状是"CLI 导入出的索引和 UI 里操作出的不一样"，这类 bug 极难查。

### 核心机制

| 机制 | 设计 |
|---|---|
| **单写者队列** | 所有写（保存 / 接受建议 / 整理落盘）串行进一个 `mpsc` 队列，单个 writer task 持有唯一 SQLite 写连接。避免 `SQLITE_BUSY`，并让"文件写 + 索引更新"的顺序可控 |
| **读写连接分离** | 写：单连接；读：连接池（`r2d2`），FTS 与向量查询并发不阻塞输入。`PRAGMA journal_mode=WAL, synchronous=NORMAL, mmap_size=256MB`，预编译语句常驻 |
| **事务边界** | 文件原子替换成功后才提交 DB 事务；DB 失败则回滚文件（写前留 `.bak`）。崩溃后**以磁盘 md 为准重放索引**——I2 保证这件事永远可行 |
| **事件总线** | 内部 `tokio::broadcast`：`note.saved` / `index.updated` / `ai.token` / `suggestion.created` / `job.finished`。UI 只订阅事件，绝不轮询；下发按帧（16ms）合并 |
| **任务调度** | `jobs` 表 + `tokio-cron-scheduler` + 指数退避重试；每任务带幂等键；启动时把上次残留的 `running` 判定为中断并重新排队（不假设它跑完了） |
| **配额与熔断** | 并发模型请求 ≤ 3；主动层按日累计 token 预算，超了自动排队到次日；连续失败的任务自动 `disabled` 并提示 |
| **崩溃恢复自检** | 启动扫描 `.note/` 下的未完成移动、临时文件残留、`conflicts/` 新增项，逐个收敛并记日志 |

**可选的 `note serve` 模式**（把 service 暴露成 127.0.0.1 的 JSON-RPC 供浏览器 UI 或脚本连）：好处是未来加 Web 界面零成本；坏处是多一套进程生命周期与端口安全（本机任意进程可读写你的笔记）。**默认不做**，真要 Web 端时再开，届时必须只绑 loopback + token 鉴权 + 默认只读。

**明确不预留**：同步服务器、消息队列中间件、微服务拆分。目前只为同步保留三样极便宜的东西——`notes.rev` / `notes.device_id` 两列、"写命令幂等"的接口约定、以及"块 ID 全局唯一 + 内容可 hash + `.note/` 与用户内容分离"这三条已有设计。它们足以让未来接入 CRDT 不必重做数据层。**故意不建 op log（操作日志表）**：没有同步协议去验证它，它就只是一张永远膨胀、从不清理的表，属于纯债务；真做同步时按当时的协议反推结构才对。

## 仓库结构

Cargo workspace 根在仓库根。**核心逻辑不放 `src-tauri`**：否则 CLI 和 MCP server 都得链接整个 Tauri 运行时（编译慢、体积大、无头环境跑不了），"三入口共用后端"就是空话。`src-tauri` 只做窗口、托盘、IPC 注册这些壳的事。

```
zhigeng/
  Cargo.toml                 # workspace 根
  docs/                      # 本目录，规格即真相
  eval/                      # 评测集 golden.jsonl + 结果快照
  testdata/roundtrip/        # golden 文件：*.md + *.json 对偶
  crates/
    md-kernel/               # ★ md ↔ 块树双向转换，G1/G5 的唯一实现点，不依赖 SQLite
    note-core/               # ★ 后端服务层
      src/
        service/             # NoteService / SearchService / AiService / JobService
        vault/               # 目录发现、原子写、文件监听、认亲、回收站、冲突保留
        index/               # schema、重建器、jieba 分词、向量、图、派生表清理
        capture/             # 速记、拖入、URL 抓取、MD/HTML 导入
        ai/                  # provider · retrieve · answer · organize · agent
        jobs/                # 本地 cron、队列、重试退避、幂等键
        events.rs            # 事件总线
        secrets.rs           # keyring
    note-cli/                # import / reindex / search / bench / eval（M0 的验证入口）
    note-mcp/                # MCP server，只依赖 note-core
  src-tauri/                 # 薄壳
    src/
      main.rs                # 单实例、托盘、窗口、生命周期
      ipc.rs                 # command 注册与 DTO（ts-rs 生成前端类型）
    capabilities/            # Tauri v2 权限，scope 锁在 Vault 内
  src/                       # React 前端
    editor/                  # TipTap 扩展、块模型、分节渲染
    features/                # 编辑器、问答、建议箱、设置、审计
    ipc/                     # 生成的 command 客户端与类型
    ui/                      # 设计 token 与基础组件
```

依赖方向单向：`src-tauri` / `note-cli` / `note-mcp` → `note-core` → `md-kernel`。后两者不得反向依赖 Tauri，`md-kernel` 不得依赖 SQLite。

**现状与这张图的差处**（2026-10-10）：`note-core/src` 目前是**平铺的 `.rs` 文件**而不是子目录，
AI 那几块分别是 `ai.rs`（客户端 + Key + 探针）、`embed.rs`、`retrieve.rs`、`answer.rs`；
评测集在 `testdata/eval/`（`v1.toml` + `corpus/` + `corpus.list`）而不是顶层 `eval/`，
格式是 TOML 不是 `golden.jsonl`。等哪一层的文件多到需要拆开时再按这张图挪，别为了对齐目录名提前动。

## 技术选型

| 层 | 选择 | 理由 | 已考虑的替代 |
|---|---|---|---|
| 桌面壳 | Tauri v2 | 体积小、内存低、Rust 核心与本地文件/SQLite 天然契合 | Electron：Node 生态省事但 200MB 起、内存翻倍，且我们本来就要写 Rust，用不上 Node 运行时 |
| 前端 | React 19 + TypeScript + Vite | 生态与人力熟悉度 | Svelte 更轻，但栈一致性优先 |
| 编辑器 | **TipTap(ProseMirror) + 自研 md 序列化 + 分节渲染** | 唯一能保住 `^b-xxx` 与未知语法往返无损的路径：自定义 Node 的 `renderMarkdown`/`parseMarkdown` 全权掌控。分节渲染解决 ProseMirror 不支持块虚拟化的问题（见 §大文档策略） | BlockNote：上手快，但块 ID 与自定义语法序列化不可控，违反 G5 |
| 样式 | Tailwind v4 + Radix UI 原语 + 自维护设计 token | Radix 把键盘/焦点/a11y 这些"优雅"的地基活做完，视觉完全自己定，不被组件库审美锁死 | MUI/Antd：体积与风格都不合适；纯手写 a11y 成本高且必漏 |
| 状态 | Zustand + 细粒度 selector | 只有 selector 订阅能避免高频更新（打字、滚动）引发全量重渲染 | Redux 太重；Context 存高频状态会造成整树重渲染 |
| 代码高亮 | Shiki（TextMate 语法，Worker 内跑）+ 只高亮可视行 + 结果缓存 | 视觉质量明显优于 highlight.js，且 Worker 化后不阻塞输入 | 主线程 highlight.js：粘贴大段代码即冻结 |
| 图谱渲染 | Sigma.js（WebGL）+ 布局在 Rust 侧算好传二进制 | 5000 节点可交互；SVG/D3 力导向在 JS 主线程上千节点必卡 | D3 + SVG：只适合 300 节点以内 |
| 存储 | SQLite (WAL) + FTS5 + sqlite-vec | 本地单用户、零安装 | Postgres 是 SaaS 解法；向量兜底用 BLOB + 暴力余弦，**不引入 LanceDB** |
| 中文分词 | jieba-rs | FTS5 原生不分中文词 | trigram（索引膨胀、排序质量差，作兜底） |
| 异步与调度 | tokio + `tokio-cron-scheduler` + 自研 job runner | 无外部服务依赖 | BullMQ/Inngest 是服务端件，不适用 |
| 凭据 | `keyring` crate → Windows 凭据管理器 | 明文 key 不落盘 | DPAPI 自加密（凭据管理器写入受限时退化到此） |
| 打包 | NSIS `.exe` + 便携 `.zip` | Windows 分发最省事 | MSIX 需证书与商店流程 |

## 性能：真瓶颈与对策

换壳不解决性能（WebView2 就是 Chromium，VS Code / Figma 桌面版同引擎）。笔记类产品的卡顿 95% 来自四件事：**编辑器 DOM 规模、索引是否阻塞、IPC 频率、渲染重排**。逐条给对策：

| 瓶颈 | 对策 |
|---|---|
| 单篇块数过大 → 编辑器 DOM 爆炸 | **分节渲染**（见下） |
| 长列表 / 目录树 | 目录树 2026-09-28 已接上（前端从 `rel` 推），**2026-10-24 起再问一次 `dir_list` 拿空目录**——空目录不在任何 `rel` 里，不给清单就看不见；形状仍在前端（层级/排序/折叠），后端只回答"有哪些目录"。**虚拟滚动还没做**：侧栏一次最多 300 篇（`list_notes` 上限），这个量级下不是瓶颈。真要上就用 `@tanstack/react-virtual`，key 用 `rel` / `block_id` 而非 index（否则局部更新会整列重渲染） |
| 检索、嵌入、图谱布局阻塞 | 全部在 Rust `spawn_blocking` / worker，前端零重计算 |
| IPC 过频 | 事件按帧（16ms）合并下发；大 payload（图谱坐标、向量、批量检索结果）走 Tauri v2 `InvokeBody::Raw` 二进制；**输入过程不 IPC**，只在保存时 IPC |
| 冷启动 | 索引校验先用 `mtime + size` 快速比对（2 万文件 stat 约 200ms），hash 校验后台补；首屏只加载编辑器与目录，命令面板/图谱/审计页按路由懒加载；WebView 预热 |
| 大附件与图片 | 缩略图预生成（AVIF/WebP）、`loading=lazy` + `decoding=async`、附件缓存 LRU 上限 200MB |
| 语法高亮 | Shiki 在 Worker 内 + 只高亮可视行 + 按内容 hash 缓存进 `.note/cache` |
| 重渲染扩散 | Zustand selector 订阅；列表项 `memo` + 稳定 key；高频状态不进 Context |

### 大文档策略（Spike C 实测后改过一版）

原本这里写的是"按标题分节、只挂载可视节的编辑器实例"，理由是 ProseMirror 不支持块虚拟化、3000 块必卡。**实测推翻了这个前提**（数据见 [ADR-004](./adr/ADR-004-长文档策略.md)）：

| 场景 | DOM 节点 | 每次输入的纯重排 p50 / p95 |
|---|---|---|
| 3000 块全部挂载（单实例） | 3001 | 4.8ms / 8.7ms |
| 分节挂载（3 实例 / 330 块） | 330 | 0.7ms / 1.7ms |
| 分节的代价：跨过一个 100 块节的卸载+挂载 | — | **9–20ms / 次** |

分节省下的不是数量级，而多实例要付的代价很实在（跨节选区与拖拽作废、撤销栈要跨实例打通）。因此 v1 的策略换成三条更便宜的手段：

1. **单实例 + 装饰惰性化**：保持一个编辑器实例；可视区之外不挂 Decoration（语法高亮、行内标记、搜索命中框），滚动进入时增量补挂。装饰层才是随文档规模真正膨胀的那部分，且不动选区与撤销模型
2. **1500 块阈值**：超过时由 AI 提 `split` 建议（不自动拆），UI 明确提示"这篇太长，建议拆分"
3. **`md_kernel.heading_sections()` 保留但换用途**：服务于目录面板、按节跳转、节级折叠，**不再用于切分编辑器实例**（该函数已实现并有测试）

定稿前提：真机（Tauri 可见窗口 + 真 TipTap）复测 3000 块文档的输入 P95 与滚动掉帧。裸 contenteditable 没有装饰层、选区与事务开销，4.8ms 是**下界而非预期值**。若真机 P95 超 16ms，加强方案是按节切分文档内容但保持单实例（局部 `replaceWith` 刷新），不是回到多实例。

### 后端调用纪律

**任何同步 IPC 调用返回不得超过 8ms。** 超过就必须改成"立即返回任务 ID + 事件流推进度"。这条守住了，UI 侧再怎么渲染都不会出现转圈死等；守不住，前端做再多骨架屏都是假的。写进代码评审清单，并由 `note ipc-bench` / `note write-bench` 的 P95 指标把关——两条都会**超线即非零退出**，都接在 `node scripts/check.mjs --bench` 里（执行方式见 §性能预算 末）。

**读侧与写侧都已达标**（2026-09-24 真机，`note ipc-bench` / `note write-bench`）。写命令按这条纪律拆成了两半：**落盘同步返回，索引与链接图在后台补 + `note://indexed`**。拆完的同步那一半不再随库变大——2000 篇 save p95 4.6 / move 1.9 / trash 4.3ms，5000 篇仍是 4.5 / 1.5 / 3.9ms。后台那一半随规模线性增长（5000 篇 20–33ms），代价只是"晚一点才可搜"，不碰输入路径。

2026-09-25 把后台那一半挪到第二条连接、并把单篇的三步包进一个事务之后，同步那一半顺带又快了一档（2000 篇 / 每项 40 次）：save p95 **2.41ms**、move **0.65ms**、trash **1.54ms**；后台 index p95 8.48ms、moved 7.94ms、trashed 6.73ms。

`note write-bench` 因此分两张表打：只有"同步"那张受红线约束，"后台"那张是趋势观察。谁把两步重新合并（图省事直接调 `save_note`），同步表会立刻现形。`note write-profile` 能把一次保存拆成落盘 / 单篇重建 / 链接解析三段分别计时，定位超线先跑它，别猜。

**但"后台"那一半不是没有代价**：它和读命令抢的是同一把 `Hub` 互斥锁。3000 块 / 490KB 的长文档实测（2026-09-24，release）——保存返回后，第一个同步读命令要等 **22.5 秒**才拿到锁，期间切笔记、搜索全部冻住，"只是晚一点才可搜"的说法在这种规模上不成立。根因不在索引算法而在 schema：`blocks.parent_id`、`chunks.start_block`、`chunks.end_block` 三条外键没有索引，增量索引一篇文章要先删掉它旧的 2999 行，SQLite 对每个被删的块在那些表上全表扫一次。补完索引是 **2.06 秒**（1500 块 1.37 秒），仍然超"切换笔记 80ms"二十倍。剩下的两步：把 `index_one` 的多次写包进一个事务（现在每条语句各自提交），以及让读命令不必排这把锁（读用独立连接，或索引按块分批让出锁）。**只要还共用一把锁，长文档的索引就永远是同步路径上的隐形预算**。

**已按那两步做完**（2026-09-25）：

1. **后台索引改用第二条连接**。`Hub` 现在除了前台那条 `Index`，还持有一条 `Arc<Mutex<Index>>` 指向同一个 `index.db`；`spawn_blocking` 只在前一秒锁主锁取这两个句柄，随后整段补索引都在第二条连接上跑，主锁立刻还回去。WAL 下读不挡写，两条连接同时想写时靠 `busy_timeout(5s)` 等——等的是写者，读者不受影响。这条性质有测试钉住：`后台索引握着它那条连接时读命令照常返回`。
   **随之而来的不变量：GUI 里主连接只读。** 前台的写一律只动文件（`Hub` 的 `*_file` 那批），要写索引就走 `indexer()` 那条。谁在前台直接往主连接写，就让两条连接对同一篇各自"先删后插"——`busy_timeout` 只让它们排队，挡不住交错出来的重复行与丢更新。
2. **`reindex_note` 的三步（写块 + 重建出链 + 接回悬空入链）包进一个事务**（`Index::in_tx`）。rusqlite 的事务是连接态，所以被包的那些方法照旧各用 `self.conn`，不必改签名。

|---|---|---|---|
| 保存长文档后立刻"打开另一篇" | **3259ms** | **96ms**（连续三轮 98 / 102 / 93ms） | 80ms |
| 稳态切换笔记（没有后台在跑） | 21ms | 19ms | 80ms |
| 保存长文档后立刻搜索 | 冻住 | debounce 300ms 之后立刻出结果 | — |
| 打开长文档本身 | 676ms | ~300ms | 见 [ADR-004] |

**剩下的 96ms 不是锁**：稳态 19ms 说明读命令本身够快，多出来的那 80ms 是后台正在往 WAL 里写 5MB 时读方要付的代价。要压进 80ms，下一步是"补索引按块分批提交"（把一次大事务换成若干小批），不是回到共用一把锁。这条留在 [05] §M1 待做 里，但它已经从"隐形预算"降级成"超线 20%"。

### 文件监听（外部改动的收敛）

用户的笔记会被这个应用之外的手改：Obsidian、别的编辑器、同步盘、命令行。监听器的职责不是"通知有变化"，而是**让索引收敛到盘上现在的事实**。已实现（2026-09-26，`note-core::watch`）。

三条规矩值得单独写下来，因为它们都不显然：

1. **收敛不信监听器的分类，只看现在的事实。** notify 在 Windows 上把一次原子写报成 rename/remove/create 的任意组合，且顺序不保证。所以事件只当"这些路径可能变了"的提示：盘上有、hash 与库里不同 → 重索引；盘上没有、库里有 → 摘掉；盘上有而库里没有 → 收进来。**自我写入因此天然是 no-op**——原子写必然会触发事件，没有这道 hash 闸门，每次保存都会掀起一轮停不下来的事件风暴。
2. **监听器只攒批、不改盘。** 300ms 的 debounce + 路径合并（同一路径后到的覆盖先到的），过滤 `.note/` 等点目录、原子写的 `.名字.md.tmp` 与非 `.md`。但**监听器的过滤规则不等于扫描器的排除规则**（`node_modules/`、`target/` 下的 `.md` 会报上来），所以收敛那一步以 `is_indexable_rel` 为准——否则索引里多出一行，全库自检从此报漂移，而且没有任何路径会把它摘掉。事件走 §后端调用纪律 里那条**第二条连接**，主锁不碰。同批里某条路径读不到（正好在两次判断之间被删）只跳过它，不让整批失败：事件不会再来第二次。
3. **界面对事件的反应分状态。** 事件负载是"变了哪些路径"。浏览态：正在看的那一篇在名单里就重装载。编辑态：**绝不动**——用户手里有未落盘的东西，任何自动重载都是数据损坏。这一条是真机验收项，不是推论。
   而"手里有没有未落盘的东西"**只认字节**：判据写成"要写的 Markdown 与上次落盘的那份不同"，不是"发过改文档的事务"。发过事务而字节没变是真的会发生——文末的代码块/表格按 `↓` 要补一个**不落盘**的空段落当落脚点，账本守卫原先在纯光标移动时也会改一下邻居块的属性（已修，见下文"账本守卫只在真的改了文档的事务上跑"）。判据认错一次的后果不只是角标下不来：`unsaved` 还挡着这条重载，Obsidian 或同步盘改了这篇就永远进不来。真机验法：点开一篇 `甲\n\n甲` → 光标放进去 → 等 1.2s → 从盘上给它加一段"外部加的" → 屏幕上要看得见（探针跑过，修之前看不见）。

网络盘（OneDrive/NAS）上的监听与 SQLite 锁行为仍未验证，风险登记在 [05] §风险。

## 界面质感

优雅不是"加动画"，而是**一致的间距节奏 + 克制的色彩 + 精确的排版 + 每处反馈都在 100ms 内**。技术上要保证这些能做到：

| 方面 | 做法 |
|---|---|
| 设计 token | 一套 CSS 自定义属性定义色阶、字阶、间距、阴影、圆角；组件只允许引用 token，不允许硬编码数值。这是"看起来统一"的唯一可维护路径 |
| 原生质感 | `tauri-plugin-window-effects` 开 Windows **Mica / Acrylic** 材质背景 + 自绘标题栏（`decorations: false` 配 `data-tauri-drag-region`）。成本极低但对"像不像精品原生应用"影响最大 |
| 字体 | Inter + 思源黑体（子集化 woff2 本地打包，绝不联网取）+ JetBrains Mono；`font-display: swap` 防文字闪烁；中文标点悬挂与中英混排间距单独调 |
| 排版 | 正文行长约束 65–75 字符并居中；行高默认 1.75，设置页 / 命令面板可切三档（本机偏好，不写文件，docs/02 D39）；段落与 ATX 标题的块级对齐落成 `<div align="…">` 包裹（文档属性，docs/02 D40）；代码块不参与行长约束。笔记产品的高级感七成来自排版 |
| 暗色 | 三档（跟随系统 / 亮 / 暗）**落 localStorage 持久化**，主窗与速记窗共用同一份，灰阶不用纯黑纯白，按 WCAG AA 校验对比度。细节见下一节 |
| 动效 | 只动 `transform` / `opacity`（不碰任何触发 layout 的属性）；150–220ms `ease-out`；一律尊重 `prefers-reduced-motion`；正文区不做动画 |
| 反馈 | 全键盘优先（命令面板、块级快捷键）、hover/focus 有明确态、骨架屏与空态、流式回答按字幕节奏输出 |
| **降级档** | 设置里给"流畅优先"：关材质、关动效、缩略图降分辨率。老 Win10 集显机器上的保命开关，也是"任何情况都不卡"的执行手段 |

已评估但因代价过高而否掉的路径：**Electron**（体积与内存翻倍，性能优势为零）、**Flutter**（画布确实顺滑，但 Markdown 块编辑生态接近从零，为 5% 顺滑度付 6–12 个月）、**Rust 原生 UI（Slint/Iced）**（性能体积最优但缺成熟块编辑器，风险不对称）。除非未来要求"低端机上也要极致流畅"，不再重开。

### 主题的持久化与两扇窗（2026-10-08 落地）

用户问"为什么没有跟随系统颜色"。查下去**跟随系统本身是通的**（`matchMedia` 那条一直在跑），
坏在两处，而且都不是"判定写错"，是**这份判定没有一个唯一的家**：

- **选过的档不存**：`useTheme` 只把值放在 React state 里，`localStorage` 永远是空的。于是每次重启都
  退回"跟随系统"——亮色机器上看着像"根本不跟随"，暗色机器上看着像"有时候不跟随"。用户点过的那一下
  在第一次重启后就没了。
- **速记窗从来没被问过主题**：`Capture.tsx` 里**一条主题代码都没有**。它是 `decorations: false` 的
  复用无边框窗，`documentElement` 上不带 `data-theme`，所以吃的是 `:root` 那份亮色 token——
  主窗暗着，`Alt+Shift+N` 弹出来一块白底。这不是回归，是从第一天起就没接上。

口径收成 **`src/ui/theme.ts` 一个模块**，两扇窗都从它读，不再各写一份 `matchMedia`：

- `读主题 / 写主题 / 套主题 / 解析 / 盯主题变化` 五个出口。`写主题` 顺手落 localStorage；
  隐私模式下 `setItem` 会抛，try 住——主题存不下不是错，界面亮着才算。
- **主窗是唯一的写者**，速记窗只订阅。两处都能写会互相打转：两边都监听 `storage`、又都往回写。
- **`main.tsx` 在 `createRoot` 之前先 `套主题(读主题())`**。等 React 挂载完再改属性，暗色用户会先看到
  一帧白底界面——而那是启动时最显眼的一帧。
- `盯主题变化` 同时挂两条：系统偏好翻转（`mq` 的 `change`）与**另一扇窗改了**（`storage`）。
  `e.key` 为 `null` 时当作"可能相关"放行——那是 `localStorage.clear()`，跟着重算比漏掉它便宜。

原生控件的深浅由 `tokens.css` 里**已有**的 `color-scheme`（亮档 `light`、暗档 `dark`）决定，
这一轮没动它，但它正是块内那个 `<select>` 展开后那张列表跟着界面走的原因——弹出层归操作系统画，
不在我们的样式表里（见 §语言的自动识别与块内下拉）。

**测法是跨窗的**：速记窗按热键才懒建，所以先 `Alt+Shift+N` 让 `/json` 从 1 个 page 目标变 2 个，
再**只在主窗写 localStorage、不重载速记窗**——它必须靠 `storage` 事件自己跟上。两态各截一张：
`light` 下输入面底 `oklch(0.996 …)`、`dark` 下 `oklch(0.21 …)`。反向也测：把那条键 `removeItem` 掉，
速记窗回到"跟随系统"（这台机器系统本身是暗的，所以"暗"才是有判别力的那一半——
`data-theme` 缺失时吃的是 `:root` 亮色 token，正是修之前的样子）。

### 块级快捷键（2026-09-26 落地）

§界面质感 那条「全键盘优先」不是一句态度，得有一张表对着做。记法跟 Google Docs（Windows 用户熟），且**每一个手柄/菜单能做的操作都有键**：

| 键 | 做什么 |
|---|---|
| `Alt+↑` / `Alt+↓` | 把光标所在的整块上移 / 下移一格（= 拖拽 `⋮` 手柄的键盘版） |
| `Ctrl+Alt+0` … `Ctrl+Alt+6` | 正文 / 标题 1–6（键位一次给全，别让"下拉里选得到、键盘上按不到"） |
| `Ctrl+Shift+8` / `7` / `9` | 无序列表 / 有序列表 / 待办 |
| `Ctrl+B` / `Ctrl+I` | 加粗 / 斜体（行内码、删除线只有气泡与 `Markdown` 语法，没占键位） |
| `Ctrl+S` | 立刻落盘（自动保存之外留一手，给不信自动保存的人） |
| `Ctrl+Z` / `Ctrl+Y`（`Ctrl+Shift+Z` 同） | 撤销 / 重做。**必须绑在编辑器上**：`contenteditable` 里不接管它，浏览器会去撤销它自己的 DOM 输入记录，ProseMirror 的文档与历史栈就此分叉 |
| `Esc` | 正文里**不做事**：没有编辑态可退出，也没有源码框可回（整篇源码态 2026-11-05 撤掉，见 §块渲染） |
| `Ctrl+K`（`Cmd+K` 同） | 命令面板：一次输入同时解决"跳到哪篇"与"做个动作"。见下 §命令面板 |
| `F11` | 进入 / 退出演示（同窗全屏、只读）。没开笔记、在设置页或属性页时这一键不接管。见 §演示模式 |

三条实现口径，都不显然：

- **一律走 `applyBlockTypeToSelection` / `moveBlock`**，与手柄、下拉、`/` 菜单同一份代码。改块类型时选区碰到的每一块一起改（结构化引用里仍只落到光标所在的子块，D43），快捷键另写一套落盘逻辑，就是"按了生效、点出来不生效"这类分叉的成因。
- **移动之后必须把光标放回那一块**。`moveBlock` 是整树替换，选区映射后可能落到别的块上，于是"连按两次 `Alt+↓`"第二次移的就不是同一块——这种"第一次对、第二次错"的 bug 只有显式放回选区能断根，也必须有测试钉住。
- **到边界不发空事务**。`Alt+↑` 已经在第一块时返回 false，让浏览器处理这个键；返回 true 会吞键，还会白标一次脏、800ms 后凭空写盘。

**常驻工具栏的内容**（2026-09-26 定，2026-09-28 补结构块与表格那一组，2026-10-28 补高亮与颜色，2026-11-02 补格式刷与上下标，2026-11-03 补块对齐；别处只引用不重列）：块类型下拉（那 10 种）· 加粗 / 斜体 / 删除线 / 行内码 / 上标 / 下标 / 链接（带输入框）· 文字颜色 / 底色（两枚）· 块对齐（左 / 居中 / 右 / 两端，只作用于正文与标题）· 清除格式 · 格式刷 · 插入分隔线 / 引用 / 代码块 / 表格 · **光标在表里时换成：加行 / 删行 / 加列 / 删列 / 本列靠左 · 居中 · 靠右 · 取消对齐** · 上移 / 下移这一块 · 撤销 / 重做。口径：

- **按钮上一律是图标，不写字**（2026-09-28 定，用户原话「文字算个什么意思呢」）。此前是 `B` `{}` `链` `清` `+行` `⇥` 这种混排：`链` / `清` / `+行` 是**拿词当图标**，一排里既读不出层级也扫不出动作。现在文字全部退到 `title` + `aria-label`（悬停与读屏都从这一句来），图标一张表：`src/editor/icons.tsx`，工具栏与选区气泡**共用**——两处不同就是两副面孔。图标走 [06] §1 第 13 行早就定好的 Lucide，按需 import 打进包（离线优先，连图标都不许联网取）；尺寸 `1em` 随字阶、描边 `currentColor`，所以 hover / `.on` / `:disabled` 那三条改颜色的规则自动管到图标。
  **Lucide 没有"加一行 / 删一列"这类名字**（1.48 里没有 `row-insert` / `column-delete`），四枚自己画，但照同一套参数（24 视野、`currentColor`、线宽 2、圆头），且**四枚共用同一个加减记号**、只差横条还是竖条——学会一个学会四个。`INSERTABLE` 的 kind 与图标名同名（divider / quote / table），对不上号时 React 直接炸而不是静默画个加号：漏一个图标在界面上是"这个按钮没脸"，比编译失败难查。
- **颜色与高亮是"先有能往返的字节，才有按钮"**（2026-10-28，见 [02] D35）：高亮写 `==文字==`，颜色写 `<span style="color:#rrggbb">`，底色写 `background-color` + 8 位十六进制。**文字颜色与底色是两枚按钮**（Word / Google Docs 那一路），不合成一枚"调色板"：换字色与换底是两件事，合成一枚时每次都得先认"我在选哪一行"。按钮下沿那道色条画的是**光标处当前的颜色**（绝对定位、不占高度——工具栏高度是契约）。色板只有六档 + 去掉，存在 `src/editor/colors.ts`（**落盘要真色值，因此这个文件在样式护栏的放行名单里**——禁区是"组件里随手写颜色"，不是"文件里要一个色值"）。**高亮收在底色面板的第一格**：它就是"默认那一档底色"，单独占一枚按钮等于同一件事摆两个入口；它是语义色（`--md-mark`，跟主题走），不占六档里的任何一格，与其余底色互斥。选中态用一圈 accent 描边而不是打个勾（色块只有 20px，勾会把颜色本身盖掉）。清除格式一并抹掉这三档。
- **上标 / 下标是精确小写的 `<sup>` / `<sub>`**（2026-11-02，见 [02] D38）：只认这一种形状，带属性或大写的标签继续是字面文字。两枚 mark **双向互斥**（`excludes` 两边都写，否则只有一个方向有效），序列化排在**最外层**——`<sup>**粗**</sup>` 能原样往返，反过来 `**<sup>粗</sup>**` 会分叉。行首不判 HTML 块、检索正文剥掉标签，两条与颜色 span 共用同一套判据（`classify` 例外表 / `plain_inline`）。
- **块对齐是精确包裹，不是 CSS 偏好**（2026-11-03，见 [02] D40）：正文 / ATX 标题的居中 / 右对齐 / 两端对齐落成 `<div align="center|right|justify">` + 空行 + 正文 + 空行 + `</div>`，左对齐就不留包裹。**只认这一种精确形状**（单块、空行齐全、`align` 属性），别的 HTML 继续不透明、按 `raw` 回显；对齐块因此不走 `simple()`，重建会丢包裹。`left` / `center` / `right` / `justify` 四档走 `src/editor/blocks.ts` 的 `applyBlockAlign`：选区覆盖的**段落与 ATX 标题**一笔事务全改，列表 / 引用 / 代码 / 表格 / 图片 / setext 标题跳过并提示"已跳过 N 个块"，全部已是目标档时不发事务。**setext 标题不开放**：内核只认包裹里的 ATX，前端标题节点也没有"setext / ATX"属性，改任何一处都会重建成 ATX（判据是 `mdRaw` 第二行是否为 `===` / `---` 下划线）。**粘贴经 `parseHTML` 的 `data-md-align` 读回 `mdAlign`**（只认三档白名单），否则同篇剪切再贴一次就丢居中。**混选时按可对齐块的共同档亮灯**（`共同对齐`）：不同档一盏不亮，不拿第一块冒充整批的结果。**改对齐要让 `mdSig` 变化才落盘，改回 `left` 又回到装载时的签名**，所以没碰过的块继续按 `raw` 逐字节回写。入口在常驻工具栏与选区气泡（表格里不出现），气泡与工具栏共用同一份纯函数；表格列对齐是另一套（写分隔行），不要混用。
- **清除格式不去掉链接**。只抹加粗 / 斜体 / 删除线 / 行内码 / 上标 / 下标 / 高亮 / 颜色并把块退回正文——`unsetAllMarks` 会顺手把 link 抹掉，而 Notion / 语雀 的「清除格式」都不该删用户挂上去的链接。
- **格式刷只抄能往返的那一层**（2026-11-02，见 [02] D37）：行内加粗 / 斜体 / 删除线 / 行内码 / 上标 / 下标 / 高亮 / 字色 / 底色，加块类型（正文 / 标题 1–6 / 无序 / 有序 / 待办）。**源取选区里第一个有字的字符**和它所在的顶层块，不取格式交集（混合选区求交集几乎总是空）；目标选区碰到的块全换类型，行内标记**先摘后加**，目标自己的链接保留。代码 / 引用 / 图片整块跳过并提示一句，表格只跳块类型、格内文字照刷；源在表格格子里时块类型为 `null`（只抄行内），矩形框选多格时**逐格刷行内、不转块类型**，表格不记"整块没动"；字号 / 居中 / 缩进 / 链接 href / 表格列对齐 / 列表层级 / 待办勾选不刷。**开刷 / 关刷只发 meta 事务**（`addToHistory: false`，不标脏、不进撤销栈），**手势结束才落笔**（左键 `mouseup`——包括拖到正文外松手，键盘只在松开 `Shift` 时；右键与按住 Shift 连按方向键的中间 `keyup` 都不算），不在 `selectionUpdate` 上刷，否则拖到一半就刷掉前几个字；单击单次、双击连续、`Esc` 或点出正文收起（`Esc` 听在 `document` 上，焦点停在工具栏按钮也能收）。行内与块类型合并成一笔可撤销事务，目标本来就是这个格式时 `tr.doc.eq` 拦掉、不发文档事务。入口在工具栏「清除格式」旁与选区气泡，共用 `src/editor/formatPainter.ts`；待命时正文换成十字光标（`data-md-paint` 由插件 view 只写 DOM，不发事务）。
- **能插的结构块只有一张表**（`INSERTABLE`：分隔线 / 引用 / 代码块 / 表格）。工具栏按钮与 `/`、`⋮` 菜单都从它生成，加一种只改那张表。骨架的**源文本必须与 md-kernel 认得的字节一致**，所以它们在 `testdata/roundtrip/06-插入骨架.md` 里各占一块、由 Rust 侧钉住——前端自己发明一种"表格"就是点了必丢。

  - **工具按钮先看选区**（2026-11-05）：选中正文 / 标题 / 列表项时，代码块与引用把**选中的整块**转过去，不再在当前块后面另插一个空骨架。代码取每块的 `textContent` 按行拼接（行内标记不进代码），引用取每块在文件里的源文本（`**粗**`、标题 / 列表记号原样保留，块锚不包进去）并逐行补 `>`；跨几块就合成一个结构块。选中图片 / 表格 / 代码 / 引用这类包不住的块时**不动文件**，只说一句"只能包住正文、标题和列表项"。表格与分隔线没有"包住文字"的写法，有选区时落在选区最后一块之后。选中半行也按整块算——Markdown 的块结构只认行，块级动作按块生效与列表 / 对齐同一条口径。**转换沿用第一块与上一块之间的空行**：作者多留的空行（`"\n\n"` 及以上）不因换了块类型被压成一行；文件开头仍不许带前导空行（D28 同一条）。**这条多行空行只对结构块生效**（2026-11-05 二轮复查）：代码 / 引用 / callout / 公式 / 表格 / 分隔线是从原块整块换过来的，空白属于那个位置；段落 / 标题 / 列表项 / 图片的 `mdGap` 只可能来自拆块时 attrs 被整份复制，不是排版——拆出来的右半按现算的一行空行落盘（探针：首块 gap `"\n\n"` 拆一次，旧口径落盘 `甲\n\n\n乙\n\n\n丙`）。
  - **没有选区时按光标在块里的位置落点**（2026-11-05）：行首 → 结构块插在这一块**前面**，原文字被挤到下一块；行中 → 把这一块拆成两半，结构块落在中间；行尾 → 插在这一块后面（旧行为）。空块直接换掉，不留一个空段落。落点跟着新块走：代码 / 引用进正文开头，表格进第一格，分隔线留在映射后的位置。结构化引用、表格格子与不透明块内部没有可拆的文字行，仍按旧语义插在其后。**拆出来的右半要重新记账**：`tr.split` 把左半 attrs 整份复制过去，编号会退回 `1.`、待办会带着上一项的勾、行内字段（`k:: v`）会在文件里出现两次——`校正拆分右半` 把编号接着往下数、勾清掉，行内字段按"留在块尾"归属（右半有字就跟着后半走，右半是空的就留在左半），右半的 `mdRaw` / `mdSig` / 块锚也在这里一并清掉。不等 `LedgerGuard` 来做，是因为摘左半字段要用 `setNodeMarkup` 整段替换左半，守卫反查映射时会把左半也判成新造的、顺手把 `mdRaw` 清掉，序号就落回 `1.`（2026-11-05 二轮复查，用例钉住五样）。
  - **setext 标题的块锚在下划线前那一行**：`块原始源` 先按内核 `trailing_id` 的口径试末尾——分隔符认空格 / 制表符，锚后允许行尾空白，摘的时候连分隔空白一起摘；落空再按"标题行 + 换行 + 下划线"拆一次只摘中间那行的尾巴。否则 `> 标题 ^b-1\n> ===` 会把锚漏进正文，制表符分隔时还会把 `\t` 带进引用（2026-11-05 二轮复查）。
  - **块类型下拉与 `Ctrl+Alt+0–6` 对选区里碰到的每一块一起生效**（2026-11-05）：只改第一块会出现"整段选好、点标题、只变了第一行"的错觉；图片 / 表格 / 本来就是这个类型的块跳过。
- **`/` 菜单选结构块是整块替换，`⋮` 菜单是在其后插入**。斜杠触发时那一块里只有那个 `/`，往后面插会留下一个空段落、`/` 还得再删一次；手柄对着的是有内容的块，只能插在后面。
- **新插入的块自带一个空行，但正文第一块除外**。紧贴上一段的 `---` 会被 CommonMark 读成那段的 setext 二级标题下划线（插个分隔线把上一段变成了标题），引用与表格的首行同理会并进上一段；而文件没有 front-matter 时正文第一个字节就是内容，给"第一块"补空行等于在开头凭空多一行——有 front-matter 时那个空行倒是必须的（它属于 `---` 与正文之间）。同一条规矩管着 `moveBlock`：**挪到最前面的块照抄原来第一块的 gap**，写死 `""` 会让 front-matter 与正文粘连。
  **2026-11-02 复查补上另一半**：**删掉第一块时，下一块继承的 gap 也不能留**——它原本是"与前任之间的一整行"，前面已经没有块了，留着就是文件开头凭空多一行（用例 `删掉第一块`）；原首块自己的前导空行则原样保留，那是文件的字节，不是排版产物。
  **2026-09-29 复查补了后半句**：那条"自带空行"隐含的前提是"上一块已经把自己的行终止了"。文件**最后一行本来不带换行**时（未改动的块原样回写、不补 `eol`），只给一个 `"\n"` 就成了 `末段\n---` → 内核读成 `heading "末段"`；`末段\n| 列 |…` → 整张表被吞进上一段（两条都是 `note parse` 实测，不是推断）。所以 gap 现在按 `out` 的实际结尾补：没终止就先补终止符，再补空行。
- **源文件"结尾有没有换行"是它的习惯，不由我们改**——但判"最后一块"必须看**"最后会写字节的那一块"**，不是"最后一个 child"。`docToMarkdown` 的 `eol` 原先按后者判，而表格后面那个落脚点**故意不落盘**：它一存在，真正写出的最后一块就不再是最后一个 child，本来不带结尾换行的文件就被多写出一个 `\n`。**第一版补法是"收尾统一削掉一个 `\n`"，那是止痛贴而且会伤人**：删掉最后一块之后，前面那块自带的换行也被削走了（`a\n` 写成 `a`），而它是未改动的块、`raw` 就是文件本来的字节（第四轮复查实测钉住了这条）。现在从末尾往前找第一个 `会写字节` 的块来判 `eol`，落脚点与结尾习惯各管各的。
- **回车拆出来的那一半不许留着原块的账本**（守卫在 `schema.ts` 的 `LedgerGuard`）。ProseMirror 拆块时把 attrs 复制给两半，于是 `mdRaw` / `mdGap` / `mdId` / `mdKind` 同时描述着两块，四条后果全是"屏幕上生效、落盘就错"：① 新块沿用原块的 gap → 没有 front-matter 的文件里第一块按回车，两块之间没有空行，重新解析**并回一段**（那次回车等于没按，真机抓的）；② 锚点落在文档序靠前那一半 → 段首回车时 ` ^b-xxx` 挂到新产生的**空块**上、正文反而没了 ID，指向它的反向链接从此指向空；③ `mdKind` 与实际节点类型不一致（拆 `mdItem` 得到的是 `mdParagraph`，kind 还写着 `bullet`）→ 序列化器认为它是列表的延续、不给空行，两行粘回一个列表项；④ 空块自己还挤出一个空行。口径：**重复的源切片只留原块那一份**（新块按新建处理，gap 现算）、**ID 只给有内容的那一半**（空块在 Markdown 里不存在，不配拥有 ID）、**重新产出后是空白的块不落任何字节**（未改动的块不算——它的 `raw` 是文件本来的字节，空白也得原样留）。判据不能只看"相邻两块 `mdRaw` 相同"：作者故意写的相邻同源块（`甲\n\n\n甲`）也满足它，随便改一处就会把另一块的空行压掉（2026-11-02 复查抓到，用例 `相邻两块源切片相同、真改其中一处`）。现在要**新造的 + 另有同源**两条同时成立——起点由反向映射 `mapResult(...).deleted` 认定，这份源切片在文档里还得另有同源；粘贴一整块也落在这条里（复制来的账本让新块贴着原块，落盘并回一段，用例 `粘贴一整块`）。撤销删除放回来的孤立原块不满足"新造"，账本跟着回来。守卫只认**局部改动**：载入、`moveBlock`、插入结构块、打签名走的都是整树替换，那里出现的"相邻两块源切片相同"是文件本来的样子（`甲\n\n甲\n`），照拆块产物去清就会把作者故意留的空行改没——那是另一种改用户内容。**2026-11-05 二轮复查补上段落 / 标题的回车**：PM 默认的 `splitBlock` 把 attrs 整份复制给两半，行内字段因此会在文件里出现两次（`甲 k:: v` 拆一次 → 两段都带 `k:: v`）——`正文回车` 接过分段 / 标题的 Enter，拆块形状照搬 `splitBlock`（块尾续一个默认正文块、段首与段中照抄类型与层级，所以标题末尾回车得到的是正文而不是又一个标题），字段归属与账本清理由 `校正拆分右半` 统一处理；多行 `mdGap` 的保留同时收窄到**结构块**，文字块拆出来的右半按现算的一行空行落盘。

### 演示模式（2026-11-05 落地）

演示是**同一扇窗里的只读全屏**，不是新开一扇窗，也不是另一种渲染路径。

- **不是 `Mode` 的一档**。`App.tsx` 用独立的 `presenting` 布尔量；做成 `Mode` 会逼编辑器按 `key` 重挂载，长文的滚动位置、撤销栈与图片解码全丢。演示时打开的还是同一篇、同一个 ProseMirror 实例，退出后不回到篇首；全屏重排后像素位置可能略有偏移，但文档与历史栈没有重来。
- **进之前先存，而且存的必须是"现在这一份"**。`enterPresent()` 先 `await persist()`，失败就中止并提示"这篇还没保存"；全屏调用失败同样中止——四周还留一圈窗口边框却叫"演示"，比不进去更让人困惑。键盘监听只建一次，所以 `enterPresent` / `exitPresent` 每渲染都挂到 ref 上再调（同 `落子用`）：自动保存会换掉 `savedDraft` / `baseHash`，抓住旧闭包就会拿旧哈希再存一次，对同一份文件误报冲突。进入前还会撤掉待触发的自动保存计时器，并用同步的"进入中"标志挡住连按 / 连点——窗口调用是异步的，光靠 `presenting` 挡不住第二次抓窗口状态。
- **窗口状态要原样还回去**。进之前记 `isFullscreen()` / `isMaximized()`；退出时只在"本来不是全屏"时 `setFullscreen(false)`，再按记录补 `maximize` / `unmaximize`。用户本来就在全屏，退出演示后仍留在全屏，不去碰最大化状态。浏览器里退回 `document.documentElement.requestFullscreen()`，没有 Tauri 窗口时也能演示。
- **只读要锁三层**。① `BlockEditor` 的 `editable={false}` 管 ProseMirror；② 组件自己的 mousedown 与拖拽手柄会在只读正文上主动 `setEditable(true)`（"点哪编辑哪"），所以另传 `locked`，由 `lockedRef` 挡住点击、手柄、拖到一半的落块、查找快捷键和链接导航；③ NodeView 里的原生控件不归 PM 管——代码语言下拉随只读 `disabled` 且 `改语言` 自带 `view.editable` 闸，图注框随只读 `readOnly`，演示 CSS 把图注工具条收走。拖选仍可用，方便复制文字。
- **链接不能在演示里导航**。只读正文里的 `<a href>` 会被浏览器当普通链接，点一下整个 WebView 就跳到站外，而这扇窗没有地址栏和后退。`editorProps.handleDOMEvents.click` 在 `locked` 时拦掉链接的默认行为；要"点链接真打开"应走系统浏览器，不能用 WebView 导航顶替。
- **界面壳收在 CSS 里，不在 JSX 里逐项条件渲染**。根节点挂 `data-present="1"`，`.titlebar` / `aside` / `.note-head` / `.editor-tools` / `.bubble` / `.handle` / `.slash` / `.drop-line` / `.md-img-bar` / `.block-drag-ghost` 统一 `display:none`；大纲、链接面板、保存提示、错误横幅与文末留白由组件条件摘掉。**AI 坞也走 CSS 收起、但不卸载**——对话轮次与未发送草稿都是组件内部状态，为了收一层壳把用户聊到一半的内容扔掉，代价不对等。这些规则与 `.present-surface` 在 `base.css` **未分层**区——`aside` 带着 Tailwind 的 `flex` 工具类，分层里的 `display:none` 压不过 utilities 层。
- **浮层（HUD）是唯一的界面壳**。篇名 + 「退出演示 Esc」贴右上，指针 / 键盘一动亮，停手 2.4 秒自己收（只动 `opacity` / `transform`）；藏起来时撤掉按钮的 `tabIndex`，藏着的按钮不进 Tab 序。**焦点停在浮层里时不做这次收起**——`aria-hidden` 不能盖住一个仍有焦点的按钮，否则键盘用户眼看按钮消失、Tab 序却停在无名的空处；焦点离开后的下一拍再收。演示期间全局键盘只认 `Esc` / `F11`：其余快捷键一律不接管（查找栏那条也在 `locked` 时不响应）；`Esc` / `F11` 走**捕获**监听，格式刷、AI 坞这些在自己的 Esc 上 `stopPropagation` 的浮层吞不掉退出这一键。长按的按键重复不参与"进入 / 退出"，免得松手时又弹回演示。
- **补篇名只在缺的时候补**。正文平时不单独显示标题（多半已写在第一块的一级标题里）；演示时若第一块不是标题，屏幕顶上就只剩一片没有名字的字。`要补篇名()` 判第一块 `kind`，是标题就绝不重复补。
- **Tauri 权限要显式给**：`core:window:allow-set-fullscreen` / `allow-maximize` / `allow-unmaximize`（`src-tauri/capabilities/default.json`）。少了它们，调用在运行时才被拒。
- 入口：管理行的「演示」（`title="全屏演示（F11）"`）、`F11`、命令面板「进入演示（全屏、只读）」，三处都走同一个 `enterPresent`。
- 测试：`src/ui/present.test.ts` 12 条（篇名补不补 3 条 + 接线守卫 9 条：`data-present` / `present-surface` / HUD、三层只读锁、链接拦截、F11 新闭包与单飞、演示键盘捕获、窗口权限、CSS 壳隐藏与 AI 坞不卸载、焦点不收浮层）。`roundtrip.test.ts` 另有一条"只读时语言下拉写不进文件"。真机证据在 [05] §M2 进度。

### 块渲染：不透明块的显示形（2026-09-28 落地）

引用 / 表格 / 代码 / 公式 / Callout 在 md-kernel 里是**不透明块**（整块 echo 源文本，见 [02] D9），
此前界面上就是把 `` ``` `` 与 `| 列 | 列 |` 原样摊在屏幕上。这一档把它们画成渲染后的样子，
但**没有**动"序列化产不出这些语法"那条事实（D27）——做法是两副面孔。表格后来单独接管成了网格
（见 §表格网格），代码块、公式与分隔线随后也各自转成单面（见 §围栏账本、§公式单面与分隔线原子块）；
引用 / Callout / HTML / 未识别语法仍是两副面孔——其中引用 / Callout 的 `>` 与 `[!type]` 后来进了
前缀账本（见 §引用 / Callout 的前缀账本），点进去看到的正文不再带语法记号。

**整篇源码框是另一回事（2026-11-05 撤掉）**：那是把整个文件塞进一个 `textarea` 编辑，顶栏一枚
「源码」就能在"整篇源文本"与"所见即所得"之间来回切。它与本节的两副面孔只共享"源文本"三个字——
前者是**文件级**的第二个编辑面（屏幕上的一切都能被绕过），后者是**某一块画不出来**时的退路
（HTML、未闭栏的代码、拼不回的表格）。用户拍板的原话是"看到什么就是什么"，所以文件级那一面撤掉；
块级这一面留着，否则那几类块就彻底不能改。撤掉的连带项：顶栏按钮、命令面板「看这篇的源文本」、
正文 `Esc` 出口、整篇 `textarea` 与 `Mode = "source"`；`dirty` 也就不再有"源码草稿"那一路，
只剩 `inlineRev > 0`。

| | 显示形 | 源文本形 |
|---|---|---|
| 什么时候 | 该块没有光标 | 光标在这块里 |
| 是什么 | `render.ts` 从源文本画的只读 DOM（`contenteditable=false`） | 一直是那份 `pre > code`，可直接改源码 |
| 落盘 | **完全不参与**：`docToMarkdown` 读 `mdRaw` 与节点正文，不 import `render.ts` | 同一条路 |

四条实现口径，都是这么挖出来的：

- **显示形是源文本的投影，不是第二份状态**。Callout 标题能点着折叠，但那只改 DOM 上的
  `data-folded`，**不写回源文本里的 `-`**；改了这块的源码，折叠就回到源文本写的那一档。
  要"界面上的状态"与"文件里的字节"各活各的，就得重开 [02] 的 I1，为一个小箭头不值。
- **切换只写 DOM 属性，不发事务**（`OpaqueFace` 插件，与 `FocusIndicator` 同一条纪律）。
  发事务会走 `onUpdate` → 标脏 → 停手 800ms 把"只是点了点别处"的一篇写盘。
  测试钉的是**这条**：光标逐个进出不透明块之后 `state.doc` 还是同一个对象、产出逐字节等于源文件。
- **重画发生在交出焦点那一刻，不在击键路径上**。ADR-004 量的 2999 块打字 p95 0.2ms 就悬在
  "每次按键重画一张表格"这种顺手写法上；`update()` 只置脏，`补渲染()` 在块失去焦点时才算。
- **画不来的必须继续显示源文本**（`data-md-view="none"`）：HTML、未识别语法、带子项的列表项。
  把内容收进一个空宿主里等于在界面上吃掉这一块——那是第一轮块编辑器的死法，换了个形式也不许认。
  带子项的列表项要画成嵌套列表，就得同时决定"子项的字节属于谁"，那是序列化口径（D22），不是显示层该碰的。
- **接管只限"左键、无修饰键的 mousedown"**（复查抓到的回归，`分派岛上鼠标`）。岛里的事件原先
  一律 `return true`，PM 与浏览器就都收不到——右键菜单、`mouseup`、双击选词、shift-点击扩选区
  一起被吞，而想扩选的人拿到的是"选区清空、光标跳块首"。现在 shift-点击按坐标扩到整块，其余
  交回默认路径。判据提成纯函数放在 `schema.ts` 外层：**写在 NodeView 里的分支没法从外面喂事件**，
  不提出来就只能靠真机点十下来猜。
  已知仍做不到：在显示形上起手的拖拽只能到**整块**粒度（岛里的字符位置 `posAtCoords` 读不准），
  块翻回源文本形之后才是正常手感。

真机（CDP 可信鼠标/键盘，逐字节比对文件）抓出两条，都不是 jsdom 测试能照出来的：

1. **Chromium 不会把插入符放进 `contenteditable=false` 的岛里**。"点一下渲染出来的表格就退回
   源码"指望浏览器与 PM 的默认行为是**不成立**的——点了什么也不发生。必须由 NodeView 自己
   在 `stopEvent` 里接管 mousedown、发一个落进该块的选区。
2. **围栏的 info 串带空格就画不出来**：`` ```rust // 标记 `` 里旧正则要求 info 是"一个不带空格的
   词"，整块静默退回源文本，看着像渲染坏了。CommonMark 的 info 可以是多词，语言只取第一个词。

另外改掉一处观感：打开一篇时 PM 的选区可能落在文末，于是**最后一块顶着源码示人**。现在
判"是不是源码形"要多问一句 `view.hasFocus()`——没有焦点就没有插入符，那块就该是显示形；
焦点变化不发事务，所以插件自己听 `focus` / `blur`。

测试 76 → 91 项（`render.test.ts` 21 项纯函数 + 往返护栏里 15 项"渲染不改字节"与两副面孔的切换）。
门禁：`node scripts/check.mjs` 全绿；`pnpm test` 91 项。

### 代码块的着色（2026-09-30 落地）

用户报"代码块没有按语言显示不同样式"。此前它连一个 tokenizer 都没有：`codeDom()` 只产出一个
`<code>` 文本节点，整块一个颜色。**选的方案是 highlight.js 按需子集**（不是自写词法，也不是 shiki）：
`highlight.js/lib/core` + 手工注册 26 种语言，实测打包 **+129KB（gzip +44KB）**；shiki 那种
TextMate 级准确要带 wasm 与主题 JSON（MB 级）且是异步着色，显示形还得处理"先画后着色"的闪烁，
不在这一档。三条边界都不显然：

- **只活在显示层**。序列化读 `mdRaw` 与节点正文，永远不读着色产出的 DOM——着色画错最坏是
  "看着不对"，绝不许"落盘不对"，这是 §块渲染 那条纯投影纪律的延伸。
  **代码块自 2026-09-30 起只有一面**（围栏进了账本，可编辑的那一面本身就是渲染好的卡片），
  所以着色走 `CodeHighlight` 的 `Decoration.inline` 而不是 NodeView 自己画：PM 的可编辑 DOM
  只能这样上色。两条实测结论：
  - **必须限视口**。不限视口的第一版在"30 个 30 行代码块"的极端文档上，中位数没变（PM 重排
    本来就 6.6ms）但 p95 从 10.6 顶到 16ms、最差一帧从 26ms 顶到 **112ms**——一次按键要重建
    三千多个装饰。收口成"只装饰视口 ±4000 字"（`posAtCoords` 量，PM 的 `visibleRanges` 是内部
    实现、类型里没有）之后，与"根本没装这个插件"的基线持平：p50 6.6 / p95 11.3 / 最差帧 26ms。
  - **装载那一刻按"开头一屏"算，既不"全装饰"也不"先不装饰等上报"**：前者就是上面那 110ms 的
    来源，后者会让滚到的位置先白一帧再上色。屏幕外的等第一次滚动上报（rAF 节流）。
- **产出必须过白名单**。highlight.js 给的是 HTML 串（正文它自己转义），而我们整条显示形是
  DOM 构造的。所以解析一遍，**只留 `span.hljs-*` 与文本**，不认识的结构连它的文字一起降级成
  文本——降级而不是丢弃。用例直接钉注入面：代码内容写成 `<img src=x onerror=alert(1)>` 时
  不许出现 `img` 元素、`innerHTML` 里除了 span 不许有别的标签、文字逐字相同。
- **认不准就不着色**（未知语言、`text`/`txt` 这种明说"我要纯文本"的、以及超过 20000 字符的
  输入）。超长那条是给性能留的：显示形的重画发生在块交出焦点那一刻，同步的 tokenizer 碰上一坨
  几万行的日志就会把那一拍钉住——**宁可平白，不可卡**。
- 颜色一律走 `tokens.css` 的 `--code-*`（护栏禁字面量颜色，而双主题本来就该由 token 承担），
  `base.css` 里只做"hljs 类名 ↔ 语义"这一层翻译；认不出的类保持正文色。
- 别名表只补 **hljs 实测不认**的那些（`shell` / `htm` / `vue` / `env` / `mdx` / `csharp` …）。
  `js` `rs` `golang` `toml` `zsh` 它自己就认，别在这儿重复——重复的条目会让人以为"改这张表就够了"。

### 语言的自动识别与块内下拉（2026-09-30）

用户拍板"识别出来就写进 ` ``` ` 后面"。这与"打开一篇不许动它"顶牛，所以口径是**猜归猜，
只有这一块真要落盘时才把那个词写进去**：

- 唯一的判据函数是 `blocks.ts` 的 **`有效开栏(node)`**，序列化与显示（`带围栏`、语言牌）都读它。
  分叉的后果是"牌上写着无、文件里多了 `py`"——那是"屏幕上生效、落盘就错"的反向版本，同样不可接受。
- **只在开栏没有 info 首词时猜**。作者写了 `klingon` 就永远留着 `klingon`：把别人写的东西
  改成我们的猜测不叫识别，叫覆盖。认不出（`highlightAuto` 落回纯文本）也给 null，绝不编一门语言。
- **太短与单行不猜**：实测 `a=1` 会被判成 `ini`。门槛是 ≥ 24 字且跨行。
- **证据不够就不落笔**：`highlightAuto` 给的是相对分数，光看"它返回了哪个语言"会把 Python 判成
  Ruby（真机就是这一版）。试过"第一名要领先第二名 1.5 倍"，结果把**对**的猜测也一起枪毙了（js 实测
  1.2 倍、rust 1.33 倍）——门槛设在高处不是变严，是变哑。最后按实测分布定成**绝对下界**：
  js 6 / rust 8 / py 9 / bash 15 / sql 5 / c→php 5 / 中文散文 0，取 `relevance ≥ 6`。
  留在 6 之下的是"证据本来就等于没有"的那一批（sql 那档偶尔会漏），而不是"猜得准但被门槛卡住"。
- 识别比指定语言贵十倍（实测 30 行 9ms、120 行 38ms），所以三条防线：装载时不算（牌先显示
  空，视图建好后从缓存刷）；**正在打字的那一块沿用上一次的答案**；一轮重算最多花 8ms 猜，
  超了就下一轮——少一帧颜色可以，把打字拖卡不行。
- 语言牌是个**真 `<select>`**（用户点名要块内可点），选项就是 `语言清单`——每一项都实测能被
  hljs 认出来，"选了不上色的语言"这种摆设不给。文件里写了个清单外的词就临时加一条
  "xxx（文件里写的）"选项，别让控件显示成"无"。选语言 = 改 `mdFenceOpen` 的首词，
  缩进、围栏长度、后面那串 `// 注释` 都原样留着。`stopEvent` 对它的每个事件返回 true：
  那一下是选元数据，不是"点进块里改源码"。
- **牌的样子**（用户："下拉框样式优化一下"）：`appearance: none` + 透明底 + 无边框，字色走
  `--text-disabled`、12px 等宽；那个箭头是 `.md-lang-box::after` 用 `border-top: 4px solid currentColor`
  画出来的三角形，不是字符——字符箭头（`▾`）在不同字体下沉降和大小都不受控。展开后的列表**必须显式给
  `option { background: var(--bg-raised) }`**：那是原生弹出层，不吃我们的容器背景，不给它就跟着
  操作系统的默认色走，暗色界面里冒出一块白底。猜出来的那一项标 `[data-guessed]` 用斜体示"这是猜的"。
- **牌刷新有三条延后的路**（视图更新完再刷、`待刷牌`、装载后那一帧），延后的路上编辑器可能被销毁。
  PM 的 `destroy()` 会把 `docView` 置空，之后 `nodeDOM(pos)` 直接抛 `descAt of null`——公开 getter
  `view.isDestroyed` 就是判这个的（1.42 的类型里有），所以 `牌刷新` 第一行先问它。这一条是**门禁**抓出来的：
  单跑 `vitest` 时 250 项全过，但那些未捕获异常让进程退出码变 1，`pnpm test` 那一档红。
  **只看"Tests passed"那一行会漏掉它**，必须跑完整门禁。

**真机四步**（探针笔记，四种开栏各一）：开局牌 = `py(猜) / js / klingon / (空)`，文件里四道
开栏一个字节没多；下拉选 `go` → 落盘 `​```go`；在裸块里打一行 → 落盘 `​```py`，而没动过的
短块与 `klingon` 块照原样；探针事后逐字还原。

**顺手修掉一条长行的显示问题，它同时暴露了一个级联陷阱**：显示形此前跟着 prosemirror-view 自带的
`.ProseMirror pre { white-space: pre-wrap }` 折行，一条长语句被切成三行、缩进语义当场没了。改成
不折行 + 横向滚动时，写在 `@layer components` 里的覆盖**根本不生效**（真机量到的计算值仍是
`pre-wrap`）——第三方样式表是**未分层**的，而未分层的声明在级联里赢过所有 `@layer`，特异度再高也没用。
只能把这一条也放到未分层，并在文件里写明"放这里的唯一理由是必须压住未分层的第三方声明"。
源文本形仍然折行：那一面是在改字，横向滚动会让光标跟着跑出可视区，两副面孔口径不同是有意的。

**仍然没做的一件**：列表项里嵌的代码块整块退回源文本（看得见 ` ```python ` 两道围栏）。根因不是
着色，是"带子项的列表项不画"那条既有限制——它的正文是整棵嵌套树，要画就得同时改"子项的字节属于
父项 `raw`"这条序列化口径（[02] D22），不是显示层能自己决定的。

### 围栏账本与内核逐条对齐（2026-10-08 第五轮复查）

上一轮把围栏搬进 attrs 之后复查，抓到**六条只有"把节点整个交出去一遍"才看得见**的缺陷。
共同形状是：装载 → 逐字节回写那一段全绿，因为没被碰过的块走的是 `mdRaw` 回声；出问题的是
**改过一次之后重新拼**那一条路。

- **闭栏的判据必须逐条抄内核**（`crates/md-kernel` 的 `take_code`），不能"差不多"。三处不一致，
  每一处都是**把用户写过的行丢掉**：
  - 内核只 `trim_start_matches(' ')`——**制表符不是缩进**。我们的 `FENCE` 写的是 `\s{0,3}`，
    于是 ```` \t``` ```` 被当成闭栏，而内核把块一直延到后面那道空格缩进的围栏；我们从中间切一刀，
    切出去的那几行在用户改第一个字之后就不在文件里了。
  - **比开栏更长的同种记号，内核不认它当闭栏**（它判的是"记号长度之后有没有东西"，```` ```` ````
    对 ```` ``` ```` 就是"有"）。CommonMark 在这里比内核宽，但**边界是内核定的**，跟着规范切就丢行。
  - 空格缩进**不限个数**：`    ``` ` 内核认，我们的 `\s{0,3}` 不认（这一条的方向是安全的，
    只是少接管一种形状）。
- **闭栏只可能在末行**。旧注释写着"CommonMark 与内核都判最后一行才是闭栏"——**前半句和后半句都错**：
  内核是从前往后**第一道**匹配就闭，而它的 `raw` 因此正好停在闭栏上。结论反而更硬：
  既然 `raw` 不会在闭栏之后还有行，那么"不在末行的那道闭栏"只可能是我们与内核判得不一样。
  改成"末行必须是内核认的闭栏，否则 `闭 = null`"，判错的余地从"切早了丢内容"变成"不接管、原样回写"。
- **代码块的块锚单起一行，走在闭栏之后**（`^b-xxxxxxxxxx`）。这与上一条直接冲突：末行是锚点，
  不是围栏。所以装载时**先摘掉那一行**（只摘与 `b.id` 一字不差的，别的一律留在正文里），
  序列化时再补回去。忘了补就是"编辑一次代码块，它的块锚从文件里消失"——反链与拖拽排序都认那个 ID。
- **CRLF 的文件此前一个代码块都不接管**。`FENCE` 的 `(.*)$` 里 `.` 不认 `\r`、`$` 又不在串尾，
  于是 ```` ```js\r ```` 判成"首行不是围栏"。Windows 优先的应用，这条不是边角料。
  判据跳过行尾 `\r`，但**存进账本的仍是原样那一行**，拼回去才是同一份字节。
- **开栏行只有一份拆法**：`fence.ts` 的 `拆开栏` / `拼开栏`。复查时它有三份正则
  （`有效开栏`、`改语言`、`刷语言` 里的 `词()`），三份对 `\r` 的态度各不相同——`词()` 那份读不出
  语言，CRLF 文件的牌就是空的。另有一条数据损失：`改语言("")` 从前把 info 的**尾巴**一起吃掉，
  `` ```rust // 标记 `` 选"无"会变成 `` ``` ``（用户清的是语言，不是他的注释）。
- **账本必须跟着进 DOM**，因为 PM 的剪贴板就是 `renderHTML` → `parseHTML` 这一条路。
  围栏住在 attrs 里而 `domAttrs` 把所有 `md*` 键都剥了，于是**复制一个代码块 = 贴出一堆裸行**：
  `# 这行不是标题` 那样的内容会直接变成真标题。现在 `pre` 上带 `data-md-fence-open/close/body`，
  `parseHTML` 用 `getAttrs` 收回来，连 `mdKind` 一起（只带围栏不带类型，贴出来的块判不出单面，
  又退回两副面孔）。真机照过：Ctrl+C 之后剪贴板里那份 HTML 是
  `<pre data-md-raw="code" data-md-fence-open="```js\r" …>`。

### 卡片上的三样：复制、块内全选、行号（2026-10-09）

用户一句话点了三件事："代码块应该有个复制图标按钮，ctrl+a 只选这一块，然后代码块是有个行号的"。
三条各自有一条不显然的口径：

- **复制按钮抄的是 `node.textContent`**，也就是围栏之间那段代码——围栏住在账本 attrs 里、
  不在正文里，所以"复制代码"天然不带 `​`` `，也不用剥什么。按钮和语言牌一样排在
  `contentDOM` **之外**（PM 看不见它，图标与回显永远进不了文件），`stopEvent` 对它返回 true，
  并且**自己 `preventDefault` 掉 `mousedown`**：不拦的话 PM 会把插入符甩到块首，用户看到的是
  "点一下复制，光标跳走了、选区也没了"。`navigator.clipboard` 优先，reject 时退回一个离屏
  textarea + `execCommand`——那条 API 在窗口没拿到系统焦点时会 reject，只留一条就是
  "点了什么也没发生"。抄成功换一枚对勾 1.4 秒（图标按钮没地方放文字，而"到底抄上了没有"必须看得见）。
- **`Ctrl+A` 是两档**：光标在不透明块里 → 第一下选这一块，整块已经包住才扩到全文。
  判据是纯函数 **`全选档(state)`**（`blocks.ts`），keymap 只负责发选区事务。
  两类块明确不接管：**表格**（它有自己的格子矩形选区，抢 `Mod-a` 会把那套判据绕开）、
  **普通段落 / 标题 / 列表项**（那是写正文的地方，全选就是全选整篇）。
  全选整篇之后 `$from` 落在文档开头（depth 0），判据直接返回 null 交回默认——所以第三下
  不会把选区缩回块里。
- **行号两行以上才有**（单行片段挂一个 `1` 看着像出错了）。三条位置上的讲究都不是审美：
  它是 `contentDOM` **之外**的兄弟节点（数字混进正文＝下一次落盘文件里多了 `1 2 3`）；
  它排在 `pre` **之前而不是里面**（`pre` 才是横向滚动的那个容器，放进去就会跟着滚走）；
  列间距做在行号自己的 `padding-right` 上而不是 grid 的 `column-gap`（单行块没有行号栏，
  用 gap 就会凭空多出一条对不齐的代码左边距）。只在**行数真的变了**才重写那一栏——
  打字时行数一般不动，这条判据让它在击键路径上零读写。行高与代码同源（`--leading-code`
  @ `--text-mono`），真机量过首行顶边差 0px；正文行高的三档偏好不作用于这里
  （否则代码块的密度会被阅读偏好改掉，行号与代码也会跟着重排）。

**没有做的**：引用 / Callout 那一面（两副面孔的那种）不给这三样——它们没有"卡片"这个视觉容器，
行号与复制按钮在那种形态上没有落点；而"没闭栏的代码块"正文里就躺着 ` ``` `，
给它一个"复制代码"按钮会抄出一道围栏来，宁可不给。公式后来转成了单面，但它只有一块居中的公式，
没有语言可标、没有行号可数，复制也只是一段 LaTeX——同样不挂这三样。

### 图片粘贴与单面图片块（2026-10-09 档 1）

用户报"文档无法粘贴和存储图片"。查下来不是坏了，是**这条链路一段都没接过**：剪贴板的字节能到
WebView2（真机取证：截图位图给出 `types:["Files"]`、`image.png` 123 字节），但 schema 里没有图片
节点、命令表里没有写二进制的命令、`assetProtocol` 用的是默认 `enable:false`、`asset:` 只在 CSP 里
等着。这一档把这四段接上，并且**图片块按单面实现**（代码块那根杆子：光标进来不许换一副样子）。

**后端 `attachment_save`**（`note-core::assets`，壳侧只做转发）：

| 口径 | 为什么 |
| --- | --- |
| 文件名 = 内容的 sha256（`hash::asset_path`，这函数从"声明了没人用"变成真的在用） | 同一张图粘第二次落到同一个路径，去重不靠约定；盘上也不会攒出第二份（真机：粘两次，`attachments/` 里始终一个文件） |
| 格式由**字节本身**判（`sniff`），不看文件名 | 剪贴板给的名字永远是 `image.png`；拿文件名当扩展名攒出来的是"叫 .png 的 JPEG"这类修不完的脏数据。白名单与内核 `is_image_target` 同一批（png/jpg/gif/webp/bmp/avif/svg） |
| 空字节、认不出格式、超过 20MB 一律拒，且**拒了不许留下半个文件** | 上限不是"存不下"，是"这一档不该一口吞下它"：大文件要配缩略图与懒加载（档 3） |
| 落盘返回才算存好，`attachments` 表那一行后台补 | 返回即代表字节在盘上，正文里那行引用不会指着空气；那一行是派生数据（今天**没有**重建路径，见本节末），为它把一次粘贴变成红色报错是撒谎。写与 hash 都在 Hub 主锁外（第六轮复查改的） |
| 字节走 IPC 的 **raw body**（`invoke("attachment_save", uint8)` → `InvokeBody::Raw`） | JSON 传一张 2MB 的图要么 base64 膨胀到 2.7MB，要么十进制数组 8MB 以上，而这条调用就压在按下 Ctrl+V 那一刻 |

**显示走 asset 协议，配置里 scope 是空的、运行期给**：`asset_protocol_scope()` 在选库时
`allow_directory(<Vault>/attachments, true)`，换库时把上一个目录 `forbid` 掉——静态配置写不死用户
随时会换的库路径，而"切库之后旧库的图还能读"不该是常态。`convertFileSrc` 要的是绝对路径，所以
库根存在 `src/ipc/commands.ts` 的模块单例里（`设库根`），**不塞进节点 attrs**：绝对路径是会话状态，
躺在节点里会被复制走、被写进 JSON，换台机器就是一堆坏链。

**图片块是原子节点 `mdImage`**，不是 `mdOpaque` 的一种显示形。理由：那一行没有"正文"可言
（整行都是语法记号），把它退回源文本编辑等于让用户手打 64 位哈希文件名。字节只从 attrs 拼，
判据与显示共用 `src/editor/asset.ts` 那一份（与 `fence.ts` 同一条理由：两套实现早晚分叉，
而这里分叉等于改用户字节）。**接管与否判得很保守**，任一条不满足就维持 `mdOpaque` 显示源文本：
整行必须只有那一个引用（`![[a.png]] 后面还有字` 接管了就把后面的字吃掉）、目标必须指向本库
`attachments/`（裸文件名与相对路径要的是全库解析，那件活 docs/05 记着没做）、形状里不许有没搬进
attrs 的字节（`![x](p "标题")`、`<p>`）。缩进、`![[x|]]` 那根空竖线、CRLF 的行尾 `\r` 都各自是
字节，用例逐条钉着往返。

**三条界面上的口径**：图注是 `contentDOM` 之外的真 `<input>`（与语言牌同一档，PM 看不见它，
`stopEvent` 对它返回 true），打的字就是文件里 `|` 后面那段，清空则连竖线一起收掉；读不到文件时
不画破图，退成文件名那一枚牌；**选中与聚焦全程不换 DOM**（真机：点中图片块 → `data-md-sel` 出现、
`<img>` 还是那一颗、屏幕上不出现 `![[`）。图片是原子块、插入符进不去，所以 `↓`/`Enter` 必须给出口，
并且插入时自带一个不落盘的空段落落脚点——这是用户报过两次的那类死局，这次不等他报。
`Alt+↑↓` 也补了 NodeSelection 这一支：不接就是"手柄能拖、键盘不能动"。

**一条我自己写错又改回来的说明**（记在这儿，免得下次再照着它编）：这一档最初把
`apply_external` 改成"先问扫描器收不收、再决定读不读文件"，理由是"粘一张 5MB 的图，监听器会
整份读一遍只为得出一句不归我管"。**这条理由不成立**——`watch::ignorable` 在攒批之前就把非 `.md`
全挡了（`crates/note-core/src/watch.rs` 里有一条用例就写着 `ignorable("notes/附件.png")`），
那种事件根本到不了 `apply_external`；而提前 `continue` 会顺手把"盘上没了就把索引行摘掉"那一条
也跳过。**已回退成原样**，代价为零，收益是注释不再撒谎。

### 第六轮复查：写侧必须跑同一份判据（2026-10-09）

图片这一档交完当天复查，六条全是**"读侧有判据、写侧没有"**这一种形状，逐条都有能跑红的用例：

| 缺陷 | 根因与修法 |
| --- | --- |
| 剪贴板能把任意字符串写进用户的 .md | PM 的粘贴就是 `renderHTML` → `parseHTML`，而 `getAttrs` 什么也没查。实测注入 `data-md-src="a.png]]\n\n# 注入的标题\n![[b"`，落盘成了**三个块**。现在写侧过同一道闸：`是库内资产` + `可无损`（拼回去再拆一遍，形状/目标/别名/竖线四项全等才算） |
| 图注里打一根竖线，这块下次打开就退回源文本 | 别名判据比内核严（内核 `split('|')` 只认第一根）。放开成"别名里可以有竖线"，与内核同口径；方括号与换行是**收掉**（`收图注`）而不是写进去，收完框里也跟着改——不留一个骗人的框 |
| 选中一张图再 Ctrl+V：屏幕没反应、盘上多一枚孤儿文件 | 原子块的 NodeSelection `depth` 是 0，`插图片块` 直接返回 null，而字节已经落盘。现在"选中即替换"，且真算不出落点时**报一句话** |
| 聚焦看一眼就把整篇顶成未保存 | `改注` 那句判据写反了：值没变照样发事务，而界面的脏判据是 `inlineRev > 0 || 字节不同`。现在值没变一个事务都不发（连竖线的标志也不动） |
| 撤销之后图注框还写着撤销前的值，一 blur 又把旧内容写回文件 | "别踩正在打字的格子"这道保护没有"已经提交"这个状态。加 `打过字` 标志，`input` 才置、提交与外部更新都清 |
| 大图的 sha256 + fsync 压在 Hub 主锁上 | 这条命令的开销**随图片大小走**（实测 5–8MB 光 sha 就 40–60ms），锁内排队就是 docs/03 记过的 3.26 秒形状。改成 async 命令：锁里只取 `Vault` 克隆与索引句柄，写与 hash 全在锁外；登记那一半的句柄也**在发起时取好**（否则换库窗口会把 A 库的账登进 B 库） |

另外三条小的：`sniff` 的 BMP 只认 `BM` 两个字母（任何以它开头的文本都会被判成图片，仓库里
那条 `sniff(b"BM........")` 的断言就是证据），补上"至少 54 字节 + DIB 头大小合理"；
"这一份已经存在"从 `metadata().is_ok()` 改成 `is_file()`（目录与断链不该短路写入）；
超限文案原来是"这张图有 20 MB，超过 20 MB 上限"（两个数都是整除后的商）。

**登记行现在有了重建路径**（2026-10-10）：`Index::rebuild_all` 扫 `attachments/` 目录，按**文件名
声明**的 sha 登记（内容寻址的名字里就写着 sha，不重读字节），`first_seen_at` 取 mtime，并把盘上
已经不存在的行先摘掉、仍存在的行原样保留（`orig_name` 那句"第一次粘进来时它叫什么"不该被重建抹掉）。
三条边界写在 [02] §资产引用格式。这一张表今天仍然不影响任何显示——存在性直接查盘，所以登记失败
只记日志，不报红，也不把一次重建判成失败。

**真机数字**（dev + WebView2，2026-10-09）：按下 Ctrl+V 到看见图片块 48ms，到看见真像素 32ms
（预算 100ms）；一张 320×180 的图存成 `attachments/d6/d62948….png`，文件名前缀与内容 sha256 对得上；

**已知没做的**：拖文件进正文（`dragDropEnabled` 默认 true，前端没听 `tauri://drag-drop`）、

### 着色与视口的两条"看着对、其实没跑"（2026-10-08 复查）

- **分层 scope 被白名单整段吃掉，函数名与类名一个都不上色**。hljs 11 把 `title.function_` 吐成
  **两个类**（`class="hljs-title function_"`，只有第一段带 `hljs-` 前缀），而白名单要求
  "每个词都以 `hljs-` 开头"——`function_` / `class_` / `invoke__` 就判死整个 span。
  实测 py / js / rs / java 全中（`go` 用裸 `hljs-title` 反而躲过），这正是用户点名的
  "适配各种语言显示不同的样式"里最显眼的一批。改法是**归一化而不是拒绝**：第二段统一补 `hljs-`
  前缀。安全性质一点没松（进 DOM 的类名全在我们自己的命名空间里，撞不上 Tailwind 的工具类），
  变的只是"能不能上色"从此由 CSS 有没有写这条决定。顺带救回子语言（`<script>` 里的 js）——
  它的 `language-javascript` 同样是被拒的。CSS 里那两条 hljs 10 时代的写法
  （`.hljs-class .hljs-title`、`.hljs-title.class_`）在新形式下永远匹配不上，一并改对。
- **视口上报是个空转**：`报()` 先 `视口 = 视口of(view)` 再带着**同一个对象**去 dispatch，
  而 `apply` 判的是"meta 里那份与模块里那份不是同一个"——自己先赋了值，这个比较永远相等，
  滚动上报全被当成"没换"丢掉。修好之后装饰集合跟着滚动走（真机照过：滚到远处那块，近处那块的
  span 撤掉、远处那块的补上）。
- **装载那一路其实在猜语言**：NodeView 构造函数调 `带围栏(node)`，而它经 `有效开栏` 跑
  `highlightAuto`——注释与文档都写着"装载时不算"。实测一块 30 行 2~13ms、首门含预热 223ms，
  十几个无标签代码块的笔记就压在打开那一刻。现在 `带围栏(node, 允许猜)`，构造与 `update` 传
  `false`（只读缓存），猜仍由 `CodeHighlight` 在装饰那一路做（那边有每轮 8ms 的预算）。
- **牌与文件必须同时改**：`update()` 此前只在交出焦点时刷牌，于是 `Ctrl+Z` 撤销一次"选语言"
  之后文件回到 `js`、下拉还写着 `go`。现在开栏一变就 `刷语言(false)`（只读缓存，击键路径上便宜）。
- **下拉里那条"（文件里写的）"只加不减**：`刷语言` 有三条来路，实测两个清单外语言的块来回
  进出 6 次，选项从 29 涨到 35。现在先清掉不在清单里、又不是当前值的那些，再决定加不加。

### 主题那一帧（2026-10-08 补）

`main.tsx` 里那句"渲染之前先套上主题"**只挡住了未着色的 React 内容，挡不住亮色画布**：
CSS 是渲染阻塞的，而模块脚本要等整个依赖图（React + tiptap + highlight.js）下载解析完才跑。
补了一段 `public/theme-boot.js`，在 `<head>` 里以**传统脚本**（非模块、不 defer）执行。
不用内联脚本：CSP 是 `default-src 'self'` 且没写 `script-src`，内联是被禁的，而这个应用
正把"渲染 Markdown 不许长出元素"当命根子，不该为一帧去开 `'unsafe-inline'`。
它必须与 `theme.ts` 同一份口径（存的是**档位**、`data-theme` 上是解析后的深浅），
两边各写一份的结果就是启动那一帧与之后那一帧颜色不同。

### 表格网格（2026-09-28 落地，改的是 D27 的适用范围）

用户反馈只有一句："为什么我创建的表格打开还是 markdown"。查下去不是渲染坏了——是**设计如此**：
两副面孔的规则是"光标进块就退回源文本"，而表格要填格子就必须待在格子里，于是用户永远只看到
`| 列 | 列 |`。代码块这样很自然（平时是代码，点进去改源码），表格这样不自然。所以表格单独接管：

| | 显示 | 编辑 |
|---|---|---|
| **代码块（有闭栏的）** | **只有一面**：卡片、语言牌、着色常驻 | **就地编辑代码本身**：开栏行与闭栏行存在账本（`mdFenceOpen` / `mdFenceClose` / `mdFenceBody`），节点正文只装围栏之间那段，所以点进去不再看到 ` ``` `；着色由 `CodeHighlight` 的装饰给、牌由 `data-md-lang` 给，于是**聚焦前后是同一批 DOM、同一份计算样式**（真机逐条对过：盒子 1104×141、padding 12/16、圆角 10、底色、牌的文字与色号、字号、`white-space: pre`、`overflow-x: auto`、`tab-size: 4`、7 个 span 全一致）。保存时按账本拼回去（`fence.ts` 的 `拆围栏` / `拼围栏` 是**唯一一份**判据，显示形与序列化共用——两套判据早晚分叉，而这里分叉等于改用户字节）。三条不退让的边界：**没闭栏就不接管**（接管等于替用户凭空造一道 ` ``` `，那种块仍然两副面孔）、`零行` 与 `一个空行` 是两种字节所以必须记 `mdFenceBody`、**未改动的块仍按 `mdRaw` 逐字节回写**（重拼只发生在真被编辑过的那一块）。最后一行按 `↓` 离开这块、`Enter` 永远块内换行，与下面那行同一套键 |
| **公式（两道都是独立的 `$$` 行）** | **只有一面**：居中的公式本身，没有宿主、没有源码面 | **就地编辑公式体**：两道 `$$` 存进账本（`mdMathOpen` / `mdMathClose` / `mdMathBody`），节点正文只装中间那段。与围栏同一条纪律：**没有成对围栏就不接管**（单行 `$$x$$`、行内公式仍两副面孔）、`零行` 与 `一个空行` 必须分开记、未改动的块仍按 `mdRaw` 逐字节回写。拆法与拼法只有 `mathFace.ts` 一份判据，显示形与序列化共用（见 §公式单面与分隔线原子块） |
| **分隔线** | **只有一面**：一条横线（原子节点 `mdDivider`，不是不透明块的一种显示形） | 没有"正文"可改，所以整块只能选中 / 删除 / 上下移动；`---` / `***` / `___` 都认，未改动按 `mdRaw` 回写，改过的写回 `---`。带块锚时 `^b-…` **必须独占下一行**——`--- ^b-…` 在内核里已经退化成段落 |
| **引用 / Callout（拼得回原字节的）** | **只有一面**：引用去 `>`、Callout 去 `[!type]`，嵌套列表画成真正的列表 | **就地编辑正文本身**：`>` / `[!type]` 按行进账本（`mdQuoteMarks`），行尾块锚进 `mdQuoteAnchor`，正文拆成真正的段落 / 标题 / 列表项子节点，Callout 标题是 `mdQuoteHead`。拼不回原字节的块（`引用接管` 返回 null）仍走源文本。见 §引用 / Callout 的前缀账本与结构化接管 |
| HTML / 未识别 / 带子项的列表项 | 没有光标时画投影 | 光标进来改源文本。**块内最后一行按 `↓` 离开这块**，`Enter` 永远是块内换行（拆出来的两半围栏 `serializeNode` 不认）。判据是"最后一行"而不是"内容末尾"。工具栏 / `/` 插进来的不透明块下面都带一个空段落落脚点（空段落不落盘），否则块在文末时只剩鼠标能出去。2026-09-29 补，与表格同一套键（见下一行） |
| **表格（接管得过来的）** | **一直是网格** | **格子里直接打字**，`Tab` 跳格、末格 `Tab` 加一行、`Enter` 到下一行同一列（末行整行为空则**删掉它并送出表格**）、最后一行按 `↓` 离开表格，工具栏那一组图标（加行 / 删行 / 加列 / 删列 / 三档对齐 + 取消，见 §块级快捷键） |

代价是这条路上**第一次出现"改一个格子会重写整块字节"**，所以判据保守到近乎胆小
（`src/editor/table.ts` 的 `parseTable`）：列数不齐、带 `^b-` 锚点、行首有缩进、中间有空行——
一律不接管，继续走源文本。每一条拒绝都对应一种"我们拼不回去"的形状：接管了却拼错，
就是改用户的字节，那是 I4 违反，不是渲染不好看。

实现口径（第一条是复查抓出来的字节级缺陷，其余都不显然）：

- **对齐是数据不是样式**：`mdAligns` 挂在表格块上，"加一列"必须同时给它补一项，
  否则产出的分隔行比表头短一列，重新解析就错位。
- **`Enter` 在格子里永不拆块**：GFM 的格子里装不下换行，拆出来的两半表格 `serializeNode`
  根本不认。所以 `TableKeys` 必须把 `Tab` / `Shift-Tab` / `Enter` 三条都接管（`Tab` 默认还会
  把焦点丢出编辑器）。
- **整块替换会把块内选区映射到块尾**：`addColumn` 用 `replaceWith` 换掉整张表，光标就跑到
  表格外面了，工具栏那两个按钮随即消失——看着像"点一下就没了"。替完按**新列数**走回原来那一格。
- **格子里不许留换行，拦在写盘前最后一道关口**（复查抓到的字节级缺陷）。`写格()` 从前只转义 `|`；
  而事务级的文本节点容得下 `\n`（`tr.insertText("甲\n乙")` 就进得去），产出 `| 1甲\n乙 | 2 |`
  这份 `parseTable` 返回 `null`——下一次打开它不再是表。现在换行连同邻近空白折成一个空格。
  **真机的结论与事务层不一样**：`Input.insertText("甲\n乙")` 打进格子，Chromium/PM 在输入层就把
  换行收掉了（格子里 `\n` 计数为 0，产出的表仍是 4 行、重新解析仍是这张表）。也就是说这条
  从界面走进来的路今天堵着，但序列化器不该依赖"上游恰好堵着"——它是唯一能保证产出形状的位置。
- **整块替换会把块内选区映射到块尾**：`addColumn` 用 `replaceWith` 换掉整张表，光标就跑到
  表格外面了，工具栏那一组按钮随即消失——看着像"点一下就没了"。所以删行 / 删列 / 设对齐与
  加列共用同一个 `回到格(tr, 表起点, 行, 列)`：**行列都按新表钳一次**，删掉的是光标自己那一格
  时自然退到左边那格 / 上一行，不需要每个动作各写一份落点。
- **删与不删的边界要说得出原因**：`removeRow` 拒绝表头行与"只剩表头"（GFM 的表格必须有表头行，
  删了它产出的就不是表；把第二行提成表头是替用户改语义），`removeColumn` 拒绝最后一列（空表不是表）。
  界面上不是"点了没反应"，是按钮**禁用 + title 写清原因**。表头 + 分隔行那种"零条数据行"是合法的，
  所以真删到那一步不再往下删。
- **对齐是一列的属性，两个地方必须一起改**：`mdAligns`（产出分隔行的 `:---` / `---:` / `:---:`）
  与这一列每格的 `align`（画出来的 `data-align`）。只改一边就是又一次"屏幕上生效、落盘就错"。
  已经是这一档时 `setAlign` 返回 null——同一列连点两次"居中"不该把这篇标成待保存，也不该
  重写那张表的字节。
- **多格选区的锚点是"表内坐标"，所以扩选区只认同一张表**（2026-09-29 复查抓到）。矩形是插件
  里的一份独立状态 `{表, 锚, 矩}`，`锚` 存的是**行列号而不是文档位置**。拖动那条路判了
  `到.表 !== 起.表` 就 return，Shift 点选那条路漏了判——于是"在 5 列的表里框过一片，再去 3 列的
  表里 Shift 点一下"会把 A 表的 (行,列) 直接扣到 B 表头上：工具栏的批量组随之指到 B 表，
  `Delete` 清空 B 表的格、`删所选行/列` 删 B 表的行列。修法是锚点只在同一张表里复用，跨表就
  以点击格重起锚；同时**单格不算矩形**（与拖动同一条规矩，否则那一格凭空多一圈框）。
- **矩形伸到表头之外时，`mdAligns` 只能按夹住后的列范围写**（同一条复查里抓到的第二道）。
  格子那一路在 `改格们` 入口就 `夹住()` 了，只有对齐那一路拿的是原始 `矩.c1`：喂一个越界矩形
  就能产出 `| :---: | :---: | :---: | :---: | :---: |` 配三列表头——GFM 要分隔行与表头等长，
  内核从此不认它是表，整块降级成不透明块，用户的表格从网格里消失（探针实测过那份字节）。
  两条合起来的口径是：**判据不许一处夹一处不夹**，越界矩形即便被造出来，也只能少改不能多改。
- **粘贴的判据与动作分开**（`判粘贴` 是纯函数，扩展里只照着做）。四种落点各有各的理由：
  空段落 + 剪贴板是表 → **换成网格**；格子里 + 多行 → **摊平成空格**；格子里 + 单行 → **交回 PM**
  （行内样式的默认粘贴不该被抢走）；其余 → 交回。剪贴板侧的判据是 `parseGrid`：Markdown 源文本
  走 `parseTable` **同一条**判据（所以"粘进来的表"与"库里的表"是一套字节口径，没有第二种表格），
  电子表格的 TSV 要求**每行列数相同、至少两列两行**，**CSV 明确不认**——逗号在正文里太常见，
  把一句话切成"三列"是拿用户的内容赌概率。
- **格子里粘多行必须自己摊平**（真机抓到的破坏，比"粘贴没生效"严重一档）：单元格是 `inline*`，
  装不下换行，交回 PM 的默认纯文本粘贴会把换行变成拆块——3 行 3 列的那张表被顶成
  `mdTable[1行x3列] + 两个空段落 + mdTable[2行x3列]`，用户粘一次字，表格就没了。
  GFM 的格子里本来就没有换行，所以落进来就折成空格，与 `写格()` 落盘那一条同一个规矩、两道关口。
- **表格后面永远留一个"落脚点"（空段落）**（2026-09-29 用户报的死局）。以表格结尾的文档**没有任何出路**：
  格子里装不下换行，`Tab` / `Enter` 在末格只会一路加行，`↓` / `Esc` / `Backspace` 什么都不做（真机与
  jsdom 双层复现过），鼠标也点不到"表格下面"——因为下面没有块。所以**插入、`/` 替换、粘贴成网格
  三条路都在表格后面自带一个空段落**，`↓` 在最后一行也现补一个。它能成立是因为
  `docToMarkdown` 那条"重新产出后是空白的块不落任何字节"——**加它不改文件一个字**，这条判据写在测试里。
- **末行整行是空的 → `Enter` 删掉那一行并送出表格**（"再按一次就出去"）。只剩表头那一行时不删
  （GFM 的表必须有表头行），只把人送出去。`Tab` 在末格**仍然只加行**——它是格子间移动的键，
  让它顺手删行会把"我刚建的空行"吃掉，而那是用户按出来的意图。
- **账本守卫不碰表格**（复查抓到的字节级缺陷）。`LedgerGuard` 的判据现在收紧成"新造的
  + 另有同源"（见上一条），表格仍要单独排除：判据的前提是**重新序列化等于原字节**——
  段落、列表、不透明块都成立，表格不成立：清完账本，用户没碰过的那张相邻表会从
  `|:-----|-----:|` 被写成 `| :--- | ---: |`。真机取证过（两张相同的相邻表，给第一张加一列，
  盘上第二张原样）。表格本来也用不到这条判据：格子里的 `Enter` 被接管成跳格，拆不出那种产物。
- **账本守卫只在真的改了文档的事务上跑**（2026-09-29 复查抓到，探针取证）。PM 对**每一次
  `apply`** 都调 `appendTransaction`，纯光标移动也算一次；不挡这道，"点开一篇有相邻同文两段
  的笔记（`甲\n\n甲`）、把光标放进去"就会清掉第二段根本没被碰过的账本——探针实测 `mdRaw` 从
  `"甲\n"` 变成 `""`，而那笔补出来的事务是 `docChanged` 的，`onUpdate` 跟着响。守卫原本只挡
  "整树替换"（载入），漏的是载入**之后**的每一拍。判据补在入口：`steps.some(tr => tr.docChanged)`，
  用例钉在"载入时相邻两块的源切片本来就相同"那条里（动一下光标，账本、字节、`update` 次数三者都不许动）。
- **"拆块产物"不再由"相邻同源"单独认定**（2026-11-02 复查抓到）。上一版的判据会把作者
  手写的相邻同源块误判：`甲\n\n\n甲` 里改第一块，第二块没被碰，账本却被清、gap 压成 `""`，
  两个空行当场没了。现在"新块"由反向映射认定（起点落回旧文档时 `deleted` 才算），再加
  "这份源切片在文档里另有同源"；顺带修好粘贴整块的合并缺陷。两条用例都在
  `roundtrip.test.ts` 的同一组里。

真机（CDP 可信鼠标与键盘）：打开就是网格、点格子打字、`Tab` 跳格、末格 `Tab` 加一行、
「+列」把每行都补齐且按钮不再消失；产出的 `.md` 过一遍 `note parse` 仍是 3 块（前后两段
一字未动），表格无损。测试 108 → 134 项，其中 12 项是表格的双向转换、12 项是它的字节判据。
**同日复查收尾又加 4 项**（换行折成空格的字节判据与转换判据各 1、显示形事件分派 2）。
**再往下一轮补上删与对齐**（真机，探针笔记那张三列表）：`−行` 把 4 行的表写成 3 行、DOM 里
剩 2 行、光标仍在格子里；`−列` 之后每行都是 2 格且分隔行同位次少一段；一路删到只剩一列时
「−列」自己禁用（title 写"最后一列不给删：空表不是表"），删到只剩表头时「−行」也自己禁用；
给原本无对齐的第三列点「靠右」，分隔行从 `|:---|---:|---|` 写成 `| :--- | ---: | ---: |`，
`Ctrl+Z` 一笔回到原样；整趟走完文件 hash 与开测前一致。**这里也踩过一次假警报**：第一次探针
连按 25 次 `Ctrl+Z` 看着"撤不回表格结构改动"，实际是**按键前没 `view.focus()`**——PM 的 keymap
挂在 `view.dom` 上，焦点不在编辑器里时那些键根本不进事务通路；补上 focus 后一次就回。
现在 `pnpm test` 220 项（表格双向转换 18 项，"表格网格化的字节判据"那一组 26 项，
矩形选区与批量 9 + 拖拽落点 18 + 目录树 18 项）。
**粘贴成网格也在这条路上验过**（真剪贴板：PowerShell `Set-Clipboard` + CDP 可信 `Ctrl+V`，
落点每步先断言光标真的在那个空段落里）：TSV 三列两行进去 → 编辑器多出 `mdTable[2行x3列]`、
光标落在第一格，等自动保存后**用内核读回文件**是 `| 指标 | 目标 | 实测 |\n| --- | --- | --- |\n| 打字 | 16ms | 待测 |`；
规范 Markdown 表进去 → 落盘 `| 列 A | 列 B |\n| :--- | ---: |\n| 含 竖线 \| 转义 | 2 |`，
对齐与转义竖线都活着；而**漏了行首竖线的那种"表"照规矩不接管**，按纯文本粘成三个段落，一个字节都没猜。

### 公式单面与分隔线原子块（2026-11-04）

用户报"块点进去看到的样式和点进去的样式不一致，比如引用"。查下来分两层：一层是显示形与源文本形
的**外观没对齐**（Callout 标题粗细、行高、折叠箭头），另一层是**公式与分隔线本来就不该有两副面孔**。
这一档先做零字节风险的外观对齐，再把这两类转成单面；引用 / Callout 随后也把前缀搬进了账本，
最后把正文接管成真正的子节点（见 §引用 / Callout 的前缀账本与结构化接管）——"内容里的行内语法
与嵌套结构跟显示形一致"那一层到此收口。

**P0 外观对齐**（只动 CSS，不碰 DOM 结构与字节）：Callout 标题按显示形那档加粗，折叠角标与标题
同一行高，正文行高统一走 `--leading-note`。探针逐条比对显示形的计算样式，聚焦前后不再跳。

**公式**：`$$` 两道围栏与代码围栏同一套账本——`mdMathOpen` / `mdMathClose` 存原样的两道栏，
`mdMathBody` 记"零行还是有一个空行"，节点正文只装公式体。于是点进去不再看到 `$$`，聚焦前后是
**同一批 DOM、同一份计算样式**（真机探针量过：显示形与可编辑面的盒子、字号、行高、`white-space`
逐项相等）。四条边界：**两道 `$$` 必须各自独占一行**（单行 `$$x$$` 与行内公式不接管，继续两副面孔）；
`拆公式` / `拼公式`（`mathFace.ts`）是唯一一份判据，显示形与序列化共用；空体必须按 `mdMathBody`
分 `[]` 与 `[""]`；**未改动的块仍按 `mdRaw` 逐字节回写**，重拼只发生在真被编辑过的那一块。
CRLF 与围栏行前后的空白原样保留，不 trim。公式没有语言牌、复制键与行号——它只有公式本身。

**分隔线**：`---` / `***` / `___` 在内核里是一个 `divider` 块、没有正文，留在 `mdOpaque` 里等于
逼用户点进去看一行纯语法记号，所以改成**原子节点 `mdDivider`**，屏幕上只有一条 `<hr>`，没有
`.md-src` / `.md-view` 两面。选中只写 `data-md-sel`（不发事务），`↓` 从它下面出去，剪贴板按
`hr[data-md-divider]` 认回来。序列化有两条不显然的规矩：

- **改过的块写 `---`，不读 `mdRaw`**。替换节点会从旧块继承 `raw`，读它就会把上一块的正文写成
  分隔线；原子块没有正文，按内核认得的骨架重建。
- **块锚必须独占下一行**。`--- ^b-xxx` 里混进了 `^`，内核的 `is_hr` 只认清一色的 `-`，读出来是
  段落而不是分隔线；独立成行的 `^b-…` 由内核挂给上面那块，所以形状是 `---\n^b-xxx`。内核侧
  用例钉住这两条（`边界_分隔符三义性`）。

测试 679 → 685 项；`cargo test -p md-kernel 边界_分隔符三义性` 与 `pnpm typecheck` 全绿。
视觉探针留在 `.scratch/probe-faces-p1.png` / `probe-faces-p2.png`（显示形 / 可编辑面并排）。

### 引用 / Callout 的前缀账本与结构化接管（2026-11-04）

用户最初报的就是这一类："点进去看到的样式和点击后不一致，比如引用"。根因是两副面孔的源文本形
会把文件里真实存在的 `>` / `[!type]` 摊在正文前面——它们既是语法记号，又占着编辑区的字位，
点进去整段就往右缩、行宽也变了。这一档分两步：先把前缀搬进账本，再把正文接管成真正的子节点。

**前缀账本**（`quoteFace.ts`）：

- **按行存前缀**（`mdQuoteMarks`，`\n` 分隔；每行一个前缀）。懒惰续行（不带 `>` 的第二行）
  存空串，拼回去仍是空串；Callout 首行的 `> [!question] ` 原样存着，节点正文里只剩标题与正文。
- **行尾块锚单独存**（`mdQuoteAnchor`）：与围栏同一条——摘下来才拆得动正文，拼回去必须原位补回。
- **拼不回原字节就不接管**（`引用账本` 返回 null），继续整段源文本。判据只有 `quoteFace.ts`
  一份：装载、序列化、显示形共用，三处各写一份早晚分叉。
- **新行沿用最近的普通 `>` 前缀**（`续行缀`），绝不复制 Callout 标题的 `[!type]`；删行时多出来的
  前缀直接丢掉，不把删掉的内容写回去。
- **账本必须跟着进 DOM**：剪贴板走 `renderHTML` → `parseHTML`，`pre` 上带
  `data-md-quote-marks`（`\u001e` 分隔）与 `data-md-quote-anchor`，`getAttrs` 用
  `缀可进账本` / `锚可进账本` 验过再收回——外面的 HTML 不能把任意字符串写进文件。

**内容也结构化**（`quoteStructured.ts`）：前缀事件之后，引用里的正文仍是 `pre` 里的一整段文字，
嵌的列表在编辑面是字面 `- 甲`、折叠 Callout 点进去会展开正文并在牌上标"折叠"——账本只能藏语法，
不能让内容按显示形的方式排。所以装载时用 `引用接管` 把正文拆成真正的子节点：

- **判据还是同一条**：用序列化器把内核给的子块写回去，必须与账本里的正文逐行相等；差一个字节
  就退回 `mdOpaque` 的源文本面。只有**段落 / ATX 标题 1–6 / 无序（只认 `-`）/ 有序（`3.` / `3)`）/
  待办（`- [ ]` / `- [x]`）**会被接管，列表项不带子项、不带对齐；代码 / 表格 / 嵌套引用 /
  setext / 对齐包裹 / `*` 与 `+` 列表一律不接管。行内语法按规范化写法拼（`__粗__` 变成 `**粗**`），
  拼不回去就不接管——接管不许以改写用户字节为代价。
- **Callout 首行是 `mdQuoteHead`**：标题本身也要原样拼得回；类型与折叠标记进账本。折叠角标只改
  DOM 上的 `data-folded`（`display:none` 收起正文、标题留着），不发事务、不写字节。
- **键盘按块内语义走**：段落里的 `Enter` 是软换行 `\n`（与内核的懒惰续行同一形状）；Callout
  标题 / ATX 标题里的 `Enter` 落出一个无空行的正文段落；标题开头与紧跟标题的正文开头退格是空操作，
  不吃标题；列表项的回车 / 项首退格沿用到引用内部；`↓` 在最后一行末尾把光标送出引用。
- **未改动的块仍按 `mdRaw` 逐字节回写**；改过的块按子节点重拼，CRLF 由 `mdQuoteEol` / `mdQuoteTail`
  原样带回。

视觉上不再有"显示形 / 编辑面"两套 DOM：引用是 `blockquote.quote.md-quote`（`contentDOM` 就是它
自己），Callout 是 `div.callout.md-quote`（角标 `cal-badge` + 正文 `cal-body` 的网格）。聚焦只改
DOM 状态，不换面孔、不发事务。真机窗口（CDP 连 WebView2）复核：四块引用 / Callout 都没有
`.md-src` / `.md-view`，点进去前后盒子、padding、边框、字号、行高（27.125px）、字重、左缘逐项相等；
嵌套列表是真正的 `[data-md-item]` 项目符号；角标点一下高度从 78.25px 收到 51.125px、再点回去，
文件字节不动；引用内回车后 `Ctrl+Z` 复原，`↓` 从末行落到下一块。

**已知没做的**：HTML / 未识别语法仍两副面孔；剪贴板不携带账本与子块的结构属性（列表类型、标题
级别、待办勾选），序列化器按 `> ` / `> [!type] ` 重新长出前缀，行内标记随节点正文保留。测试：
`quoteFace` 单测 7 项 + `quoteStructured` 17 项（判据 8 / 落盘 3 / 键盘 6）+ 往返用例，总数
685 → 703；`pnpm test`、`pnpm typecheck`、`node scripts/check.mjs`、`cargo test -p md-kernel` 全绿。

### 拖拽手势（pointer 事件，不用 HTML5 拖放）

侧栏树行、块手柄、表格多格框选都是同一套打法，所以规矩集中在这儿，别处只引用。**为什么不用
`draggable` / `dragstart`**：真机验证只能通过 CDP 发普通鼠标事件，`dragstart` 那一套触发不了——
**验证不了的交互不该上生产**。代价是原生文本拖拽会被浏览器抢走，得自己挡。

四条都不显然：

1. **三个出口都要收监听**：`pointerup` 落子、`pointercancel` 放弃、以及 `pointerId`/`isPrimary`
   判据。触摸与笔会被浏览器抢去滚动（`nav` 是 `overflow-y-auto` 且没写 `touch-action`），那种
   手势**只有 cancel 没有 up**——不接就是拖拽粘住：指示线跟着手指跑，下一次按下再挂一对监听，
   一次手势落两次子、搬两次文件。第二根手指同理，不按 `pointerId` 收就等于多路并发。
2. **落子读的是松手那一刻的状态，不是按下那一刻的**。`up` 是按下时创建的闭包，而拖一次中间会
   重渲染（指示线自己的 state、索引事件带来的列表刷新）。连着拖两次时，第二次若拿旧树、旧顺序
   算整层序列，就会把第一次刚落盘的排序盖掉——所以经由 ref 拿当前那份处理函数。
3. **拖完补的那一下 click 只吞"被拖的那一行"**。按在 A 行松在 B 行时，浏览器把 click 发给两行的
   共同祖先，B 行的 onClick 本来就不跑；整棵树一起吞（上一版的写法）会吃掉"拖完立刻点开另一篇"
   的那一下，用户得点两次。真机验法：拖一行 → 17ms 后点另一行 → 那一篇要开得出来。
4. **`dragstart` 只在确认是框选时挡**（表格那一路）。它一触发 pointermove 流就断，表现为"框到一半
   冻住"，而用户以为自己框了四格——那种"少改"比不改更难发现。副作用登记在 [05]：格子里拖选文字
   这条路被它挡掉了，目前用双击选词 / Shift+方向键替代。

顺带一条真机取证：`Input.dispatchMouseEvent` 连发多个 `mouseMoved` 会被浏览器合成，量到的落点是
中间某拍——按帧（16ms）间隔发；拖拽途中布局会自己动（工具栏换档多一行 = 正文下移 25px），所以
**每一拍都要重新量目标元素**，不能拿按下那一刻算好的坐标一路用。

### 反链面板（2026-09-28 落地）

正文下面两段：谁链到我、我链到谁（含链空的）。读命令是 `note_links`，形状与不收的东西见
[02] D30 与本文 §IPC 契约。三条不显然的：

- **按对方分组，不按链接条数**。真库里那篇长文档性能夹具把同一个 `[[悬空写法]]` 重复了 40 次，
  一条一个按钮就是一屏重复行；分组后是"3000 块长文档实测 ×40 链空了"。合并行的"到块"徽章
  取的是**全部**都是到块才显示——一篇里既有 `[[乙]]` 又有 `[[乙#某标题]]` 时，看第一条是在说谎。
- **保存之后不立刻刷新，而是"索引一响就静默重取"**。链接图是后台索引算的，保存返回那一刻去问
  问到的是旧图，面板会在用户眼前闪回错误内容。**为什么不限定"事件里有本篇才刷"**：改名 / 归档
  的负载里只有被搬走那一篇，而它的一批入链方（可能正是眼前这篇）不在名单里——按负载过滤，
  面板在最常见的四种操作（改名 / 归档 / 删除 / 恢复）之后就一直过期。静默 = 不清空重画，
  免得每存一次闪一下；读失败就留着手上那份，别把辅助信息抹成空。
  **代价是负载欠报这件事还在**：`note://indexed` 报的是"这次动过的那几篇"，不是"链接图变了的所有篇"。
  补全它要在 `break_incoming_links` / `resolve_broken_to` 那两条整片 UPDATE 旁边再 SELECT 一次
  受影响路径——等于把同一段 WHERE 写两遍，将来一处改了另一处不改，面板就又过期了。
  所以这里选"多刷一次"而不是"复制判据"。**别的订阅方别把这份负载当成完整清单用。**
- **两半各取 40 条，取不完要说**。Rust 侧多取一条只为了知道"后面还有没有"，前端据此显示
  "还有更多没列出来"。让前端猜数组长度等于把截断藏起来。
- **悬空的排最前且不可点**。面板要说的正是"这篇链到了一个不存在的东西"，`links.target`
  （schema v3）就是为这一条才加的；没有笔记可开的行做成按钮，比不给按钮更坏。
- **资产链接（`![[…]]`）说的是盘上的事实，不是"能不能解析成笔记"**（2026-10-10 补）。
  判据只有 `note_core::assets::exists` 那一份：索引期算一次写进 `links.broken`（**只当排序用的缓存**），
  读路径再算一次覆盖它——外部删一个附件不会碰任何 `.md`（`watch::ignorable` 在攒批之前就把非 `.md`
  挡了），只有现算才追得上盘上。措辞跟着分档：图在 → "附件在库内"，真没了 → "文件丢了"，
  而不是对着一个文件说"链空了"。**资产行一律不可点**，即使它 `rel` 现在装着那个文件的路径——
  它没有对方笔记。`[[notes/乙.md]]` 这种"写法里带点的笔记引用"仍按笔记走（`LinkRow.toNote` 分得开），
  所以界面判的是"对方是不是笔记"，不是在界面上特判 `attachments/` 前缀。完整口径在 [02] §资产引用格式。
  真机三态（`D:\Notes` 探针，验完删、全库 `.md` 的 SHA256 与基线逐行相同）：图在 → 不红 + "附件在库内"；
  把那张 png 从盘上挪走（不改任何 `.md`、不重索引）→ 同一篇重开一次，那一行变红 + "文件丢了"；
  放回去 → 又回到"附件在库内"。测试 Rust 136 → 145 项、vitest 291 → 307 项。

真机（`D:\Notes`，那台库的索引还停在 v1）顺带照出迁移的两个硬伤——顺序错了整个库打不开、
版本号没记下来导致每次开库重跑迁移——根因与修法都写在 [02] D30。测试 105 → 110 项（Rust）。

### 接入模型那一档（AI 档 0，2026-10-10 落地）

M2 的第一块砖不是问答，是"有个地方能把模型接上，并且当场验给你看"。四件事定在这里：

- **形态只有一种：OpenAI 兼容**（用户拍板）。`base_url` + 对话模型名 + 嵌入模型名三格，
  一套代码覆盖 OpenAI / DeepSeek / Kimi / 通义 / vLLM / Ollama 的 `/v1`。Anthropic 原生协议
  将来要另加适配器，**不在这里塞 provider 枚举**——枚举一多，"哪一格该填什么"就没人说得清了。
- **`base_url` 一般填到 `/v1` 为止**，探针打的是 `<base>/chat/completions` 与 `<base>/embeddings`。
  **校验器不猜也不悄悄补 `/v1`**：改写了用户填的地址，屏幕上显示的与实际请求的就是两句话。
  替代做法是把提示做进错误里——404 且末尾不是 `/v1` 时才附一句"这个地址末尾可能要加 /v1"。
- **Key 只进 Windows 凭据管理器**（`keyring`，条目名固定 `dev.note.service` + `ai`）。
  界面上只能看到 `…末4位（N 位）`。docs/02 目录树里预留的 `.note/secrets.keyref` **这一档没写**：
  条目名能推导出来，再存一份就是第二真相；等真支持一个库两把 Key 时再引入。
  **`keyring` 必须显式开 `windows-native` feature**——3.x 没有默认 feature，漏了它编译进的是
  进程内的 mock 存储：`set_password` 返回 Ok、界面报"已存进凭据管理器"、`cmdkey /list` 里什么都没有。
  这条由用例 `存进的是真凭据管理器而不是进程内的假存储` 钉住，判据是**换一个 `Entry` 实例还要读得回来**
  （mock 按实例存，真凭据管理器按目标名存），不是"能读回自己写的值"（那条 mock 也满足）。
- **`note ai key-stdin`：Key 有一条不进对话、不进 argv 的进场路**（2026-10-18）。
  界面输入框那条路会被 WebView 里的脚本看到，命令行参数那条路会进进程表与会话记录——
  只有管道能让它只进凭据管理器。命令**只回末 4 位**，并且**当场读回来对账**：
  空输入是"删掉"而不是"存了一把空的"，那两种结果说两句话（第一版不分叉，把删成功报成了故障）。
- **探针只发固定文本 `ping`**，chat 那一步 `max_tokens: 1`。这句话在界面上明写，因为本地优先的
  产品里"我按测试会不会把笔记发出去"是真问题。真机取证：假端点把收到的每个请求体都落了一份日志，
  六个请求里最长的 82 字节，内容只有模型名与 `ping`，**零笔记内容**。

**200 不等于通**：有些网关会回一个 HTML 登录页。所以成功分支还要认 JSON 里该有的那个字段
（`choices[0]` / `data[0].embedding`），嵌入那一步顺手把**维度**报出来——那个数将来要钉进
`embeddings` 表的建表语句里，现在报出来用户就能自己核对模型选对没有。

**真机踩到的两条，都不是产品逻辑而是边界上的约定**：① Tauri 的 command 参数按 **camelCase** 收
（`baseUrl`），前端按下划线传会直接 `missing required key baseUrl`——按钮点了没反应，而 Rust 侧
什么都没发生；② 探针脚本量按钮坐标与派发点击之间布局会自己动（填齐后"还差…"那句消失、按钮横移），
**每次点击现量一次坐标**，与 §拖拽手势 那条是同一条教训的第二次落地。

**这一档只到"接上了"**：`chat_ask`、`suggestions_*`、`ai_runs` 审计、评测集都还没动，界面上也
明写了"配好之后先别找问 AI 的入口"。配置落在 `<Vault>/.note/config.toml` 的 `[ai]` 段——
那个文件的段级读写从这一档起收进 `note_core::config`（`[backup]` 也搬过去了）：**"读整篇、
只换自己那一段、写回"这条纪律只能有一份实现**，各写一份的结局是后写的把先写的抹掉。
顺带钉住一条 TOML 事实：**段名必须是 ASCII**（`[甲]` 是非法裸键），字段名倒是无所谓（序列化器会加引号）。

### 嵌入落库那一档（M2 档 1a，2026-10-10）

`note_core::embed` + `note ai embed|status`。**这一档没有界面**，看得见的只有 CLI 那三行数字——
下一档（混合检索）才把它变成屏幕上的搜索结果，所以别把"向量进库了"当成"AI 能用了"。

- **写路径一次网络都不发**（G6）。`index_file` 里没有任何一处调嵌入；只有显式命令与将来的
  后台任务会走。把嵌入塞进保存路径，等于让"打字"依赖一个云端 API 的可用性。
- **回包判据比落库严格**：`data[i].index` 要能对上送出去的顺序，缺条、重号、维度不齐
  **整批不落库**。顺序错位会把 A 段的向量安到 B 段头上，而它在检索里只表现为"结果有点不对"，
  几乎不可能被归因到这一步。真机第一次跑就撞上了：靶子只回一条、送出去两条，
  报的是"嵌入回包缺条数：要 2 条，只给了 1 条"，`status` 里已嵌仍是 0——**没有半批偷偷进去**。
- **可续**：`待嵌` 是 `chunks LEFT JOIN embeddings ON model` 里没行的那些，所以中途失败再跑一次
  就接着来，不需要断点记录；换模型名 = 全量重嵌（旧表不猜着删，删它是花用户 token 重做）。
- **进度要说三笔**：已嵌 / 待嵌 / **永不嵌**（隐私位与视图）。少了第三笔，"已嵌 + 待嵌 ≠ 全部"
  就成了用户看得见却没人解释的一笔错账。
- 实现细节（表名 hash、cosine、先删后插、隐私在源头）都写在 [02] §派生表 那段注释里，
  那里是唯一口径。

### 混合检索与评测集那一档（M2 档 1b，2026-10-10）

`note_core::retrieve` + `note ai search` + `note eval` + 侧栏搜索框下面那块「语义补充」。

- **匹配式只有一份**（`retrieve::匹配式`：jieba 分词 → 各词 OR → 丢掉文档频率过半的词）。
  界面搜索与召回共用它。分成两份的代价在真机第一版就照出来了：同一次搜索里，上面那块说
  "没有匹配的笔记"，下面那块说这一篇"两路都中"——两份判据在同一屏上互相打脸。
  顺带改掉的是**短语语义**：FTS5 里整句包成一串要求词相邻，`备份 保留多少份 唯一副本`
  因此什么都搜不到，而它恰恰是最该命中的那篇。
- **丢高频词按文档频率，不按停用词表**：词表要按语言维护，而 df 对这个库自己就是答案。
  不这么做的话，"库里根本没记过"的查询也会因为一个"的"字捞回一堆结果。
  兜底：只剩一个词、或所有词都被判成高频时回到原样——**宁可给噪音也不静默返回空**。
- **合并用 RRF（名次倒数，常数 60）不用分数加权**：BM25 越大越好、余弦距离越小越好，
  两者不可比。同分时按切片号排，保证可重现。多样性是**单篇最多 4 块**（一篇长文能同时
  占掉两路前茅）。
- **配了模型但连不上 → 报错；没配 / 没嵌过 → 退回只走关键词并说明为什么**。这两种情况
  必须分开：把失败说成"这一路没开"就是把错误吞成状态，跟这一档要修的那些谎同一种。
  所以 `混合或退回` 只在"没有向量表"这一支兜底，`ai::embed` 那一跳的失败原样抛。
- **异步那一趟不握着任何人的锁**：`search_hybrid` 里有一次网络往返，所以它从后台那条连接
  `fork()` 出一条专用连接再干活（开 SQLite 连接是毫秒级，摊在网络往返旁边不算成本）。
  握着主锁或后台锁打它，就是"保存后读命令等 3.26 秒"的同一种病。
- **界面上限 5 行、按篇去重、徽章说来源**（两路都中 / 语义 / 关键词）。KNN 一定给得出 30 个
  最近邻，不设上限那一块会把关键词区整个挤出去（第一版真机就是这样）。

### 拒答门那一档（M2 档 5，2026-10-18）

`retrieve::{查询词, 表达式, 覆盖率, 取详情}` + `answer::{依据下限, 最强依据, 无依据}`。
判据、标定表与真机三态在 [04] §拒答判定，这里记工程侧的四条：

- **词表算一次用两处**。`查询词`（分词 + 丢高频词）与 `表达式`（拼 OR）拆成两个函数，
  是为了让"跑一趟"能把同一份词表既送进 FTS、又拿去算覆盖率——否则"匹配到几个词"量的
  就不是实际送进查询的那几个词。`匹配式` 现在是这两个的复合，界面搜索照旧共用。
- **两把尺子分开存**：`evidence`（覆盖率，阈值按它标定）与 `similarity`（余弦相似度，**未标定**）
  是两个字段。合成一个 `max` 很诱人，但那等于拿覆盖率的阈值去卡一把数值天然高得多的尺子，
  标定的意义当场作废。
- **门有两道，重排夹在中间**：先拿全部候选过预检（弱就根本不跑重排——重排只改顺序，造不出依据），
  没被拦才重排；重排后再用**实际送进模型的 top-8** 过第二道门。拦下来时 `in/out tokens` 为 0
  （若跑过重排，重排那笔照样记）；审计里 `候选 = min(检索条数, 8)`——"有候选但都不够依据"与
  "什么都没搜到"必须是两笔能对上的账。
- **标定绊线是常量断言**（`#[expect(clippy::assertions_on_constants)]`）：它不测运行时行为，
  作用是"覆盖率口径或语料变了就编不过/跑不绿"，提醒重标。真跑数据的入口是
  `note eval <库>` 输出里那段**依据强度分布**（升序，标着 正·中 / 正·漏 / 负）。

### 流式那一档（M2 档 6，2026-10-19）

`ai::chat流` + `answer::ask流` + `chat_ask` 事件。**只动"字什么时候到"，不动"什么才算答案"**：
`答复` 的返回形状一字未动，引用完整性判定仍在函数返回前跑完，所以流式不可能把没采信的东西递出去。
四条工程侧的口径：

- **一条流水线，两个壳**。`发问` 这个 trait 加了 `流着问`（默认实现就是 `问` 然后一次给完），
  于是假模型与不关心流的调用方一行都不用改，而**幻觉门只有一处**。当初想过"再写一条流式的
  问答函数"，那就是两条流水线——一条改了另一条没改，而这条上挂着红线。
- **思考不是答案**。DeepSeek-R1 一类先吐 `reasoning_content`，那几十秒里 `content` 是空串
  （真机第一条：解析器只认 `content`，于是报"一个字都没有"，实际是它还在想）。现在
  `ai::流::{答案, 思考}` 分开走，`事件::思考` 只喂界面上那句"正在思考…｜已思考 N 字"，
  **一个字都不进 `答复.text`，也不进引用判定**。
- **超时不能按"整段几十毫秒回完"来设**。非流式那条 20 秒总超时是对的；流式必须放宽
  （现在 180 秒），否则思考型模型必然被自己掐死。`reqwest::blocking` 的 builder **没有**
  `read_timeout`（只有 async 侧有，实测编译不过），所以宁可给一个宽松的总闸也别没有闸——
  没有闸的话一次挂死的流会永久占住那条 `spawn_blocking` 线程。
- **对方不支持流式就退回非流式，但要说**。一个字节都没收到 = 它多半不 stream（真机那家网关
  会在流中途直接 reset 连接），这时用非流式再问一次并留一条 `warn`——用户要的是答案，不是
  我们的实现偏好，代价（首字时间没了）写在文档与日志里。
  **只回了思考却没等到答案的不自动重试**：它已经想了那么久，再打一趟是双倍的钱与等待。
- **一行 SSE 只报一件事，而字最要紧**（2026-10-30 真机取证）。`解流行` 原先先认 `usage` 再认字，
  而这家网关**每个块都带 `"usage": null`**——`Value::get` 对"有键但值是 null"回 `Some`，于是每个
  带字的块都被整块吞成"用量"，全文与思考双双归零，看起来正好是"这家不支持流式"。三趟采样：
  30/30、38/38、12/12 块全被吞。它的后果不是报错，是**每一次流式都悄悄退成非流式**（首字时间
  没了、多打一趟），而那条 `warn` 用的是 `tracing`——这个应用没装订阅器，等于没说。
  现在的顺序是 思考 → 答案 → 用量 → 收尾，且 null 不算用量。
- **答完的空 ≠ 没答完的空**（同一天）。`finish_reason=stop` 或收到 `[DONE]` 而 `content` 全空，是
  对方答完了、答的是空：传输层不替调用方决定这算什么，把空串带出去，顺带把已经到手的 `usage`
  一起带走（在这儿报错等于把这笔开销从账上抹掉，同 §审计那条"拒收也要记账"）。改写这层于是
  能说那句实话——**这一档只会把一段换成另一段，删不掉东西**：用户要求"把这段清除掉"时，模型
  想的正是 `output should be nothing`，而我们没有"换成空"这个动作。没走完的空（`length`、半路断）
  才由 `chat流` 报 `EmptyAnswer`。原先那句"多半是被超时截断了，试着把问题问短一点"是把猜测
  当结论：账上那一趟 20.8 秒，而流式超时上限是 180 秒，超时根本没发生过。
  **2026-11-02 补**：空回稿不再止于一句提示——用户明确要求删除时，AI 对话框给出一枚
  「删除这段」的二次确认钮；确认后只删这一轮锚住的那段文字（一笔可撤销事务，锚点失鲜则拒绝）。
  改写本身仍只做"换一段"，删除是另一枚动作。
  **同日再补整篇清空**：AI 对话框识别"清空整篇 / 全文 / 文档内容"这类整篇意图后，不走改写、
  也不调模型——直接给二次确认，确认后以一笔事务清空全部正文（front-matter 保留、`Ctrl+Z`
  一步回退；确认期间文档被改过就拒绝）。它不重新生成块，因此不碰 G5；整篇"生成式改写"走下面
  那条块级补丁协议。
  **整篇编辑也补上了**（同一天，11-02 晚又收了入口）：对话框不再有「本段 / 整篇」范围开关——
  选中文字就改选区，**没选字就是整篇**（把块清单 key / kind / text 发给模型）。模型只回块级补丁
  （replace / delete / insert_after），前端校验 key、在对话框里预览，用户点「应用修改」才以一笔
  事务落入；提问也走整篇这一路，回答写在 `note` 里、`edits` 留空。未涉及的块原样复用，块 id 跟着块走；
  表格 / 图片 / 分隔线不给 replace（表格可删/旁插，图片只能删，分隔线可删/旁插）。
  **没有 `^b-` 的真实笔记也能编辑**：块 key 在收集时按顶层序号发成 `i-N`，计划带整篇快照，
  只在 `state.doc.eq(快照)` 时应用——临时 key 只活在这一趟请求里，不落盘。**空文档能写**：
  块清单为空时模型只许 `insert_after` + `after: null` 从文首写。**`replace` 可带 `kind`**
  换块类型，排版优化（段落→标题/列表/引用/代码）不必拆成删+插；拆分 = 删原块 + 同一锚点多次
  `insert_after`，合并 = 保留首块 `replace` + 删除其余。`kind` 只开段落 / 标题 / 列表 /
  引用 / 代码：**带 `^b-` 锚点的块不换成分隔线或表格**——分隔线写不回锚点（`--- ^b-…`
  已经不是分隔线），表格序列化器也从不写锚点，换过去就是悄悄弄丢引用；要这两类就
  `insert_after` 另插。**替换沿用原块的 `mdRaw`**（只当"这块来自文件"的凭据与有序记号来源，
  `mdSig` 仍清空，绝不会被原样回写）：清掉它，作者留的两三个空行会被当成新建块重算成一个——
  改内容与改类型都不该顺手改排版。整篇补丁**中途插入的源码块不带头落脚点**（不落盘，
  但在正文里多一行可见空白），只有整份结果真的以表格 / 源码块收尾时才补一个；**同一块替换之后
  还跟着 `insert_after` 时也不补**——它已经不是末块，空段落就是正文中间凭空多出一行。
  **块边界按落盘后的 Markdown 判**（同日第三轮复查）：改过的段落 / 表格 / 图片若紧贴在上一块
  后面（`mdGap` 为空），重读时会被当成续行并进上一块——"文首插一段"与"列表项改成正文"
  两条真探针都复现过合块。`docToMarkdown` 现在只在**边界任一侧变过**、且下一块不能自己起头
  （标题 / 列表 / 引用 / 围栏 / 分隔线可以）时补一个空行；两块都没碰过的紧排（标题紧接段落）
  原样保留。**代码块替换先摘尾锚**：模型看到的是带 `^b-…` 那行的完整围栏源码，原样回传会让
  `拆围栏` 的"闭栏在末行"判据失败、整块退回源码视图；先摘掉再拆，锚由 `mdId` 补回。
  **块级记号整份拒绝**：段落正文以 `#` / `-` / `>` / `1.` / `---` / 四格缩进 / `![[` 开头
  （围栏另算），落盘就会被重启时读成另一种块；整篇编辑整份拒绝并说清换用哪个 `kind`，
  选区改写只拦"回稿落在行首"（块首或硬换行之后），并在那一轮明说"块级记号"而不是
  "锚点失鲜"——标题自带 `## ` 前缀、代码与引用块里 `#` 就是正文，两边都不拦。
  最近 8 条对话（≤6000 字）随请求带上，
  "再短一点""接着刚才那版"能接上。整篇"重新生成 blocks"仍不做——那要重写块边界与块 id。
  **取回稿不走流式**（2026-11-02 真机取证后定）：计划是 JSON，没有逐字显示的需求；
  而这家网关的 SSE 会偶发吞掉第一块——同一句追问采到的回包从 `"its":[],"note":` 开始，
  `{` 连同 `"ed` 一起没了，解析必然失败。改走 `ai::chat长`（非流式 + 180 秒），
  五条真模型请求（空文档写作 / 整篇排版 / 整篇问答 / 带历史追问 / 换块类型）全部拿到合法计划。
- **半截流不算答案**：EOF 与 `[DONE]` 在 `read_line` 眼里都是 0，所以 `收流` 单独记一个
  `见到结束`；有字但没见到 `[DONE]` 的直接报"不完整、没有采信"，不交给引用门——
  门只查编号，查不出半句话被截断。非流式那条仍用 20 秒总超时，流式放宽到 180 秒。
- **`ai://reset` 不是装饰**：第一次的答案违规时字已经播到屏幕上了，没有这个信号，屏幕上就会
  留下一段"显示过但没被采信"的答案——那正是这一档最坏的样子。用例
  `流式播字与违规那次要播重来` 钉的就是这个序列。

### 带引用的问答那一档（M2 档 2a，2026-10-10）

`note_core::answer` + `note ai ask|runs` + 底部那格「问答」。M2 三条验收硬门里，**幻觉率 = 0 是唯一
一条不需要真模型就能钉死的**（`recall@8` 得有好语料，隐私召不回已经由 1a 的源头排除管住），
所以这一档的判据全做成纯函数，假回答就能把它跑红。

- **提示词只是请求，不是保证**。"绝不编造编号"写在系统提示里，而真正的门是程序侧的
  `引用编号` / `越界引用`：`[K3]` 与裸 `K3` 都认，`K1x` 算一个词不算编号，小写 `k` 不算
  （否则模型写 "SQL" 或 "Keras" 会被误判成幻觉）。
- **违规只赌第二次**：出现没给过的编号就重生成一次，并且**把违规编号和允许清单原文说回去**
  （"你上一条引用了没给过的编号：K9。只允许这些：K1、K2"）。第二次还有就降级，不再赌第三次——
  我们不敢保证模型不编，但保证**编了的东西不会作为答案递给用户**。降级话里要点名是哪个编号，
  不然用户和未来的自己都无从归因。
- **"没依据"有三种，都得算依据不足**：模型自己说「依据不足」、回答里一个编号都没有（泛泛而谈）、
  两次都有幻觉。第二种最容易漏——它读起来像答案，而它没有任何一条能点回去。
- **零候选一次模型都不打**（`生成` 在依据为空时先返回）。省的不只是钱：没有片段可依据时，
  叫模型只会让它自己编。**但真机照出这条路几乎走不到**——一旦有了向量表，KNN 对任何问题都给得出
  邻居，检索层永远返回候选。所以真正挡"没依据还硬答"的是**答案层的分数阈值，而它还没标定**
  （[04] §拒答判定）。这条写在这里是为了防止以后把"零候选 → 依据不足"当成防线已经成立。
- **上下文上限 8 片段**（`引用上限`；召回配额是每路 30）。全塞进去既烧钱又稀释注意力，
  而 [04] §上下文组装 的形状就是这一档的实现形状（`[K3] 面包屑 (块 ID)` + 正文），
  编号按名次排——模型看到 K1 排第一，不用再猜我们的分数怎么算。
- **`ai_runs` 每次都落，包括失败与降级那次**。审计页要回答的是"这个库问过什么、引用了哪几块、
  多少 token"，漏一条就是一条查无实据的账。`ok = !insufficient`，两趟的 token 累加，
  附带 `retried` / `semantic` / `candidates` / `cited`（所以界面上能看出这条是第二次才过的）。
  **审计写失败只 `warn` 不把答案吞掉**——钱已经花完、答案已经生成，此时报错等于把已到手的
  结果换成一句失败；但也不许静默，那正是"账对不上"的来路。`usage` 没回时记 0 而不是猜一个数。
- **界面上把账摊开**：`模型｜候选 N｜in/out tokens｜ms｜（重试过）`，采信的依据逐条可点跳回块，
  未采纳时整卡转红。底下「最近的生成」直接读 `ai_runs`，失败的那几条也在。
- 锁的纪律同 1b：`ai_ask` 最多两次网络往返，从派生连接 `fork()` 出专用连接再干活。

### 只填一格那一档（M2 档 A，2026-10-10）

`ai::列模型` + `ai_discover` + `note ai models` + 设置里那枚「列出可用模型」。
这一档不新增能力，改的是**门槛**：必填从三格降到两格（地址 + 对话模型），嵌入模型变成可缺。

- **为什么嵌入模型不该是必填**：DeepSeek 只有对话端点，Anthropic 的 Messages API 没有
  embeddings，Kimi 的嵌入要单独申请。把它算成"没配好"等于**逼用户去填一个他家不存在的东西**，
  而后果只是"少一路检索"。留空是一条正常配置，不是残缺状态。
- **判据不许各写一份**：`ai::缺项`（Rust，`probe` 用它决定发不发请求）与 `ui/ai.ts` 的 `缺项`
  （界面用它决定按钮能不能点、状态怎么写）必须同规则——两边各自有用例钉着同一批事实，
  其中一边是反面断言（Rust 侧断"缺项里不许出现 `embedding_model`"，TS 侧断"留空算齐"）。
- **"没发请求"不是"通了"也不是"失败"**：`probe` 在嵌入留空时发一步 `embeddings-off`，
  `ok = true`（它不该红）但**单独占一行、写清少了什么**。报告标题那句"两个探针都通了"改成
  `探针结论()` **数出来**——只打了一个探针还说"两个"，是同一种谎。
- **界面上那句"通了"以前也是半个谎**：报告标题那句要分**能检索**与**只对话**。用户看到"通了"
  会以为搜索也在用模型，而搜索那一路当时根本没开——这句话现在只活在 `探针结论()` 里（它按
  实际打了几发探针数出来说），不再由入口上那枚角标替它说。
- ~~**配齐但没测过说"已配置"，不许空着**~~ **同日撤回：角标整个不要了**（2026-10-27 晚，用户
  拍板）。那枚角标要同时回答"盘上填了没"（`aiView`）与"这一次测过没"（会话内的结论），两件事
  挤在 12px 里各说半句；而"填了没"设置页「模型与 Key」那一格已经说，"测过没"由它自己的测试
  报告说——三处讲同一件事，用户还得挑一个信。现在标题栏那枚齿轮**只有图标**，配置状态只在
  设置页看。`徽标()` / `徽标红()` / `备份角标()` 与"测过"那一格状态一并删掉，不留纯函数当
  摆设（真机照出来的那个"保存后一个字都不显示"也就无从发生了）。
- **问端点而不是背文档**：`/v1/models` 是"这把 Key 能用哪些模型"的官方回答，所以程序去问。
  挑候选的判据**宁可漏也不猜**——只认 id 里含 `embed`（不区分大小写），`bge-m3` 这种不含的
  就不猜，清单原样摊在界面上让他自己挑（猜错一个名字的代价是他花 token 嵌完整库再发现维度对不上）。
- **读不懂 ≠ 没有**：`解析模型清单` 认 `data[].id`、`models[].id`、`models[].name` 三种形状，
  认不出来**报错**而不是返回空清单——"这家一个模型都没有"和"我没读懂它的回包"必须分开
  （同 1b 那条"配了但连不上 ≠ 这一路没开"）。
- **这一步零隐私成本**：`GET /v1/models` 无请求体。真机取证：假端点收到的五次列模型请求
  body 全为 `(空)`，那一轮里唯一带笔记字节的请求是问答本身（294 字节，装着 `[K1]` 片段摘录）。
- **真机照出来的两条都是文案**：① 未启用那一步的指引写着「看看这家有哪些嵌入模型」，
  而按钮叫「看看这家有哪些模型」——用户按着找就找不到；② 面板底部那句"测试只发两个最小请求"
  在只有一个探针时是错的。两条都改，并且第一条现在由 `src/ui/ai.test.ts` 那条**跨语言用例**钉住：
  它从 `App.tsx` 与 `ai.rs` 两边各读出按钮名比等值，改一处就红（这类"话与控件对不上"的缺陷
  单侧测试永远拦不住）。
- **路线随之改了**：既然对话模型是唯一人人都有的那一个，检索质量的下一档就押在
  **图扩展（纯本地免费）+ LLM listwise 重排（只要对话模型）**上，嵌入降级为"有就更好"。
  口径见 [04] §召回 与 [05] §M2。

### 选区改写那一档（M2 之后、M3 之前，2026-10-21；2026-10-28 改成底部对话框）

`note_core::rewrite` + `ai_rewrite` + **文档底部的 AI 对话框**（入口从"工具栏 / 气泡上那枚 ✨"
换成它，理由见 [02] D36）。用户点名的缺口是"正文里没有调用 AI 改字的入口"；这一档补的是入口，
不是自动整理。**边界写进 [04] §0**：AI 自己起的写意图仍一律 `suggestions`；这一次是用户主动
发起的编辑动作，AI 只交候选，点「替换」才落盘。

- **只改一个目标，整篇只作背景**（2026-10-28；目标来源 11-02 收口）。目标 = 选中的一段；
  **没选字时不再按光标所在段兜底**，而是走整篇块级编辑（`收集整篇` + `aiDocEdit`）。选中原文
  直接显示在对话框输入框上方（`看选区`），发送前能核对；请求体 = 系统提示 + 目标原文 + 那条要求 + **整篇正文作背景**（上限
  2 万字，超出截断并在请求里写明；不送路径、标题与 front-matter）。带背景是为了让"这段在说
  什么"成立——只给一句话的改写，经常把上下文里已经交代过的信息又写一遍。假端点逐条落盘的
  请求体可复查（`vibe_images/ai-rewrite/requests.log`）。**私密篇的整篇背景在 Tauri 层就挡掉**
  （`rewrite::是私密篇` 查索引库的 `ai_private` / `no_ai`，查不到按不私密处理），只把用户点名的
  目标段发出去；回稿里 `ctxChars = 0`，界面据此说"私密篇：只发了目标段"。
- **一条流水线**。`rewrite::生成` 复用 `ai::chat流` 的 `流::{答案, 思考}`，前端拿
  `ai://rewrite-token` / `ai://rewrite-think` 拼字；`runId` 对不上就丢，关掉对话框后再到的字
  不会落进下一次。
- **只接一段连续文字**。`取选段` / `看选区` 是纯函数：整块选中 / 跨块 / 含换行 / 全空白 /
  超过 8000 字都直接说原因（预览照实显示原文），不把按钮灰掉让人猜。回稿同样只接受单行；多行、空、超过 20000 字
  一律判"没有采用"（`洗回稿`），不在客户端悄悄折叠。
- **替换是一笔事务，替换后把新文重新选中**。`替换选区` 把回稿按同一份 `parseInline`
  解析成行内 Markdown（加粗 / 斜体 / 删除线 / 行内码 / 上标 / 下标 / 链接 / 高亮 / 颜色 span），再用
  `replaceWith` 落进文档；**只有覆盖整个选区的标记才继承**给回稿里没写样式的字，回稿自己的
  标记优先，父节点收不下标记时退成纯文字。预览走同一份解析，所以"看到的样式"与"落进正文的
  样式"是同一句话。选区落到**新文整段**上——下一句"再短一点"接着改的就是刚改完的这一段，
  这是"对话式改字"的连续性。不重新选中的话，下一句就会被当成"对整篇说的话"。`Ctrl+Z` 一步
  回到原文——打签名那笔事务本来就 `addToHistory:false`，不会被撤销栈夹在中间。重开应用后
  编辑器历史不跨会话，这条保护只在当前窗口有效。
- **显式样式动词在本地执行**（2026-11-02）。整句与动词表**完全对上**（加粗 / 斜体 / 删除线 /
  行内码 / 上标 / 下标 / 高亮 / 六色文字色与底色 / 标题 1–6 / 正文 / 无序 / 有序 / 待办 / 引用）就直接改文档：
  不发请求、不记账、不需要模型；它排在 `aiReady` 检查之前。带内容要求的句子（"加粗一点顺便
  改得更正式"）仍然交给模型。行内样式只动选中的字，块类型动光标所在块；没有实际改动就不发
  事务（空事务会把笔记白标一次脏）。
- **失鲜就拒绝**。等回稿期间锚点跟着每个事务映射（`from` assoc=1、`to` assoc=-1），应用前再比
  一次 `textBetween`。改过就保留那一轮的回稿、明说"目标那段文字在这期间被改过"，不拿旧锚点盖新字。
  真机验过（当时代码）：回稿到后把首字改掉再点替换，文档保持"改是一段…"，提示里的红字就是原因。
- **落点：钉在正文列下沿，不跟着选区跑**（2026-10-28）。对话框挂在滚动容器**之外**
  （`App.tsx` 里 `.editor-pane` 这一层），正文怎么滚它都不动；默认只露一条把手，悬浮 120ms
  展开、移开 260ms 收起。**五种情况不收**：焦点在框里、正在生成、有未发送草稿、被钉子钉住、**指针仍停在坞上**——在面板里点一下空白会让输入框失焦，但那不是"用户走了"，收掉面板等于"我就点了下空白，怎么没了"。
  "移开就收"这条规则不该把用户正在读或正在写的东西收走。原来按选区几何算落点的那一套
  （`浮层位置`）随之删掉：位置固定以后，"放不放得下"这个问题不存在了。
- **入口只有一处，判据只有一份**（2026-10-28）。工具栏最右与气泡条上的两枚 ✨ 撤掉了——同一条路
  开三个门，用户每次都要先认"这枚是哪个"。被拦下（模型没配 / 目标不成立）的原因直接写在
  对话框里（发送时那一行红字），不再需要挂在工具栏下沿的 4 秒提示。
- **审计不存正文**。`ai_runs` 行 `task='rewrite'`、`trigger='user'`，`cited_blocks_json` 只放
  `preset / charsIn / charsOut / ctxChars`（背景带了多少字，用来解释"这次为什么这么贵"，**不存
  背景内容**）；失败那趟也落（`ok=0` + 错误）。写审计失败只 `warn`，回稿照给。
- **真机**（Win11 + WebView2 + 临时库 + 假 SSE 端点，块间隔 300ms）：三击选中 33 字 → 气泡
  「AI」→ 浮层流式到 20 in / 12 out、936ms → 点「替换选中」→ 盘上 `notes/改写探针.md` 变成回稿
  且自动保存 → `Ctrl+Z` 一步回到原文；`ai_runs` 读出 `r-vg1tt6hz | rewrite | user |
  {"charsIn":33,"charsOut":17,"preset":"polish"}`。用户库未打开（指针指向临时库），收尾恢复指针、
  清掉假 Key，`D:\Notes` 全部 `.md` 的 SHA256 与基线一致。**上面这一趟是 2026-10-27 那版浮层的
  记录**；2026-10-28 换成底部对话框后，请求、回稿、替换与审计走的是同一条流水线，**对话框本身
  尚未真机走**：要验的是悬浮展开 / 移开收起、点发送与替换时不丢选区、以及"替换后新文整段选中"。
- **仍欠**：只支持单段文字（跨块 / 表格 / 整块另开档）；**整篇改写没有落盘路径**——回稿要能逐块
  落盘，才谈得上"把整篇交给模型重写"（块边界 / 表格 / 围栏 / 块 id 都会被重新生成打散，G5 不允许
  静默重写，见 [02] D36）；撤销只靠当前窗口的编辑器历史；改写质量没量过——假端点只证明机制，
  不证明"改得好"。

### 设置页（2026-10-23 落地）

一个页面，四格：**外观**（主题）/ **备份** / **模型与 Key** / **库与关于**。入口是标题栏那枚
齿轮（`Ctrl+K` 里也有「打开设置」）。原来散在三处的东西搬进来了：主题原来在标题栏一个
`<select>` 上，AI 配置原来在侧栏底部那格「AI」里，备份目录原来在备份面板里。

几条不能省的规矩：

- **判据只有一份**。备份的状态是三态（开着 / 没配 / 关着），判据收在 `src/ui/settings.ts` 的
  `判备份` 一处，备份面板那一行与设置页那一格都从它取——两处各拼一次就会有一处说
  "没开"而另一处说"开着"。用例钉的是**三态要能分辨**（"没配"与"关着"是两回事：前者是没去设、
  后者是明确说了不备份），不是三处文案相等。
- **设置页是主区的一个 mode，不是浮层**：与备份 / 回收站 / 导入同一套（`mode` 状态机）。切走
  前先 `persist()`——切走会卸载编辑器，而自动保存那条 effect 在 `editing` 变假的那一刻就撤了
  待发的定时器，不先落盘，改的字要等回到正文才重新排上队。
- **换库要清旧库的编辑态**。`vault_open` 之后只刷 info 与列表，`selected` / `draft` / `links`
  揣的还是上一篇——不清就是"在新库里显示旧库那一篇"，一保存还会写回旧目录。切过去之前先
  `persist()`，切过来之后 `setSelected(null)` 等一并清掉。
- **入口不挂状态**。侧栏那格「AI」没有了之后，那枚角标曾在 2026-10-27 白天挂到标题栏齿轮上，
  当晚按用户的要求撤掉（理由见上一节）：**入口只负责进去**，状态归它自己那一页。同一天撤掉的
  还有备份按钮上那句"没开"——它挂上去那一排放不下（挂上就换行，换行后两排方框粘成一张格子），
  而设置页的备份行与备份面板本来就说这件事。侧栏底栏只剩「回收站 / 导入 / 备份 / 问答」。
- **主题用原生 `<select>`**（[06] §4：控件行为与键盘都得原生的，自造下拉是被判死的），三档
  跟随系统 / 亮色 / 暗色。搬进设置页后标题栏只剩一枚齿轮。
- **哪些跟着库走、哪些跟着这台电脑走**写成设置页里两行（跟着库走 / 跟着本机）：备份目录与
  AI 端点、模型名落在 `<Vault>/.note/config.toml`（随库走）；主题落应用自己的存储；API Key 落
  Windows 凭据管理器。这两行就是下面 §路径归属那句"换机不是零成本"的用户可见版本——
  **Key 不随 Vault 迁移**。
- **按钮基线提到 `src/ui/controls.ts`**：设置页与主窗要用同一副，留两份常量就让 [06] §3 那张
  "Button 变体体系"的欠账从两份变三份。
- **版面改成了设置行（2026-10-27 第二版）**：标签在左、控件在右，行与行一条细线，组名旁边只留
  状态（已开启 / 已配置 / 索引 N 篇）。卡片、每节摘要、脚注全去掉了——设置页要能扫，不要读。

  两句话自相矛盾。回话落在右下角：
  页顶那行 flash 在长页里会滚出屏幕，等于存完没反馈（与正文"已自动保存"同一处、同一套 token）。
- **存 Key 并进「保存配置」**（2026-10-27 用户拍板，撤掉原来那枚独立的「存 Key」）：Key 落
  Windows 凭据管理器、三格落 `.note/config.toml`，**存储分开是后端的实现**——用户按的是"保存"，
  不该知道有两份存储，更不该记得多按一次。现在「保存配置」= 把这一页的改动一次写进去（先存
  配置再存 Key；Key 存失败时配置已落盘，照常把新的 view 填回界面，Key 那一句单独报——失败
  只该影响 Key 那一格，不该把整页说成"什么都没保存"）。输入框有字时行内写一句"按「保存配置」

  "这把 Key 现在存不了"——保存那一枚本来就按不动，不能还说"按一下就写进去"。

  删 Key / 测试 / 列模型）都是"成功了才 `setError(null)`，失败就换一条新的"，且保存走
  Key 那一支时连上一条成功 toast 一起撤——红字与"已保存"不许同屏。

  `setBackupDraft` / `setAiReport(null)` / `setAi发现(null)` / `填回(aiView)`，于是刚填的备份
  目录、模型字段、测试结果全没了，齿轮偏偏就在光标旁边、长得像开关。侧栏底栏那四格（回收站 /
  导入 / 备份 / 问答）才是开关，齿轮不在那一排里——于是设置页必须**自己带一条回正文的路**：

### 版本快照那一档（M3 档 0，2026-10-24 落地）

M3 建议箱的第一件事不是建议箱，是**撤销要落在哪里**。M3 的验收门 ① 是「任何一条建议接受后都能一步撤销并还原到快照」——而"还原到快照"这句话在 `note_versions` 表建好却零写入的时候是没有落点的。档 0 把那条路修好：`note-core::versions` 是新的一个模块，它管三件事——**存前像**、**读回一版**、**按 reason 区别对待**。

**一条快照 = 一次操作之前盘上的内容**（前像）。不是后像：撤销要的是"回到没改之前"，存后像等于存了"再往前一版"，中间那一步——正是用户要撤的那一步——永远撤不回来。三种 reason 只有"谁触发的"不同：`manual`（用户改一篇 / 从备份快照恢复）、`ai_applied`（对话框点「替换」落的那一笔，前端把这一次标成 AI 传下来）、`before_delete`（移进回收站）。**30 分钟合并窗口只作用于 `manual`**——连续编辑不该在历史里留一串快照；`ai_applied` 与 `before_delete` **不合并、不清理**，它们是撤销与恢复的落点，留着是因为留着才有意义。

**钥匙是 path，不是 note_id，而且不挂外键**（[02] D32）。原来的 `ON DELETE CASCADE` 有一个致命后果：笔记进回收站 → `notes` 行被删 → 版本跟着级联消失，而那正是撤销与恢复唯一要用的落点。改路径（改名 / 归档）时版本历史跟着搬——否则历史就掉在旧路径上，撤销在新路径下找不到落点。

**快照分两半落**（[02] D33）。同步那一半**只读盘、只排队**：冲突判定本来就要读盘上那一份，那一次读顺手把前像读出来（前像与冲突判定共用一次读，不多花钱），然后排进一个内存队列。blob 与行由**后台那一半**落——往 SQLite 写一行要跟后台那条连接抢写锁，而主锁被后台事务占住时前台任何一条命令都得排队，那是 3.26 秒那次事故的形状。队列挂在 `Index` 上，`fork()` 复制同一个 `Arc`，所以主连接排进去的东西后台那条连接看得见。爆队时丢最老的一条（丢的是"历史里的一版"，不是笔记本身）。

**落哪几条路**：保存（`manual`）、从备份快照恢复（`manual`，恢复是覆盖动作）、移进回收站（`before_delete`）。**导入不进这一列**：导入**从不覆盖**——目标已有同内容就跳过、有不同内容就 `-2` 另存，所以它没有前像可存。同理速记永远落在新文件上。

读回一版时**核对 hash**：对不上就是坏档，宁可报错也不把半截内容当成用户的旧版本还回去。

**一条只跑单测照不出来的坑**（2026-10-24 端到端才照出来）：开库那一刻会清孤儿（没有行指着的 blob 删掉）。清孤儿拿**相对 `.note/versions/` 的那一截**去比行里存的**库根相对路径**——两边口径不一致，于是**每一份快照都被当成孤儿删掉**：行还在、文件没了，读回当场报错，撤销的落点全空。单测写完立刻读，中间没有"重开一次库"这一步，所以照不出来；是命令行那条链（备份 → 恢复 → 列历史）照出来的。已修，两边现在比的都是库根相对路径，并补了两条用例钉住：**重开库之后快照还在**、**没有行指着的 blob 会被清掉**。

这一档**还没有界面**：服务层有 `note_versions` / `note_version_content` 两个方法，CLI 有 `note versions`（`--show <id>` 取正文），但 Tauri 侧还没接命令——界面在 M3 档 2（建议箱 UI）与档 3（应用与一步撤销）才有像素，那时才接得上。

### 命令面板（2026-09-28 落地）

`Ctrl+K` 唤起，输入框 + 一张按分数排的表。三件事写在这里，因为它们都是"看起来小、做错就难受"：

- **只放不需要二次确认的动作**。改名 / 归档 / 删除在界面上都带着确认或冲突处理（"仍然存我这份"
  那种），把它们塞进"打字 + 回车"的入口等于绕过那道确认。所以面板里是：跳笔记、改属性、
  回收站 / 导入 / 备份、主题三档、重新读取索引。**后来还加了「问 AI（带引用）」与「打开设置」**
  （2026-10-27 对回代码补的这一句——从前这里与 [05] 都写着"问 AI 没放进去"，而它早就在了）。
  没进去的是**改写**：它在**文档底部的 AI 对话框**里（2026-10-28 换了入口），命令面板够不着——
  那是一个带着当前选区 / 光标位置的对话面，塞不进"打字 + 回车"的一张表。
- **打字没找到就是要建**——"没找到"指的是**一条命中都没有**（`补新建`，判据与动作分开的纯函数）。
  这条 2026-09-29 修过一次：从前判的是"有没有**全等**的标题"，于是打前缀时（"性能复测" 对上
  "性能复测样本（临时）"）结果里明明列着那篇，「新建笔记」还是冒出来，而且 `unshift` 到第 0 行——
  **回车默认落到的正是那个会往库里写文件的动作**。复测当天探针按 `↓`+`Enter` 想打开样本，
  实际建出了一篇重复笔记（已删）。判据改对之后它只在空结果时出现，那时它是唯一的一条。
  顺带留着的另一条事实：这条路是真机验出来的——误按回车时 front-matter 的 id / title / created 全对。
- **关掉要把焦点还给开它之前的地方**，否则键盘用户每开一次都要重新找光标。列表只在面板打开时
  现搭：300 篇的数组每次渲染都建一遍的话，正文里每敲一个字都要白付一次。

匹配是纯函数（`src/ui/palette.ts`）：全等 &gt; 前缀 &gt; 连续子串（越靠前越好）&gt; 子序列，
**label 的命中永远压过 hint**（搜"回收"要先出"回收站"，不是路径里带回收的笔记），空查询保持
调用方给的次序。8 项单测钉住这些次序，因为它们只能被"打出来的字"证伪。

真机（CDP 可信按键）：`Ctrl+K` 开、打「渲染」出三条、`↓` + `Enter` 打开那篇并挂上编辑器、
没命中的词只剩「新建笔记『…』」、`Esc` 关掉；**面板里打字全程正文 `textContent` 一字未变**，
库里 `.md` 逐字节未变。

### 属性面板（2026-11-05 落地）

整篇源码态撤掉之后，`tags` / `props` / `ai.private` / `ai.no_ai` 在界面上没有入口了。
属性面板补回这一块，但它**不是源码模式的替身**：正文仍然只有所见即所得一面，这里只列
结构化字段。

- **入口**：正文右上角管理动作里的「属性」，以及命令面板的「编辑这篇的属性」（没开笔记时
  不出现）。它是主区的一档，不是浮层；`Esc` 能出来，但焦点在输入框里时那一键归输入法 /
  输入框自己（与设置页同一条守卫）。
- **只动改过的那几行**：`crates/note-core/src/meta_edit.rs` 按行替换 `tags` / `props` /
  `ai.*`。未知顶层键、段外的注释、CRLF 行尾都原样保留；没有变化时连 `write_atomic`
  都不走（不产生版本快照、不刷 mtime）。两处边界要说清：**改 `tags` 会整段重写这一节**
  （块写法里的段内注释、flow 行尾注释不保留）；**属性改名会把它挪到 `props:` 段尾**
  （后端按"删旧键 + 段尾写新键"执行）。行内写法（`props: {a: 1}` / `ai: {private: true}`）
  要改其中一项时先展开成块写法——数据保留，格式变成常见的块状。
- **只发真正改过的栏位**：没碰标签输入框就不发 `tags`。标签框是"逗号分隔的一行文本"，
  盘上合法的 `tags: ["a,b"]` 在里面表达不出来，无条件重解析会把一个标签悄悄拆成两个；
  没动的 AI 开关同理。属性本身是逐项意图，复杂值没删就完全不进补丁。
- **复杂值只读**：`props` 里的列表 / 映射在面板里没有能表达它们的控件，只显示、可删除，
  不用一个文本框去猜。新增属性的类型按值推断（日期 / 数字 / 布尔 / 文本），已有属性的
  类型不跟着值改。
- **没有 front-matter 的笔记也能加**：导入路径不改用户文件（docs/02 D24），所以这类笔记
  第一次保存属性时会新起一块 front-matter，只写用户填的那几项，不补 `id` / `created`。
- **坏 YAML 只读**：解析不出来时不拿一份空结构去猜改哪一行，面板明说"改不了"。
- **结构不对的段整次拒绝**：整段能解析不等于面板能改——`props:` / `ai:` 若是块序列、
  `ai:` 是标量、`tags:` 是映射，按行插入会把文件拼成不合法的 YAML 或悄悄吃掉原结构。
  这三种现在都返回错误、一个字节不写；落盘前还会把拼好的 YAML 再解析一遍兜底。
- **冲突走同一条判定**：打开时拿盘上 hash，保存原样带回；对不上就报冲突，横幅上给
  「读磁盘版本 / 仍然存我这份」。保存成功后**必须重新装载这篇**——编辑器的
  `EditDoc.frontMatter` 还是旧的，不重载的话下一次正文保存会用旧 YAML 把刚写的属性盖回去。
- **没保存就切走要问一句**：离开这一页的入口在侧栏、搜索命中、底栏四格与命令面板、
  新建笔记（建完就进正文），面板自己接不住，所以由 `App.tsx` 的 `可弃属性()` 统一拦；
  「取消」是用户明确要丢，不走这一问，`Esc` / 「完成」则跟其他入口一样先确认。已在属性页时
  再执行命令面板的「编辑这篇的属性」是一次空转，不会清掉未保存标记。
- **冲突横幅里的强制保存也过面板校验**：行有重名 / 空键时「仍然存我这份」与主按钮一样禁用，
  不让一份明知有问题的补丁去覆盖邻居。
- 测试：Rust `meta_edit` 21 条（增删改 / 无改动零字节 / 未知键与注释保留 / 行内展开 /
  CRLF / 新建 front-matter / 坏 YAML 拒绝 / 改名撞复杂值被拒 / 新建也校验重复键 /
  非键值段拒绝写入）+ 服务层 1 条端到端冲突用例；前端 `src/ui/props.test.ts` 21 条（标签解析、
  类型推断、补丁只带改过的栏位、含逗号的标签不被重解析、复杂值不误写、复杂值键占位、接线守卫）。
  **真机未跑**：本档只做了测试与门禁验证。

## Windows 侧要点

- **WebView2 Runtime**：Win11 预装；Win10 由安装器带 bootstrapper。`tauri.conf.json` 里的合法值是 `downloadBootstrapper` / `embedBootstrapper` / `offlineInstaller` / `fixedRuntime`——**没有 `bootstrapper` 这个字面量**（写错会在 `tauri-build` 阶段失败，且报错不指明是哪个字段）。离线机器用 `offlineInstaller`。**这是 Windows 分发的头号踩坑点，M0 就在真机（含一台纯 Win10）上验**。
- **路径归属（重要，别搞混）**：
  - 用户内容与全部应用数据 → **一律在 Vault 内**，含 `index.db`、`config.toml`、日志（`.note/logs/`）。判 bug 时"把 Vault 里 `.note/logs` 发我"就够，不用去翻两个地方
  - 只有 WebView2 自身的浏览数据、系统崩溃转储由 OS 决定位置，我们不放业务数据
  - 结论：**不存在"业务配置写 APPDATA、内容写 Vault"的分裂状态**。复制 Vault 即带走全部内容资产与设置
- **Vault 默认路径**：`D:\Notes`，无 D 盘回落 `%USERPROFILE%\Notes`，首次启动必须让用户确认而不是静默创建
- **换机不是零成本**：API Key 存在 Windows 凭据管理器里，**不随 Vault 迁移**（这是刻意的安全取舍，不改成明文落盘）。迁移到新机器 = 复制 Vault + 重输一次 Key，这个事实要写在设置页与导出说明里，不要让用户以为拷完就全能用（**已写在设置页**：§设置页 的「库与关于」里「跟着库走 / 跟着本机」两行；导出说明还没写）
- **长路径与编码**：内部路径统一 UTF-8 正斜杠；落盘前对超长路径加 `\\?\` 前缀；中文文件名与空格作为一等测试用例；换行符跟随文件原有风格（CRLF/LF 不擅自统一）
- **单实例**：`tauri-plugin-single-instance`，二次启动 unminimize + set_focus 唤起已有窗口（不是开第二个库——SQLite 写锁只能有一个 owner）
- **dev 端口的两个坑**（本轮实际踩过）：① 1420 是 Tauri 社区惯例端口，但本机另一个项目正占着它 → 本项目固定 **1425** 且 `strictPort: true`，宁可起不来也不静默换端口（换了端口壳连不上，表现就是白屏）；② Vite 默认 host 是 `localhost`，在本机解析到 IPv6 `::1`，而 `devUrl` 写的是 `127.0.0.1` → 必须把 host 显式绑到 `127.0.0.1`，否则连不上
- **"上次打开哪个 Vault"的指针存在 Vault 之外**（`app_config_dir()/last-vault.txt`）：指针必须在 Vault 之前存在，否则鸡生蛋。它是元数据不是用户内容，不违反上面的路径归属
- **速记入口**：系统托盘 + 全局快捷键（默认 `Alt+Shift+N`，可改）弹无边框速记窗，内容落 `inbox/`；支持把文件/图片直接拖到速记窗
- **托盘菜单**（2026-11-02）：左键仍是唤起主窗口，右键才出菜单（`show_menu_on_left_click(false)`，与加菜单前的左键行为一致）。菜单项：打开知更 / 快速速记 / 打开设置 / 立即备份 / 打开库文件夹 / 隐藏窗口到托盘 / 退出知更。**两处跨层动作**：「打开设置」由壳发 `tray://open-settings`，界面接住后走同一个 `openSettings`（先落盘再切页）；「立即备份」在后台跑 `snapshot_vault(force=true)`，结果发 `tray://backup`；界面成功时只补读 `app_info`（不重跑整页 `refresh`，否则会冲掉设置页正在改的表单），成功走几秒后自清的 flash、失败走错误横幅（窗口收进托盘时两条都看不见，系统通知还没做）。备份被显式关掉与没配目录在快照层都是 `None`，提示统一说「备份未开启」并走中性 flash（这是配置状态，不是失败）。标题栏关闭仍是退出应用，菜单里的「隐藏窗口到托盘」才是显式隐藏
- **开机自启**：默认关，设置里可开（`tauri-plugin-autostart`）
- **备份（本地优先产品的头号数据风险）**：不做云同步，但**不能把备份完全推给用户**。默认开启"每日一次 Vault 增量快照到用户指定的第二个目录（另一块盘 / NAS 挂载点），保留最近 30 份"，首启向导里必须让用户选这个目录或显式选择"我不备份"。另提供"一键导出 Vault zip"，以及"把 Vault 直接指向 OneDrive/NAS 目录"的说明与注意事项（网络盘上的文件监听与 SQLite 锁行为需在 M1 验证）。判据：**唯一副本 = 没有副本**
  - **已实现**（2026-09-26，`note-core::snapshot`）。落盘格式与三条规矩见 [02] §快照备份落在盘上长什么样。触发点是"**当日首次启动后**"（与 §周期任务的口径一致，不是固定钟点）：壳在打开上次那个库之后，把 `Vault` 克隆出来丢给 `spawn_blocking`，**不排主锁**——握着主锁做整库遍历等于把刚拆掉的隐形预算从后门请回来。"立即备份"按钮同理（面板、托盘、每日三个入口都进 `spawn_blocking`）。
  - `manifest.jsonl` 是「读全量 → 追加 → 超限重写」的读改写，三个入口可能同时触发：快照层在进程内用一把锁串行化，`prune` 的清单重写走临时文件 + 改名，读方不会撞见半截清单。
  - 备份目录的配置存在 `<Vault>/.note/config.toml` 的 `[backup]` 段：它是**这个库的属性**（换机重开这个库时仍该知道备份在哪），符合 §路径归属"业务配置写 Vault"。
  - 目录与"不备份"这两个动作现在在**设置页 → 备份**里（侧栏那格「备份」只留"看历史、立即备份"，改设置要进设置页）；状态判据只有 `判备份` 一份，见 §设置页。
  - 还没做：一键导出 Vault zip（下面那半句），以及备份失败/完成时的系统通知（现在只有界面横幅与 flash；窗口收进托盘时用户看不见结果）。

## IPC 契约

Rust command 为唯一入口，类型由 `ts-rs` 生成到 `src/ipc/`，**禁止前端手写接口类型**（防漂移）。

| command | 说明 |
|---|---|
| `app_info` / `list_notes` / `read_note` / `search_keyword` | 只读窄接口，实现在 `note-core::service::Hub`；壳、CLI、MCP 走同一批函数 |
| `note_links` | 反链面板（2026-09-28 已实现）。一次返回两半：入链（谁链到我，带来源块的文字）与出链（我链到谁 + 悬空的，带原始写法）。视图文件不收，归档的收但带 `status`，隐私位**不过滤**（那条硬门管的是 AI 上下文，不是人看自己的库） |
| `vault_open` | 首次打开会建索引，之后启动不自动重建（否则冷启动被全量重建拖过 1.5s） |
| `note_read/note_write/note_create/note_move/note_trash/note_restore` | 写操作一律走原子写 + 索引增量重建 |
| `tree_order` / `tree_order_save` | 侧栏目录树的自定义顺序（2026-09-29）。读的是 `.note/tree.toml` 而不是索引，所以库里没索引也照样返回空表；保存交的是**整层的全序列**，同步落盘、不碰 SQLite、不触发任何重索引——这是它能压在 8ms 里的原因。落盘格式与八条口径只在 [02] §侧栏自定义顺序 定义 |
| `dir_list` / `dir_create` / `dir_rename` / `dir_delete` / `dir_empty`（2026-10-24，档 A） | 目录本身的操作，判据与边界只在 [02] D34。**只有 `dir_list` 是 async + `spawn_blocking`**：它要递归遍历整个 Vault，而同步预算 8ms 是给"索引查询"的，不是给磁盘遍历的——锁里只克隆出 `Vault` 句柄，遍历在锁外做（与备份/`ai_*` 同一副做法）。另外四条是同步的：它们只碰一个目录项，且**不触发任何重索引**（改名/删除只允许空目录），所以不进索引事件。**`dir_empty` 是菜单能不能给"改名 / 删除"的唯一判据**：一次 `read_dir(...).next()`，问的是盘上此刻有没有东西——此前用 `list_notes(300)` 返回的行反推，列表一截断，深层的空目录就会被误判成非空（或少判，两种都错）。它不拿索引说话，所以应用外刚建/刚清空的目录问它也立刻是准的。`note_create` 从这一档起多收一个 `parent: Option<String>`，不传就是默认 `notes/`；父目录必须存在且是笔记目录（`check_note_parent`），返回的 `rel` 由后端拼 |
| `capture_text` | 速记落盘：**同步等落盘（含 fsync，实测 p95 2.7ms）**，索引丢给后台线程，完成后发 `note://indexed`。返回即代表内容已落盘 |
| `hide_capture` | 速记窗隐藏（Esc）。窗口是复用的，不是每次新建 |
| `search_hybrid` | 关键词 + 链接（+ 语义，配了嵌入模型才开），返回带块 ID 与命中片段的列表（2026-10-10 实现前两路，2026-10-18 补上第三路，见 §混合检索那一档 与 §图扩展那一档）。**没配任何 Key 也照样有结果**——链接那一路是纯本地的，所以界面上那块不再被"AI 配没配"挡着。没有向量表时退回走本地两路并说明原因；配了模型但连不上则原样报错，不把失败说成"这一路没开"。返回里带 `reranked / rerankIn / rerankOut`——合并之后那一道**可选**工序（§重排那一档，默认关）生效没有、花了多少 token，都在这三个字段上 |
| `chat_ask` | **2026-10-19 起是流式的**（原 `ai_ask` 改名，返回形状一字未动，所以前端与审计都不用改判据）。一次一问，返回 `{ text, citations[], insufficient, retried, candidates, in/outTokens, ms, model }`，**引用完整性仍在返回前判完**（越界 → 重生成一次 → 再越界就不采信）——流式只改变"字什么时候到屏幕上"，不改变"什么才算答案"。事件：`ai://token`（一截答案）、`ai://think`（一截思考，只当进度用）、`ai://reset`（**把已经播出去的字清掉**，因为第一次违规了不会被采信）。每条负载都带界面生成的 `runId`，对不上就丢——连问两句时前一句的尾巴不能贴到后一句下面。跟 `search_hybrid` 一样从派生连接 `fork()` 出专用连接干活（最多两次网络往返，绝不握着锁打） |
| `ai_runs` | 审计页数据源（2026-10-10 已实现）：读 `ai_runs` 最近若干条，**失败与未采纳的那几次也在**。「最近的生成」那块直接读它 |
| `suggestions_list/accept/reject/undo` | accept 才落盘，返回 md diff；undo 依赖 `note_versions`——**那块地基已经在了**（M3 档 0，`note_versions` 换成 path 钥匙且去掉级联外键，真有前像落进去，见 §版本快照那一档）。命令本身还没接 |
| `jobs_list/run_now/enable` | 主动层任务的查看与手动触发 |
| `ai_view / ai_save_config / ai_save_key / ai_test` | AI 档 0（2026-10-10 已实现，见 §接入模型那一档）。四条都是 async + `spawn_blocking`，**锁里只拿 `Vault` 句柄**；三条返回的都是 `AiView`，**结构里没有 Key 字段**。`ai_save_config` 从 2026-10-18 起多收一个 `rerank: bool`（重排那一格的初值与去向都只经这一条命令） |
| `ai_stats` | token 与花费曲线（读 `ai_runs`） |
| `backup_set/run/recent/history/restore` | 快照备份（2026-09-26 已实现）。全部走 §后端调用纪律 的第二条连接与 `spawn_blocking`，`run` 不排主锁；配置落 `<Vault>/.note/config.toml` 的 `[backup]` 段 |
| `import_preview/apply` | 外部 Markdown 导入（2026-09-26 已实现）。`preview` 只出计划不碰盘，`apply` 才写；整段跑在第二条连接上，做完发一次 `note://indexed`（负载是导入进去的全部路径） |
| （事件）`note://indexed` | 负载是**这次动过的那几篇路径**（`string[]`）——**不是"链接图变了的所有篇"**：改名 / 归档时入链方不在名单里。订阅方要么自己兜底重取（反链面板就是这么做的，见 §反链面板），要么就别依赖它做完整性判断。要报全就得在两条整片 UPDATE 旁边再 SELECT 一次受影响路径，等于把同一段 WHERE 写两遍——已知取舍，写在这儿免得下一个人踩。正在看的那一篇如果被外部改了，据此判断要不要重装载——见 §文件监听 第 3 条 |

**实现现状（M0）**：`Hub` 内含 rusqlite 连接因而不是 `Sync`，壳里暂时用 `Mutex<Option<Hub>>` 粗粒度串行化。接口形状已按最终形态定死（同步命令都是纯索引查询），M1 换成单写者队列 + 只读连接池时不需要改调用点。

**约定**：所有写操作返回统一 `WriteResult { ok, diff, conflicts }`，让 UI 能一致地展示改动与冲突。耗时按三档处理，不留中间地带：

| 预估耗时 | 做法 |
|---|---|
| **≤ 8ms** | 允许同步 command 直接返回结果。这是硬上限（G6） |
| **8ms – 300ms** | **一律异步 + 乐观 UI**：立即返回"已受理"，前端先按预期渲染，结果到了再校正。这一档禁止转圈 loading——用户不该为一次搜索或一次保存看到进度条 |
| **> 300ms** | 异步 + 事件流推进度（`note://index-progress`、`ai://token`），且必须可取消 |

任何 command 落到第二、三档却不按对应方式实现，视为接口设计错误，用"前端加个 loading"糊过去是不允许的。

## 测试策略

| 层 | 手段 | 门槛 |
|---|---|---|
| **G5 无损往返** | `testdata/roundtrip/` golden 文件对（md ↔ 块树 JSON）+ 随机 md 语料 property test（中文、嵌套列表、表格、代码块、超长行、CRLF、`---` 歧义） | **每次提交必跑，字节级相等** |
| 重建一致性 | 同一 Vault：增量索引结果 == 全量重建结果，逐表 diff | 必跑 |
| 派生表无孤儿 | 删除/重解析笔记后全库检索，命中已删内容数必须为 0 | 必跑 |
| 检索质量 | 50 条真实问答 golden set，`recall@8` / `MRR`（见 [04] §8） | 改 prompt 或换模型必跑 |
| 崩溃安全 | 写入过程中强杀进程，重启后 Vault 无半截文件 | M0 验收 |
| **性能门禁** | `perf-budget.json` 写死 §性能预算 的全部数字（键齐不齐由 `scripts/guard.mjs` 查）；`node scripts/check.mjs --bench` 跑 `note ipc-bench` / `note write-bench`，同步路径 p95 超线即**非零退出**；`note bench` 跑导入吞吐、检索 P50/P95、往返转换吞吐并与上次快照对比 | **超阈值即红，不允许"先记下以后改"**。目前没有 CI（没远端），所以这条由 `scripts/check.mjs` 承担，见 §性能预算 末 |
| 端到端 | **单一栈**：`tauri-driver` + WebdriverIO 跑 5 条主路径；同一套 driver 开 WebView2 的远程调试端口，用 CDP 采 INP 与长任务 | M1 起 |

端到端只保留一套驱动。曾经并列写过 Playwright，但 Playwright 驱动 WebView2 与 `tauri-driver` 是两条互不兼容的路线，同时维护等于把 e2e 成本翻倍——性能指标改用同一栈的 CDP 采集即可拿到。

性能基准每周自动跑一次并留曲线；发布前必做一次**体验基线压力库**（5000 篇真实长文 / 约 20 万块，外加一篇 3000 块极端样本）的人工体感检查（指标全绿但手感发涩，仍算不通过）。

**浏览器侧测量的前置断言**：任何输入延迟/掉帧测量在开测前必须检查 `document.visibilityState === 'visible'`，不满足就报错退出而不是静默出数。Spike C 的教训：自动化浏览器里页面常处于 hidden，rAF 饥饿会让"输入到可见"测出 43s 的假尖峰（详见 `probes/spike-c/README.md`）。测到窗口调度而以为是代码慢，是这类基准最坏的结果。

**"release 构建"只认 `pnpm tauri build`**（2026-09-29 复测当天踩的）。直接 `cargo build --release -p zhigeng` 出来的 exe **运行时去加载 `devUrl`**：起来后页面是 `127.0.0.1:1425 拒绝连接`（vite 没开时）或者干脆是 dev 服务那份未压缩前端（vite 开着时）——两种情况都不是发布件，量到的数字全部无意义；体积也比 CLI 产物小 216KB（10,395,136 vs 10,611,200），是唯一能从外部看出来的线索。机制在 `tauri-build::is_dev()`：它读 `DEP_TAURI_DEV`，而这个变量由 **CLI** 设置，`cargo` 单独跑时没人设它、构建期就按 dev 分支生成了。连带两条纪律：① 量之前先 `Runtime.evaluate` 读一次 `location.href`，是 `tauri://localhost`（Windows 上是 `http://tauri.localhost/`）才算数；② release 里没有 `window.__editor`（那是 `import.meta.env.DEV` 才挂的探针钩子），测量只能走 DOM + 可信输入 + `PerformanceObserver('event')`——反而更接近用户真实路径。

## 性能预算（超出即视为 bug）

先统一规模口径，否则"2 万篇"和"5000 篇"会在不同文档里被当成同一个目标反复引用：

| 名称 | 定义 | 用来做什么 |
|---|---|---|
| **体验基线** | **5000 篇真实长文 ≈ 20 万块**（自用一年量级） | 日常开发、e2e、每周性能跑都用这档；这是"必须绝对不卡"的规模 |
| **设计上限** | **2 万篇 ≈ 40 万块** | 架构与索引预算按这档算，允许单项指标退化但不得数量级劣化 |
| **极端样本** | 单篇 3000 块 | 专门验分节渲染，任何一版都要测 |

下文所有 `@ N 篇` 的阈值默认指**体验基线**，标 `@ 设计上限` 的除外。

| 指标 | 目标 |
|---|---|
| 冷启动到可编辑 | < 1.5s |
| 速记窗唤起 | < 100ms |
| **同步 IPC 调用** | **< 8ms**（超出必须改异步 + 事件） |
| **打字到屏幕** | **< 16ms**（120Hz 下不掉帧；60Hz 机器 < 33ms） |
| **INP（交互到下一帧绘制）** | **P95 < 50ms**，长任务（> 50ms）每屏 0 个 |
| 切换到另一篇笔记 | < 80ms 可见内容 |
| 命令面板呼出 | < 50ms |
| 保存（含索引增量，不含网络） | < 150ms |
