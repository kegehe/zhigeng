# 06 · 界面样式规范

> 把 [03] §界面质感 变成可执行条款。**样式的核心不是"好看的设计稿"，而是一致性可以被机器检查**——
> 硬编码色值、随手写 `14px`、动效碰 `width`，这三类是界面劣化的根因，本文件的禁止清单由 `scripts/guard.mjs` 逐条盯着（它是 `node scripts/check.mjs` 的一步）。

## 1. 落地方式

| 项 | 选择 | 理由 |
|---|---|---|
| 样式语言 | Tailwind v4（CSS-first，`@theme` 里定义 token）+ 少量原生 CSS | 构建快；token 直接用 CSS 自定义属性，运行时可换主题 |
| 组件基元 | Radix UI（无样式）+ 自绘外观 | 键盘导航、焦点管理、ARIA 由 Radix 保证；外观不受库限制 |
| 主题切换 | `:root` 亮色 / `[data-theme="dark"]` 暗色，跟随系统 + 手动覆盖 | 单一套 token 名，两套值，组件零改动 |
| 图标 | Lucide，按需 import（tree-shake） | 线性风格统一，尺寸随字阶 |
| 字体 | Inter（拉丁）+ 思源黑体 SC（中文）+ JetBrains Mono（代码），woff2 子集化本地打包 | **绝不联网取字体**：本地优先产品启动时不该有外部请求，也避免离线时字体闪烁 |

文件布局：

```
src/ui/
  tokens.css        # 唯一允许出现字面量颜色与尺寸的地方
  base.css          # reset、排版、滚动条、焦点环、选中文本
  components.css    # 少量无法用工具类表达的组件（标题栏、Callout、代码块）
src/ui/primitives/  # Button / Input / Menu / Dialog / Tooltip / Toast（Radix 之上）
```

## 2. Token 定义

### 色：明度阶梯 + 语义两层

**不允许**在组件里写 `bg-blue-500` 这类"物理色"，只允许用语义色。改主题=改语义映射，不用改组件。

| 语义 token | 用途 | 亮色 | 暗色 |
|---|---|---|---|
| `--bg-base` | 应用底 | `oklch(98.5% 0.002 260)` | `oklch(17% 0.006 260)` |
| `--bg-raised` | 卡片/弹层 | `oklch(100% 0 0)` | `oklch(21% 0.007 260)` |
| `--bg-sunken` | 代码块/引用底 | `oklch(96% 0.004 260)` | `oklch(14% 0.006 260)` |
| `--bg-hover` / `--bg-active` | 交互反馈底 | base 上压暗 1.5% / 3% | 同上提亮 |
| `--text-primary` | 正文 | `oklch(24% 0.012 260)` | `oklch(93% 0.004 260)` |
| `--text-secondary` | 次要 | `oklch(50% 0.014 260)` | `oklch(66% 0.012 260)` |
| `--text-disabled` | 禁用 | 次要再降一档 | 同 |
| `--accent` | 主操作/链接/当前项 | `oklch(58% 0.16 265)` | `oklch(70% 0.14 265)` |
| `--accent-hover` | 主操作悬停 | accent 提亮 6% | 同 |
| `--success` `--warning` `--danger` | 状态色 | 绿/琥珀/红，同一明度层 | 同一套色相，明度降 8% |
| `--border-subtle` / `--border-strong` | 分隔 | base 上压 4% / 10% | 提 6% / 12% |
| `--focus-ring` | 焦点环 | accent，2px offset | 同 |

三条硬规定：

1. **暗色不用纯黑、亮色不用纯白**（纯黑背景上的白字会因辉光效应产生残影）
2. 正文与背景**必须过 WCAG AA**：正文 ≥ 4.5:1，大字/图标 ≥ 3:1。`--text-disabled` 是唯一豁免位，且不得用于正文
3. 强调色**不得作为唯一信息载体**（色盲场景）：错误态除红色还要有图标或文案

### 字阶与排版

| token | 值 | 用途 |
|---|---|---|
| `--text-xs` | 12px / 1.5 | 时间戳、徽标 |
| `--text-sm` | 13px / 1.6 | UI 控件、侧栏 |
| `--text-base` | 15.5px / **1.75** | 笔记正文 |
| `--text-lg` | 18px / 1.6 | 三级标题 |
| `--text-xl` | 22px / 1.4 | 二级标题 |
| `--text-2xl` | 28px / 1.3 | 一级标题 |
| `--text-mono` | 13.5px / 1.7 | 代码块 |

正文排版细则（笔记产品的观感七成在这里）：

- **行长 65–75 字符**：`--measure: 46rem`，正文容器 `max-inline-size` 用它并居中；窄窗时留边距优先于拉伸
- 段间距 `1.15em`；列表项间距 `0.35em`；标题上间距 `1.8em`、下 `0.6em`（视觉上的"呼吸"来自不对称间距，不是均匀间距）
- 中英文之间由 CSS 自动留白（`text-spacing` 尚在提案，先用 `word-spacing` 微调 + 渲染时插入半角空格），中文标点悬挂（`hanging-punctuation`）
- 代码块不参与行长约束，超宽横向滚动，**不换行折行**

### 间距 / 圆角 / 阴影 / 层级

- 间距只用 4px 栅格：`--space-1..12` = 4/8/12/16/20/24/32/40/48/56/64。**出现 `13px`、`15px` 即为缺陷**
- 圆角：控件 `--radius-sm 6px`、卡片 `--radius-md 10px`、弹层 `--radius-lg 14px`、胶囊 `--radius-full`
- 阴影三档且**必须与边框组合使用**（暗色下阴影几乎不可见，只靠阴影会失去层次）：`--shadow-1` 浮起小件、`--shadow-2` 下拉/气泡、`--shadow-3` 模态
- 层级：`--z-base 0` / `sticky 100` / `overlay 500` / `popover 600` / `toast 700` / `modal 800`。**禁止组件里写裸 `z-50`**

### 动效

| token | 值 | 用途 |
|---|---|---|
| `--dur-1` | 120ms | 悬停、按压 |
| `--dur-2` | 180ms | 展开、淡入 |
| `--dur-3` | 240ms | 面板进出 |
| `--ease-out` | `cubic-bezier(0.22, 1, 0.36, 1)` | 进入 |
| `--ease-in` | `cubic-bezier(0.4, 0, 1, 1)` | 离开 |

- **只动 `transform` 与 `opacity`**。动 `width/height/top/left/margin/padding` 会触发布局，直接违反 G6
- 高度未知的展开用 `grid-template-rows: 0fr → 1fr`，而不是动画 `height`
- 一律包在 `@media (prefers-reduced-motion: reduce) { 动画时长归零 }` 里
- 流式回答的文本按帧合并渲染（16ms），**不做逐字打字机动画**：那是 G5 之外的第二类"看起来在掉帧"

## 3. 组件基线

| 组件 | 必须做到 |
|---|---|
| Button | 4 种变体（primary / secondary / ghost / danger）× 3 尺寸；禁用态降透明度而非降对比；`:active` 有 `translateY(1px)` |
| Input / Editor | 焦点用 `--focus-ring`（2px offset，**不得用 `outline: none` 一去了之**）；错误态同时给文案 |
| Menu / Command Palette | 全键盘可达、↑↓/Enter/Esc、分组用分隔线而非空白、当前项左侧 2px accent 条 |
| Dialog / Toast | 焦点陷阱、Esc 关闭、Toast 可手动关闭且默认 6s |
| 列表 / 目录树 | 虚拟滚动（`@tanstack/react-virtual`），行高固定，缩进 16px 一级 |
| Callout / 提示块 | 六类语义色 + 图标；暗色下用半透明底（同色相 12% alpha），不是硬编码灰 |
| 空态 | 文案 + 一个主操作按钮，不插画满屏；空态是最容易被遗忘的界面 |
| 骨架屏 | 与真实内容同尺寸同间距（骨架抖动=布局错误的信号） |
| 标题栏 | 自绘（`decorations:false` + `data-tauri-drag-region`），Mica/Acrylic 底，按钮 46×32 命中区 |

## 4. 禁止清单（护栏可查，逐条都有理由）

| 禁止 | 为什么 |
|---|---|
| 组件内出现 `#hex` / `rgb()` / `oklch()` 字面量 | 绕过语义色 → 暗色必然不一致。只允许 `tokens.css` 内有字面量 |
| `px` 字面量不在 `tokens.css` | 间距漂移，界面"看着乱但说不出哪不对"的根因 |
| `outline: none` 且无替代焦点样式 | 键盘用户失去定位，且 a11y 直接不合格 |
| `transition: all` | 会连带过渡布局属性 → 掉帧（违反 G6）；必须显式列属性 |
| 动画 `width/height/top/left/margin` | 同上，触发布局 |
| 裸 `z-index` 数字 | 层级失控，弹层被覆盖这类 bug 查一下午 |
| 联网取字体/图标/脚本 | 本地优先产品启动不该有外部请求；离线必须零退化 |
| 用远程图片/字体做首屏 | 同上，且违反"数据不出本机"的定位 |
| `!important` | 除了 `prefers-reduced-motion` 的归零规则，一律不允许 |

检查方式：已落地为 `scripts/guard.mjs` 的一部分（原计划单独做 `note style-lint`，没必要——同一套护栏还要管依赖方向与预算键，合并只有一份维护成本）。它扫 `src/**` 的 `.ts/.tsx/.css`，命中禁止清单即 exit 1。

两个实现细节，不写下来一定被反复误报：

1. **先剥注释再做匹配**。否则本文件里"绝不用 outline:none"这类说明性注释会被规则自己抓住（第一轮就是这样）。
2. 允许清单只有 `src/ui/tokens.css`（token 定义处）与 `probes/**`（一次性验证代码）。**新增例外必须写注释说明为什么**。

`outline-none`（Tailwind 写法）与 `outline: none` 同等禁止——第一轮就在搜索框上顺手写了 `outline-none`，被这条抓出来后改成依赖全局 `:focus-visible` 环。这也是把规则做成脚本而不是文档条款的理由：人写 class 时不会想起条款。

## 5. 主题值一览（实现时的唯一来源）

`tokens.css` 的 `@theme` 块是本仓库**唯一**允许出现颜色字面量的地方；任何组件引用它。
新增 token 的流程：先在此文件列出语义与用途 → 亮/暗两套值 → 过 AA 对比度校验 → 再写组件。
反过来（先写组件再补 token）会破坏一致性，视为缺陷。

## 6. 与设计稿的关系

没有独立设计稿。**样式规范即设计源**：组件按 token 实现后，观感由 token 值统一调，
不逐个组件微调像素。这样"改一处全局生效"，也让一个人能维持界面一致性。
若要整体换风格（如更紧凑的字号、不同 accent 色），只改 `tokens.css`。
