# 06 · 界面样式规范

> 把 [03] §界面质感 变成可执行条款。**样式的核心不是"好看的设计稿"，而是一致性可以被机器检查**——
> 硬编码色值、随手写 `14px`、动效碰 `width`，这三类是界面劣化的根因，本文件的禁止清单由 `scripts/guard.mjs` 逐条盯着（它是 `node scripts/check.mjs` 的一步）。

## 1. 落地方式

| 项 | 选择 | 理由 |
|---|---|---|
| 样式语言 | Tailwind v4（CSS-first，`@theme` 里定义 token）+ 少量原生 CSS | 构建快；token 直接用 CSS 自定义属性，运行时可换主题 |
| 组件基元 | Radix UI（无样式）+ 自绘外观 | 键盘导航、焦点管理、ARIA 由 Radix 保证；外观不受库限制。**未落地**：依赖还没进 `package.json`，命令面板的 ↑↓/Enter/Esc 与焦点归位目前是 `CommandPalette.tsx` 手写的那一份 |
| 主题切换 | `:root` 亮色 / `[data-theme="dark"]` 暗色，跟随系统 + 手动覆盖 | 单一套 token 名，两套值，组件零改动 |
| 图标 | Lucide，按需 import（tree-shake） | 线性风格统一，尺寸随字阶。2026-10-11 起标题栏、侧栏新建键、目录树箭头也走同一套（以前那几处还是 `─ ▢ ✕ ＋ ▸` 字符，与编辑器工具栏的 Lucide 混在同一个屏里） |
| 字体 | Inter（拉丁）+ 思源黑体 SC（中文）+ JetBrains Mono（代码），woff2 子集化本地打包 | **绝不联网取字体**：本地优先产品启动时不该有外部请求，也避免离线时字体闪烁。**未落地**：仓库里没有 `@font-face`，也没有任何字体文件。实测本机 `JetBrains Mono` 与 `Noto Sans SC` 都没命中——等宽落到 Cascadia Code（同一串代码比 JetBrains 宽 **32%**），中文落到系统默认。也就是说 `--text-mono: 13.5px` 那套度量目前是按一台没在用的字体定的，换机器就换字形宽度。补齐之前，字阶表里的"每行多少字"只能算估算 |

文件布局（与仓库现状一致；`components.css` 与 `primitives/` 是计划中的拆分点，现在这两块内容分别住在
`base.css` 的 `@layer components` 与 `App.tsx` 顶部那两个 `btn` / `btnPrimary` 常量里）：

```
src/ui/
  tokens.css        # 唯一允许出现字面量颜色与尺寸的地方
  base.css          # reset、排版、滚动条、焦点环、选中文本 + @layer components
src/ui/primitives/  # （计划）Button / Input / Menu / Dialog / Tooltip / Toast
```

## 2. Token 定义

### 色：明度阶梯 + 语义两层

**不允许**在组件里写 `bg-blue-500` 这类"物理色"，只允许用语义色。改主题=改语义映射，不用改组件。

> **2026-10-27 换版「星穹 Aurora」**：整套面/文/强调从灰蓝（hue 260）迁到蓝紫极光家族
> （hue 259–290），亮面是"雾蓝纸 + 白卡 + 极光蓝"，暗面是"深紫黑 + 玻璃卡 + 极光冷蓝"。
> 新增 `--aurora-cool` / `--aurora-warm` 两枚底纹 token（静态径向渐变，`.app-bg` 取用，
> 主窗口根节点挂载）。全部色值换算过 WCAG（数值标注在 tokens.css 注释里），`--code-*`
> 八枚着色不在本次换版范围（它们是按旧 sunken 底调过的语法色，新底对比只增不减）。

| 语义 token | 用途 | 亮色 | 暗色 |
|---|---|---|---|
| `--bg-base` | 应用底 | `oklch(97.3% 0.007 269)` | `oklch(18.8% 0.020 289)` |
| `--bg-raised` | 卡片/侧栏/弹层 | `oklch(99.5% 0.003 269)` | `oklch(24.9% 0.023 285)` |
| `--bg-sunken` | 代码块/引用底/骨架之外的沉底 | `oklch(92.4% 0.020 264)` | `oklch(15% 0.017 290)` |
| `--bg-hover` / `--bg-active` | 交互反馈底 | `oklch(92.2% / 88.3%)` | `oklch(30.1% / 34.2%)` |
| `--aurora-cool` / `--aurora-warm` | 极光底纹（仅 `.app-bg`） | accent 压 **6%** / 琥珀压 **5%** | accent 压 **10%** / 琥珀压 **6%** |
| `--text-primary` | 正文 | `oklch(24.9% 0.030 267)` | `oklch(96% 0.008 286)` |
| `--text-secondary` | 次要 | `oklch(46.5% 0.039 261)` | `oklch(73.8% 0.027 279)` |
| `--text-disabled` | 禁用与占位 | `oklch(65% 0.025 258)` | `oklch(54.7% 0.033 279)` |
| `--accent` | 主操作/链接/当前项 | `oklch(56.3% 0.161 259)` | `oklch(78.3% 0.110 260)` |
| `--accent-hover` | 主操作悬停 | `oklch(65.4% 0.137 259)` | `oklch(84% 0.080 257)` |
| `--accent-soft` | 选中底（当前行 / 框住的格子 / `::selection`） | accent 压 **18%** alpha | accent 压 **18%** alpha |
| `--accent-faint` | **整块**选中的底（代码卡 / 引用 / 表格那一整块） | accent 压 **12%** | accent 压 **16%** |
| `--md-mark` | 正文高亮（`==文字==`）。**用户自己挑的文字色/底色不走 token**——它们是真色值写进文件（[02] D35） | 暖黄压 **32%** | 同一色相压 **26%** |
| `--success` `--warning` `--danger` | 状态色 | 绿/琥珀/红，同一明度层 | 同一套色相，明度提一档 |
| `--border-subtle` / `--border-strong` | 分隔 | `oklch(91.8% / 83.3%)` | `oklch(30.6% / 38.5%)` |
| `--focus-ring` | 焦点环 | accent，2px offset | 同 |

四条硬规定：

1. **暗色不用纯黑、亮色不用纯白**（纯黑背景上的白字会因辉光效应产生残影）。这条以前被自己违反过：
   本表曾把 `--bg-raised` 的亮色写成 `oklch(100% 0 0)`，而实现是 99.6%——**以实现为准**，纯白那一档不要回来。
2. 正文与背景**必须过 WCAG AA**：正文 ≥ 4.5:1，大字/图标 ≥ 3:1。`--text-disabled` 是唯一豁免位，且不得用于正文
   ——**也不得用在真内容上**。侧栏的时间戳、文件路径、快照 id、模型名、token 数这些是内容，一律 `--text-secondary`；
   只有 placeholder、"还没有快照"这类提示语才留在豁免位。这条界线在 2026-10-11 之前是糊的（那批元数据全在 disabled 上，实测 3.2:1）。
3. 强调色**不得作为唯一信息载体**（色盲场景）：错误态除红色还要有图标或文案。
4. **交互状态必须量得出差别**。底色型状态（hover / active / 选中）与它压着的底之间至少 **1.15:1**，
   选中那一档（`--accent-soft`）至少 **1.25:1**。定值时别用眼睛判——近黑处 WCAG 的 `+0.05` 会吃掉一切，
   "往下挖"在暗面基本无效（`--bg-sunken` 从 14% 挖到 11.5% 只换来 1.04→1.07）。
   暗面要"看得见的标记"一律往上提（骨架屏用 `--bg-active`，1.58:1）。
   现行 Aurora 值的实测：亮 hover/raised **1.24**、hover/base **1.17**、active/raised **1.40**、soft **1.26**；
   暗 hover/raised **1.18**、active/raised **1.37**、soft **1.47**（2026-10-27 逐对算过，脚本口径同 WCAG）。
5. **"是一块卡片"必须看得出来**。凡拿 `--bg-sunken` 铺底的块（行内码、代码卡、图片卡、资产牌）
   都带一条 `--border-subtle`：暗面 sunken 压在页面底上只有 **1.06:1**，底色承担不了"边界"这件事。
   这条道理以前只写在行内码那一条的注释里，代码卡漏了——2026-10-12 暗面复查照出来
6. **选中态要比未选中态重一档，但主信号是边、不是底**。整块选中用 `--accent-faint` 淡染一档
   （暗面与未选中的 sunken 差 1.31:1，亮面只有 1.15:1——亮面那条底本来就不承载信息），
   把边换成 accent 才是两个主题都成立的那一格（暗 9.9:1 / 亮 3.7:1，均以 sunken 为底实测），再叠一圈 `inset` 描边
   照顾没有边框的变体。底色压重了的坏味道是"这块在发光"而不是"这块被选了"。
   但**不许改几何**：边框从 1px 加粗到 2px 会把块里的内容顶偏一两个像素，
   与图片卡那条同一判据（"选一下画面抖一下"）

### 字阶与排版

| token | 值 | 用途 |
|---|---|---|
| `--text-xs` | 12px / 1.5 | 时间戳、徽标 |
| `--text-sm` | 13px / 1.6 | UI 控件、侧栏 |
| `--text-base` | 15.5px / **1.75** | 笔记正文 |
| `--text-lg` | 18px / 1.6 | 三级标题 |
| `--text-xl` | 22px / 1.4 | 二级标题 |
| `--text-2xl` | 28px / 1.3 | 一级标题 |
| `--text-mono` | 13.5px / 跟着所在段落；整块代码另有 `--leading-code` = 1.7 | 代码块 |

**这张表是成对的：字号与行高一起才算一档。** `@theme inline` 里必须同时登记
`--text-*` 与 `--text-*--line-height`——只登记字号时 Tailwind 会把自己那套默认行高漏进来，
实测 `text-xs` 落在 12px/16px（1.33）、`text-sm` 13px/18.57px（1.43）、`text-mono` 干脆没有行高，
与本表的 1.5 / 1.6 / 1.7 全对不上，而中文界面的松紧恰恰由这一层决定（2026-10-11 修）。

另一条命名坑：`text-<名>` 这个槽位由**字号与颜色两个命名空间抢，而颜色赢**。以前登记了
`--color-base`（为了 `bg-base`），于是 `text-base` 生成的是 `color: var(--bg-base)`——把字刷成页面底色，
字号一个像素都不给。现在那一族叫 `bg-page`，`text-base` 回到本来的意思。

正文排版细则（笔记产品的观感七成在这里）：

- **行长 65–75 字符**：`--measure: min(72rem, 100%)`，正文容器 `max-inline-size` 用它并居中；窄窗时留边距优先于拉伸。
  这条 2026-09-26 改过一次，因为**原来的值和它自己写的规则对不上**：`46rem` 是照拉丁文的 `ch` 定的，而本产品正文以中文为主——15.5px 的字、减去页边后一行只排得下**约 44 字**，比规范要求的 65–75 还窄，用户在 1680 宽的窗口里看到的就是「59% 是空白」。改成 72rem（1152px）后一行约 **74 字**，正好落回这条规则本来的区间；`min(…, 100%)` 让窄窗自然收缩。**不做「全宽开关」**：一个默认值就该对中文成立，多一个开关只是把没算对的数留在原地。
- **面板那一支另有一档**：`--measure-ui: min(56rem, 100%)`。导入 / 备份 / AI / 问答 / 回收站这五支的字是 13px，
  照 `--measure` 排是 88 字一行——同一条"65–75 字"换成那个字号，上限就得是 896px（约 69 字）。
  以前这五支根本没有行长约束，1680 宽的窗口上一段说明文字铺满 1392px。
- 段间距 `1.15em`；列表项间距 `0.35em`；标题上间距 `1.8em`、下 `0.6em`（视觉上的"呼吸"来自不对称间距，不是均匀间距）
- 中英文之间由 CSS 自动留白（`text-spacing` 尚在提案，先用 `word-spacing` 微调 + 渲染时插入半角空格），中文标点悬挂（`hanging-punctuation`）
- 代码块不参与行长约束，超宽横向滚动，**不换行折行**

### 间距 / 圆角 / 阴影 / 层级

- 间距只用 4px 栅格：`--space-1..12` = 4/8/12/16/20/24/32/40/48。**出现 `13px`、`15px` 即为缺陷**，
  Tailwind 那套 `p-1.5` / `px-2.5` / `mt-0.5` 半格步进（2/6/10/14px）**同样是缺陷**——它们比 13px 更常见，
  因为看起来"像 token"。2026-10-11 那轮清了 31 处，护栏现在直接按类名抓（见 §4）
- 圆角：控件 `--radius-sm 6px`、卡片 `--radius-md 10px`、弹层 `--radius-lg 14px`、胶囊 `--radius-full`
- 阴影三档且**必须与边框组合使用**（暗色下阴影几乎不可见，只靠阴影会失去层次）：`--shadow-1` 浮起小件、`--shadow-2` 下拉/气泡、`--shadow-3` 模态
- 层级：`--z-base 0` / `marker 1`（贴在行上的落位线）/ `sticky 100` / `overlay 500` / `popover 600` / `toast 700` / `modal 800`。
  **禁止组件里写裸 `z-50`，也禁止 CSS 里写裸 `z-index: 1`**——后者以前抓不到，因为护栏只匹配 Tailwind 那种 `z-[数字]` 写法

### 动效

| token | 值 | 用途 |
|---|---|---|
| `--dur-1` | 120ms | 悬停、按压 |
| `--dur-2` | 180ms | 展开、淡入 |
| `--dur-3` | 240ms | 面板进出 |
| `--ease-out` | `cubic-bezier(0.22, 1, 0.36, 1)` | 进入 |
| `--ease-in` | `cubic-bezier(0.4, 0, 1, 1)` | 离开 |

- **只动 `transform` 与 `opacity`**。动 `width/height/top/left/margin/padding` 会触发布局，直接违反 G6
- **时长与缓动只准引 token**：`var(--dur-1..3)` / `var(--ease-*)`。组件里写死 `160ms` 这种"看着差不多"的值，
  等于把动效表变成装饰品（命令面板那个入场以前就是 160ms）
- 底色/文字色的 `transition-colors` 是这条规则的**明确例外**：它不动布局，只是补上"点到了没有"的反馈。
  写下来是因为照字面读"只动 transform 与 opacity"会得出"hover 不许淡入"的结论，而那不是本意
- 高度未知的展开用 `grid-template-rows: 0fr → 1fr`，而不是动画 `height`
- 一律包在 `@media (prefers-reduced-motion: reduce) { 动画时长归零 }` 里
- 流式回答的文本按帧合并渲染（16ms），**不做逐字打字机动画**：那是 G5 之外的第二类"看起来在掉帧"

## 3. 组件基线

| 组件 | 必须做到 |
|---|---|
| Button | 4 种变体（primary / secondary / ghost / danger）× 3 尺寸；禁用态降透明度而非降对比；`:active` 有 `translateY(1px)`。**后两条 2026-10-11 落地**（`disabled:opacity-55` + `active:translate-y-px`；以前写的是 `disabled:bg-active disabled:text-fg-disabled`，实测 2.88:1，是"降对比"的反面教材）。**前一条没落地**：变体目前是 `App.tsx` 与 `FirstRun.tsx` 里各一份的 `btn` / `btnPrimary` 字符串常量，没有尺寸档位，也没有 ghost |
| Input / Editor | 控件焦点用 `--focus-ring`（2px offset）。**正文编辑器例外**：整篇描边在 Chrome 里躲不开（可编辑的 `contenteditable` 连鼠标聚焦都判 `:focus-visible`），所以焦点指示改成**当前块**左侧一条竖线——见 §4 那条精确化 | 错误态同时给文案 |
| Menu / Command Palette | 全键盘可达、↑↓/Enter/Esc、分组用分隔线而非空白、当前项左侧 2px accent 条。**accent 条 2026-10-11 落地**：透明边框先占位，选中才换颜色，切换时文字不左右跳；输入框那条 outline 环在 `overflow-hidden` 的面板里会被圆角裁掉，所以换成底边一条 accent（同一选择器上给替代指示，见 §4） |
| Dialog / Toast | 焦点陷阱、Esc 关闭、Toast 可手动关闭且默认 6s |
| 列表 / 目录树 | 缩进 16px 一级（`--space-4`，不写死像素）；行高固定。**虚拟滚动还没做**：侧栏一次最多渲染 300 篇（`list_notes` 的上限），这个量级下 DOM 不是瓶颈；真要上就按 `@tanstack/react-virtual` + key 用 `rel` 而不是 index。**可以整行拖拽**自定义同级顺序、也可以把笔记拖进目录（= 真移动文件，档 2）：顺序存 `.note/tree.toml`（[02] §侧栏自定义顺序），拖拽判据在 `src/ui/dragdrop.ts`（纯函数，没有 DOM 也测得到）。用 pointer 事件而不是 HTML5 拖放，理由同编辑器块手柄——`dragstart` 那套真机验证触发不了。**右键菜单（2026-10-30）**：目录行、笔记行与树的空白处各自右键出菜单，行尾那枚「…」与右键是**同一副**菜单（一个 `树菜单` 状态、一处坐标、一处关闭），因此菜单内容与视口夹取是纯函数 `src/ui/tree-menu.ts`；菜单用 `position: fixed` 挂在侧栏滚动层外面，否则贴近底部的行弹出来会被裁掉。语义顶层（`notes`/`inbox`/`archive`）只给"建"；改名 / 删除只给**物理空**的非语义目录，删除项用危险色并在菜单里再确认一次 |
| 表格多格选区 | 拖过几格或 Shift 点两下框出矩形。**框到的格 = 批量动作的作用域**，所以框必须所见即所得：底色 `--accent-soft` + inset 描边（只给底色在暗色下分不出边界）。两条硬规矩：① 选区**只发 meta 事务**，不发文档事务——否则"拖一下鼠标"就把笔记标成待保存，800ms 后白写一次盘；② 框选期间关掉正文的 `user-select` 并清原生选区，否则浏览器扩选会 `scrollIntoView`，格子在光标底下跑。工具栏换档（进表多出"行列与对齐"那一组）**不许改变工具栏高度**——真机照过：高度一变正文下移 25px，拖选按旧坐标落在错的格子上，"想框四格只框到两格"。所以 `.toolbar` 一次留够两行 |
| 拖拽落位反馈 | 落位线与编辑器里块拖拽共用一条视觉语言（同一个 `--focus-ring`、2px、`pointer-events: none`，否则它吃掉 `elementFromPoint` 就量不到指针下的行）。"移进目录"不画线，改成给那一行 inset 描边（暗色下阴影不可见，见 §阴影那条）。缝隙归属定死一条：**算给下面那一行**——目录展开时下面那行就是它的第一个孩子，所以"目录行与其子项之间"天然等于"插成该目录第一个孩子"，不需要再猜。拖完补发的那一下 `click` 必须按时间戳挡掉（真机照出 `setTimeout(0)` 与 click 派发有竞态，漏过去就把目录折叠了） |
| 编辑器工具栏 / 选区气泡 | **按钮上是图标，不是词**（`B` `{}` `链` `清` `+行` 这类混排在 2026-09-28 全部换掉）。图标一张表 `src/editor/icons.tsx`，工具栏与气泡共用；尺寸 `1em` 随字阶、描边 `currentColor`，所以 hover / `.on` / `:disabled` 三条改颜色的规则自动管到图标；文字退到 `title` + `aria-label`（读屏与悬停都从这一句来），带开关语义的再加 `aria-pressed`。缺的图标自己画，但照 Lucide 的参数走（24 视野 / 线宽 2 / 圆头），混排看不出差级 |
| 常驻工具栏（2026-10-28 悬浮化） | 从通栏条改成**悬浮胶囊**：`width: fit-content` + `margin-inline: auto` 居中，`--shadow-2` 与边框同用（暗面靠边框承担边界）。上面那条"两行 min-height"的高度不变式**原样保留**——换档只往宽里长（`max-width: 100%` 兜住后内部换行），高度一像素不动，拖选坐标就不漂。工具栏上那句提示的绝对定位改挂胶囊右缘（以前挂通栏右缘；AI 那枚提示 2026-10-28 随入口一起撤掉了） |
| 底部 AI 对话框（2026-10-28 新增） | 挂在正文列下沿、**滚动容器之外**（`.editor-pane` 那一层），正文怎么滚都不动。收起只有一枚**图标**把手（没有标题与目标文案），悬浮展开、移开收起；**焦点在内 / 生成中 / 有草稿 / 钉住 / 指针仍停在坞上**时不收（在面板里点空白会让输入框失焦，但那不算移开）。面板本身**没有标题行**：右上角只有两枚图标（钉住 / 收起），下面是记录与一个起步 5rem、随内容长到 9rem 的 textarea 加「发送」，只有输入框时连分隔线都不画。把手只在收起时渲染——展开时不再在面板底下挂第二个开关。材质与气泡同一套（`--bg-raised` + 1px `--border-subtle` + `--shadow-2`），宽度跟 `--measure-ui`（56rem）走——对话不必跟正文一样宽，再宽读起来就是扫视；高度上限 `min(46vh, 26rem)`——**不新增 token**，用户挑的颜色另走内联色值（[02] D35）。正文尾部留 `h-12` 空档：把手浮在正文上，不留就把最后一行永远压住。右下角保存提示从 `bottom-5` 上移到 `bottom-16` 让开它 |
| 大纲栏（2026-10-28 新增，布局三） | 正文右侧一条独立滚动列，**宽度 `w-50`（200px，`--spacing×50`）是布局契约**——不钉死就会被最长标题撑开，正文列宽跟着抖。只列前三级标题（`outlineOf` 走顶层块，`mdLevel ≤ 3`）；活动节跟**光标**走（`activeHeadingOf`：光标前最近标题，文档开头 -1 不亮任何节），不做滚动跟踪的 IntersectionObserver。当前节 = `--accent-soft` 底 + inset 2px accent 条（选中主信号是边，几何不动）。组件自带事件订阅 + 条目签名判据，不往上传选区变化（打字路径上多渲染一棵 main 子树 = 违反 G6）。无标题时整只不渲染，空栏是"为了布局而布局"。点击跳转发**选区事务不发文档事务**（不标脏），滚动用 DOM `scrollIntoView({block:"start"})` 顶到上沿（`tr.scrollIntoView()` 只滚最少距离，标题会贴视口底沿），不做平滑动画（动效规则只认 transform/opacity） |
| 面包屑（2026-10-28 新增） | meta 行里的 mono `rel` 换成目录链：目录段 `--text-secondary`、篇名（最后一段）`--text-primary`，分隔符 `/` aria-hidden。截断留给整条 nav——窄窗从尾部省略时牺牲目录链，篇名不能看不见 |
| Callout / 提示块 | 六类语义色 + 图标；暗色下用半透明底（同色相 12% alpha），不是硬编码灰 |
| 空态 | 文案 + 一个主操作按钮，不插画满屏；空态是最容易被遗忘的界面。**2026-10-11 补齐**：主区空态以前只有一句话（实测 `main` 里按钮数 = 0），现在带一枚「新建一篇」 |

## 4. 禁止清单（护栏可查，逐条都有理由）

| 禁止 | 为什么 | 护栏 |
|---|---|---|
| 组件内出现 `#hex` / `rgb()` / `oklch()` 字面量 | 绕过语义色 → 暗色必然不一致。只允许 `tokens.css` 内有字面量；**唯一例外是 `src/editor/colors.ts`**——那是用户挑的颜色，要原样写进 `.md`，换成 `var()` 文件就带不到别的编辑器里去（[02] D35） | ✓ |
| `px` 字面量不在 `tokens.css` | 间距漂移，界面"看着乱但说不出哪不对"的根因 | ✗ **只人工查**：1px 描边、2px 位移这类本就得写 px，一刀切会把 `base.css` 全刷红。半格间距那一条（下面一行）才是机器能判的 |
| 半格间距（`p-1.5` / `px-2.5` / `mt-0.5`…） | 2/6/10/14px 都不在 4px 栅格上，而它们比 `13px` 更难发现——长得像 token | ✓ 2026-10-11 补 |
| `outline: none` 且无替代焦点样式 | 键盘用户失去定位，且 a11y 直接不合格 | ✓（CSS）|
| Tailwind 写法 `outline-none` 出现在 `.ts/.tsx` | 与上一条同等对待。以前**只**在 CSS 里判，于是 TSX 字符串里那个 `outline-none` 一路绿灯走过护栏——那种"去掉描边"必须落到 CSS 的同一条选择器上，机器才认 | ✓ 2026-10-11 补 |
| `transition: all` | 会连带过渡布局属性 → 掉帧（违反 G6）；必须显式列属性 | ✓ |
| 动画 `width/height/top/left/margin` | 同上，触发布局 | ✓ |
| 裸 `z-index` 数字 | 层级失控，弹层被覆盖这类 bug 查一下午 | ✓ **两条都查了**：Tailwind 的 `z-[数字]` 一直有，CSS 里那条 `z-index: 1`（目录树落位线）以前抓不到，因为它只匹配方括号写法 |
| 联网取字体/图标/脚本 | 本地优先产品启动不该有外部请求；离线必须零退化 | ✓ |
| 用远程图片/字体做首屏 | 同上，且违反"数据不出本机"的定位 | ✓（同上一条的匹配） |
| `!important` | 除了 `prefers-reduced-motion` 的归零规则，一律不允许 | ✓ |

检查方式：已落地为 `scripts/guard.mjs` 的一部分（原计划单独做 `note style-lint`，没必要——同一套护栏还要管依赖方向与预算键，合并只有一份维护成本）。它扫 `src/**` 的 `.ts/.tsx/.css`，命中禁止清单即 exit 1。

> 这张表最后一列是 2026-10-11 加上的。在此之前本文件的说法是"禁止清单由护栏逐条盯着"，
> 而实际有三条根本没实现（CSS 裸 z-index、TSX 的 `outline-none`、半格间距），
> 于是文档里的"机器可查"变成了"机器挑着查"。**要么补规则，要么把这一列写清哪条是人查的**——
> 含糊过去，下一次评审还是人来当护栏。

两个实现细节，不写下来一定被反复误报：

1. **先剥注释再做匹配**。否则本文件里"绝不用 outline:none"这类说明性注释会被规则自己抓住（第一轮就是这样）。
2. 允许清单只有 `src/ui/tokens.css`（token 定义处）与 `probes/**`（一次性验证代码）。**新增例外必须写注释说明为什么**。

`outline-none`（Tailwind 写法）与 `outline: none` 同等对待——第一轮就在搜索框上顺手写了 `outline-none`，被这条抓出来后改成依赖全局 `:focus-visible` 环。这也是把规则做成脚本而不是文档条款的理由：人写 class 时不会想起条款。

**但规则判的是"有没有焦点指示"，不是"必须用一圈描边"**（2026-09-26 精确化，护栏同步改了实现）。写清楚是因为老措辞把两件事混成了一件：

- 正文编辑器**必须**去掉整篇的 `:focus-visible` 圈。原因：Chrome 对可编辑的 `contenteditable` 在**鼠标**聚焦时也判 `:focus-visible`（真机量过，去掉 `preventDefault`、去掉程序化 `focus()` 都没用），所以只要用圈，用户点一下字就圈住整篇文章。
- 替代形式：焦点指示落在**当前块**上（左页边一条 2px 竖线，位置由 `FocusIndicator` 插件写进 `--focus-top/--focus-h`，可见性由 `.block-editor:focus-within` 决定）。这比一圈更符合本意——键盘 Tab 进来时看到的是"焦点在这一块"，而不是"这个容器有焦点"。
- 护栏因此改成条件判：文件里出现 `outline: none` 时，**必须同时存在一条由 `:focus` 驱动的正向指示声明**（`outline`/`box-shadow`/`border`/`background`/`opacity: 1` 之一），否则仍然红。这不是白名单：什么都不给就是红。

## 5. 主题值一览（实现时的唯一来源）

`tokens.css` 里那三个块——`:root`（亮色值）、`[data-theme="dark"]`（暗色值）、以及只做事不写值的
`@theme inline`（把语义 token 映进 Tailwind 的命名空间）——是本仓库**唯一**允许出现颜色字面量的地方；
任何组件引用它。写组件时别把 `@theme` 当"值"的来源：它是映射表，值在上面那两块里。
新增 token 的流程：先在此文件列出语义与用途 → 亮/暗两套值 → 过 AA 对比度校验 → 再写组件。
反过来（先写组件再补 token）会破坏一致性，视为缺陷。

## 6. 与设计稿的关系

没有独立设计稿。**样式规范即设计源**：组件按 token 实现后，观感由 token 值统一调，
不逐个组件微调像素。这样"改一处全局生效"，也让一个人能维持界面一致性。
若要整体换风格（如更紧凑的字号、不同 accent 色），只改 `tokens.css`。
