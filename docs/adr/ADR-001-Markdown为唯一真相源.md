# ADR-001 · Markdown 文件为唯一真相源

**状态**：已采纳（2026-09-22）

## 背景

本地优先的笔记产品必须在"自有数据库为真相源"和"纯文本文件为真相源"之间二选一。这决定用户是否敢把长期记忆交进来，也决定 AI 层能否建立在其上。

## 选项

| 选项 | 优 | 劣 |
|---|---|---|
| A. SQLite/自有格式为真相源，Markdown 只是导出格式 | 数据模型自由，块/属性/链接随便改，无解析歧义 | 用户不信任（"我的东西到底在哪"）；Obsidian/VSCode/git 生态全部失去；产品一旦停更，数据即被绑架 |
| B. **Markdown 为真相源，DB 为纯派生索引** | 任何编辑器可读写、可 git 管理、迁移成本近乎零、与 Obsidian 生态互认 | 必须接受 md 语法子集约束；要处理外部修改与冲突；无损往返是长期税负 |

## 结论

**选 B。**

## 代价与必须守住的约束

- 一切块类型必须能用 Markdown 表达，因此 v1 放弃白板、内嵌数据库渲染、批注层
- 派生物（嵌入向量、分词、摘要缓存）不进 md 文件，只进 `index.db`，避免污染 diff
- I1–I4 不变量与字节级往返测试作为回归红线（[02] 文档）
- 外部修改冲突策略必须显式设计，不能"以最后一次写入为准"
- 明确 **I1 例外清单**：派生索引、AI 过程数据、性能缓存允许只在库里；**用户手写内容不行**。这份清单是防止日后偷偷往库里塞用户数据的护栏

若某天发现必须破坏 I1 才能实现某个功能，那说明该功能不该做，或该产品不该是本地优先——两者都需要重开 ADR，而不是偷偷在代码里加一张"只有 db 有"的表。
