# ADR-002 · 块 ID 采用 Obsidian 兼容语法 ` ^b-xxxxxxxxxx`

**状态**：已采纳，**M0 Spike B 需真机验证**（2026-09-22）

## 背景

AI 原生要求每个块可精确寻址：问答引用要能点回原文，建议箱要能对"某一块"提补丁，检索切片要有稳定边界。ID 必须写在文件里（否则用户用其他编辑器改完就对不上），因此这是一个**语法选型**问题，不是实现细节。

## 选项

| 选项 | 优 | 劣 |
|---|---|---|
| A. `{#b-xxx}`（kramdown / MyST 属性约定） | 部分渲染器认；语义上是"属性"而非正文 | Obsidian 不认，`[[note#^id]]` 跳不过去，双向互操作丢失 |
| B. **` ^b-xxx`（Obsidian 块引用语法）** | Obsidian 原生可跳转可引用；导入导出零转换；`[[笔记#^b-xxx]]` 语义现成 | 不支持块 ID 的渲染器（GitHub 等）会把尾部当正文显示；代码块/表格需另起一行放 ID |
| C. ID 只存 `index.db`，按 `(文件, 序号, 内容hash)` 定位 | md 文件绝对干净 | **违反 I1**；外部编辑一次即错位；AI 引用可能指向已变内容，溯源不可信 |

## 结论

**选 B。C 直接排除**——它把可寻址性建立在派生物上，AI 引用溯源会随外部编辑腐烂，等于放弃产品最核心的可信卖点（G4）。

## ID 规格

- 格式：`^b-` + 10 位小写字母数字，追加在块末行尾部；无法追加的块类型独占一行写在块之后
- 永不复用、永不因移动/编辑改变；文件复制导致的 ID 冲突按 [02] §块 ID 的冲突规则处理

## 待验证（M0 Spike B）

1. 真实 Obsidian Vault 用本产品打开 → 保存 → 回到 Obsidian：块引用、嵌入、反链面板是否全部正常
2. 嵌套列表项、表格、Callout 三种块放 ID 后，Obsidian 与我们的解析器结果是否一致
3. 若结论是"互相破坏"：退回选项 A，并明确放弃 Obsidian 双向互操作。这属于产品级降级，须重开本 ADR 而非静默改代码
