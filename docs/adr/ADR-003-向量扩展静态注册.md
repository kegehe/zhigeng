# ADR-003 · 向量扩展用静态注册，不分发 sqlite-vec 的 .dll

**状态**：已采纳（2026-09-22，M0 Spike A 实测通过）

## 背景

[02] §待办决策 原本假设：Windows 上要把 `vec0.dll` 随安装包分发，运行时 `load_extension` 加载，并担心签名与加载链路。Spike A 的实测结果推翻了这个前提。

## 实测结论（Windows 11 / MSVC / rustc 1.95）

```
依赖：rusqlite 0.40 (features=["bundled"]) + sqlite-vec 0.1.9
装载：sqlite3_auto_extension(Some(transmute(sqlite_vec::sqlite3_vec_init)))
     —— 必须在开任何 Connection 之前注册
结果：sqlite version = 3.53.2
     CREATE VIRTUAL TABLE v USING vec0(embedding float[8])  → OK
     INSERT (rowid, embedding) + "WHERE embedding MATCH ? AND k = 3 ORDER BY distance"
     → (1, 0.0) (2, 0.14142138) (3, 1.4142135)   距离为 L2，排序正确
```

`sqlite-vec` 这个 crate 直接把扩展的 C 源码随构建编译进来，因此**不需要任何 `.dll`**，也不需要 `load_extension`。

## 选项

| 选项 | 优 | 劣 |
|---|---|---|
| A. 分发 `vec0.dll` + `load_extension` | 可扩展其他扩展；升级扩展不动主程序 | 安装包多一个二进制要签名与路径解析；**`load_extension` 本身是需封禁的危险 API**（一旦对 SQL 注入开放即等于任意代码执行）；加载失败是运行期错误 |
| B. **静态注册（`sqlite3_auto_extension`）** | 零分发物、零运行期装载失败、可以把 `load_extension` 永久关死、启动即可用 | 扩展版本与主程序一同编译，升级要重编（本地单用户场景无所谓） |

## 结论

**选 B。** 附带三条硬约束：

1. **虚拟表语法一律用 `vec0`**：`CREATE VIRTUAL TABLE vec_<model> USING vec0(embedding float[<dims>])`。旧文档里写的 `vec_embeddings` 是过期语法，已废弃。
2. **向量以 BLOB 传入**：小端 `f32` 序列（`f32::to_le_bytes` 拼接），`rowid` 与 `chunks.id` 对齐。
3. **`note-core` 不得暴露 `load_extension`**：全仓库禁止调用 `rusqlite::Connection::load_extension_enable`，在代码评审清单里作为一条固定检查项。这是把"SQL 注入 → 任意代码执行"这条升级路径彻底焊死。
