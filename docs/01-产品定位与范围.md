# 01 · 产品定位与范围

## 一句话

一个**长在 AI 上的本地个人知识库**：你只管往里面丢东西，AI 负责整理、串联、回忆，并在对的时机主动把该看的东西推到你面前。

## "AI 原生"的可验证判据

把全部 AI 模块摘掉，产品应该只剩一个能用但没人愿意用的空壳。若只是"少了个润色按钮"，那叫接入 AI，不叫原生。

差别体现在四条主路径的归属权：

| 环节 | 传统笔记（AI 是插件） | 本项目（AI 是骨架） |
|---|---|---|
| 写入 | 打开编辑器 → 打字 | 任意时刻丢进 inbox，整理由 AI 异步完成 |
| 组织 | 手动文件夹、手动标签、手动建链 | 结构由 AI 涌现，人只做修正与确认 |
| 检索 | 目录树 + 关键词搜索框 | 语义问答为主路径，树与标签退为可视化兜底 |
| 消费 | 自己去翻 | AI 在对的时机把对的笔记推过来 |
| 作者 | 只有人 | AI 也会自己产生笔记（纪要、周报、跨笔记综述） |

## 目标用户与场景

**唯一目标用户：自己。** 一个人管理长期积累的想法、阅读材料、会议记录和待办。痛点是"记了但找不到""找不到当初想过什么""整理比记录更累"。

核心使用回路：

```
丢进 inbox → AI 整理入库 → 需要时问 AI（带引用） → AI 主动回顾与串联 → 产生新笔记
```

## 两条与功能同级的硬要求

这两条不是"做好了再优化"，而是从 M0 就参与取舍的约束（阈值与手段见 [03] §性能 与 §界面质感，编号见 G6/G7）：

1. **不能有任何卡顿，且数据量大了依然不卡。** 具体化为：打字到屏幕 < 16ms、同步调用 < 8ms、INP P95 < 50ms、2 万篇检索 < 80ms、3000 块长文可正常编辑。做不到就不做该功能——宁可少一个特性，不要一次掉帧
2. **界面要优雅漂亮。** 具体化为：统一设计 token（禁止硬编码色值与间距）、原生材质（Mica/Acrylic）、排版讲究（行长 65–75 字符、行高 1.7、中文字体子集化本地打包）、所有动效只用 `transform/opacity` 且尊重 `prefers-reduced-motion`、任何动作 100ms 内有反馈

这两条会真实地否决一些"看起来更丰富"的选择（例如在正文区做动画、用重组件库换开发速度、为了渲染方便把内容一次性全量挂载）。

## 范围

### 目标形态（v1 完整范围，括号内是交付里程碑）

里程碑定义见 [05-路线图与验收标准.md](./05-路线图与验收标准.md)。

- **端**：Windows 桌面（M0），本地单用户
- **体验**：虚拟滚动列表（M1）、长文分节渲染（M1）、Mica/Acrylic 材质与自绘标题栏（M1）、"流畅优先"降级档（M1）
- **记录**：块编辑器（M1）、Inbox 速记 + 全局热键（M1）、无限层级目录（M1）
- **组织**：双向链接与反链（M1）、标签与属性（M1）、全文搜索（M1）、命令面板（M1）、关系图谱（M3）
- **采集**：手动输入与文件拖入（M1）、网页 URL 抓取（M1）、图片与 OCR（M5）、PDF/EPUB 解析（M5）、语音（M5）
- **AI**：混合检索 + 强制引用问答（M2）、自动标题/摘要/打标/建链走建议箱（M3）、后台整理与周期回顾（M4）、跨笔记综述与纪要（M5）
- **生态**：导出 Markdown（M1）、MCP Server 只读暴露（M5）
- **数据安全**：回收站与恢复（M1）、外部修改冲突保留（M1）、每日快照备份到第二目录（M1）、版本历史与建议撤销（M3）
- **模型**：用户自带 API Key 或本地 Ollama（M2）

> **可用版 = M0–M2**：能记、能查、能问。M3 之后每一档才是在堆差异化。

### 明确不做（不列出来它迟早会偷偷长出来）

| 不做 | 原因 |
|---|---|
| 登录、注册、账号体系 | 本地单用户，没有多用户身份需求；有账号就要有服务端与找回流程，纯增负担 |
| 权限、角色、加密隔离 | 单机单用户，文件系统权限即边界 |
| 多人协作、评论、@ 提醒 | 同上，CRDT 协同复杂度足以吃掉半年 |
| 云端托管、多端同步、SaaS 后台 | 与本地优先定位冲突；仅在 schema 预留字段，不写任何同步代码 |
| Web 端、移动端、浏览器剪藏扩展 | Windows 优先，其余后置 |
| 计费、配额、成本管控 | 用户自带 Key，成本天然归用户 |
| macOS / Linux 适配 | 架构不排斥，但不为它们做适配与打包验证 |
| 与 Notion 拼块编辑器细节（白板、公式排版、拖拽动效） | 追平 80% 即停，剩余精力投在差异化层 |
| 内嵌数据库视图的复杂计算（rollup、公式跨表引用） | 无法无损落成 Markdown，与 G1 冲突 |

## 差异化押注（按优先序）

1. **主动层** —— AI 找上门：晨间整理 inbox、"你三个月前想过这个"、记了问题没记答案的缺口提醒。市面产品普遍最弱，也最难抄。
2. **可信溯源层** —— 无引用不作答、每个结论可点回原始块、AI 行为可审计。这是本地优先用户愿意把记忆交出来的前提。
3. **MCP Server 暴露** —— 同机的 Claude / Qoder / 任意 agent 都能读这份记忆，让笔记成为整个 AI 生态的长期记忆源。本地架构下实现成本极低，收益不对称。

自动组织与生成能力**不作为差异化主张**：它们是必须做到但做到了也不构成竞争力的地基。

## 三个必须正视的风险

| 风险 | 后果 | 对策 |
|---|---|---|
| 空库悖论（不是"启动慢"那个冷启动） | AI 再强，库里没内容就是空转，第一周就流失 | 采集与导入排在 AI 能力之前（M1 先于 M2）；一键导入 Obsidian/Notion/印象笔记 |
| 自动整理不可控 | 用户发现笔记被悄悄改乱，信任一次性崩塌 | G3 红线：AI 只写 `suggestions` 表；`link`/`merge`/`restructure` 在代码层禁止自动执行 |
| 外部编辑器导致索引失真 | 用户在 Obsidian 改完，AI 读到旧内容 | 文件监听 + 三种情形的冲突策略（[02] §写入与外部修改）；一切以 md 内容 hash 为准 |

## 成功判据（自用三个月后回看）

- 记录动作中位耗时 < 3 秒（全局热键到落盘）
- "我记得我记过但找不到"的挫败感消失：问答能命中，且引用可点回原文
- 每周回顾由 AI 起草，人只做删改，不再手写
- 库增长到 5000+ 篇时检索质量不下降（用评测集证明，不靠感觉）
